## 一、挂载位置（★ 与 09-25 的预设不同，有理由）

`configs/_final.json` 的 `build_extra` 现在是：

理由：本脚本的落位完全由"占用栅格"决定，**栅格越完整，草坪越不会压到别人的东西**。
排在最后（除配色重标外）⇒ 栅格能看到主景树 / 教学区路缘标线 / 全园门廊踏步。

## 二、核心方法论：**摆件位置不靠手算，靠量**

分区铺装（`SITE_分区_*`，`M_区_*`）原本 ~100% 铺满。要在上面抠绿地，就得知道**哪里真空**。
1. **占用栅格**（1.0 m 步长，自上而下 `scene.ray_cast`）—— 判据是**白名单** `_coverable()`：
   只有 **`M_区_*` 分区铺装** 与 **`R5_*` 院落/中央广场/中央庭院**（`M_广场铺装`）允许被覆盖，
   其余（`BLD_` / 主路 / 步道 / 中轴 / 广场 / `R4_` / `R5_运动_` / `R6_` / `DTL_` / `ENT_` / 树）一律占用。
   ★ **白名单比黑名单安全**：将来新增一类构件，默认落在"不覆盖"一侧。
2. 候选区 = **分区矩形内缩 2 m**（不给窄带 —— 窄带抠不出 25~35%）。
3. **最大矩形**（直方图 + 单调栈）反复抠，占用格按 `margin` 膨胀。
   ★ 不用"从四边往内缩"：那只对付贴边障碍，障碍在候选区**中间**时会缩不动，整块报废。
4. 只在抠出的矩形里铺草 / 种树 / 放水景 / 起缓丘。

## 四、坑（★ 都是"不报错"的静默失效，全部留在代码注释里）

**坑 1 — `emit_to()` 是"新建对象"，不是"替换"。**
`tree()` 每株调两次 `emit_to`，几百株就是几百个 `R7_景观_树干.NNN`。
**修**：所有几何先进登记表 `_REG`，最后 `_flush_reg()` 统一落地一次 ⇒ **8 个对象**。

**坑 2 — 验收判据自己把成果吃掉了。**
第一版把"命中树冠"归成"硬质"，于是**刚种完树的那块草坪反而变"硬"**
（生活区西：铺 4 371 m² 只量出 3 075 m² 绿地）。
**修**：**两级射线** —— 高空 `Z_RAY=150` 只判"是不是建筑"（建筑从 `Z_TOP` 起，
低空射线会从**建筑内部**穿过，判不出墙）；低空 `Z_TOP+1.4` 判地面
（低于树冠底 ≥1.5 m、高于所有铺装/草坪，所以树冠不挡它）。
★ 这个"两级"是被迫的：树冠底最低 ~1.5 m，灌木顶最高 ~1.82 m，**没有单一高度能同时躲开两者**。

**坑 3 — `margin` 膨胀会整条吃掉窄草带。**
生活区东 `可覆盖 8 826 m² 却只抠出 3 710 m²`。`_MARGIN` 2.2→1.5、`_CELL` 2.0→1.5→**1.0**，
抠出升到 5 708 m²。★ **栅格步长必须小于最窄的自由条带**，否则窄条在栅格里根本不存在。
★ 为此加了 `_cover_area()`（**未膨胀**可覆盖面积）做诊断 —— 一眼分清"本来没地"还是"被 margin 吃掉"。

**坑 4 — 水景与缓丘都取"最大草坪块的正中"⇒ 山堆在池子里。**
根因是两处各自独立地取 `rect[0]` 的中心，谁也不知道对方占了那块地。
**修**：池子登记表 `_POOLS` + `_in_pool(x,y,pad)`，树 / 灌木 / 缓丘落位前先查表；
并把**水景的落位提前到铺草种树之前**。

**坑 5 — 尺度失准（两处，都要靠实拍才发现）。**
· 水池 20×12 m 在 89×69 m 草坪里读成**小水洼** ⇒ 放大到 30×19 / 26×16 / 20×12。
· 缓丘 1.5 m 读成**平的浅色圆盘** ⇒ 按 V3 上限给 2.0~3.0 m，
  并按地块大小**自适应降高** `_h_max = (min(w,d)-6)/16`（下限 1.5 m）——
  比"统一给一个值、小地块全被跳过"合理：小的草地也该有起伏，只是小一点。

**坑 6 — 同位置叠两层草 = 共面 ⇒ Cycles 花斑。**
林地色斑与草坪顶面同在 `Z_TOP+0.16`。**修**：`lawn()` 加 `dz`，色斑抬 2 cm。

**坑 7 — "整块内缩的深绿矩形"太生硬。**
三种绿（草坪 / 林地色斑 / 土丘草）挤在一起谁也不像谁的邻居。
**修**：色斑改成**环池种植带**（池外扩 5.5 m）—— 语义清楚："水池 + 岸边树丛"。

**坑 8 — 水面标高想错了（注释已改正）。**
水面盒从 `Z_TOP+0.10` 起、厚 0.10 ⇒ 顶面 `Z_TOP+0.20`，比草坪顶（+0.16）**高 4 cm**，
所以它读成"石边**抬高**水池"，不是"沉下去的池"。要真下沉得把草坪板在池口挖洞（拆四块），不值当。

## 八、这一轮真正修掉的东西 —— 一个藏了很久的静默失效

本工程有**两个**"钛锌"材质，名字只差一个字：

| 材质名 | 建在哪 | 用户数 |
|---|---|---|
| `M_钛锌屋面板` | `build_campus_r0.py:117` | **1** |
| **`M_钛锌板`** | `build_campus_r1.py:171`（把全局 `M_ZINC` **重绑**成这个名字） | **32** |

而 V2.4 的 `_RETUNE` 表**只写了前者**。实测 `M_钛锌板` 的基色一直是建材质时的
`(0.172,0.180,0.190)`、金属度一直是 **0.42**（镜面金属）。

后果两层：
1. 屋面接近水平，掠射角反射的正是蓝天 —— 鸟瞰里屋面占近 40% 画面，**等于把天铺了一地**；
2. ★ `palette_retune.py` 里那句沿用下来的判断
   「**实测把 metallic 从 0.60 压到 0.15 后成图几乎没变**」**是错的** ——
   那次实验只落在**那一个**对象上，32 个屋面从未被改过。
   （09-21 日志第 156 行记的就是这句错结论，**已在代码注释里改正**。）

⇒ 与 skill「材质名对不上 = 静默失效」同源。**改材质前先数用户数**（`_dump_palette.py` 现在就报 `users`）。

## 九、为什么必须**拆材质**

32 个对象共用**同一个** `M_钛锌板`，材质是对象级的共享资源 —— 想让教学屋面暖灰、
科技屋面铜绿，只能按对象 `copy()` 成两份、再把对象材质槽的引用改指过去。
顶点色 / attribute 要动几何，会毁掉 GLB 的抽稀，不做。

★ 两个实现细节：
- 遍历 `bpy.data.objects` 找用户 —— **材质不记录"谁在用我"**，`users` 只是个计数；
- 改槽位前先查 `ob.data.users > 1`（网格数据共享时会连带改到别的对象）。

结果：`M_钛锌板`（32）→ `M_钛锌板_暖灰` **25** + `M_钛锌板_铜绿` **7**；
原材质被搬空，**必须登记进 `_ROOF_DEAD`**，否则会误报成"僵尸材质"。

## 十、色值怎么定的 —— **明度对齐旧屋面，只换色相**

| | 线性 RGB | 相对亮度 | sRGB |
|---|---|---|---|
| 旧蓝灰（改前） | (0.172,0.180,0.190) | 0.179 | (115,119,122) |
| 暖灰 v1（**作废**） | (0.216,0.188,0.150) | 0.191 | (128,120,108) |
| **暖灰 v2（定案）** | **(0.155,0.136,0.112)** | **0.146** | **(110,103,93)** |
| **铜绿 v2（定案）** | **(0.085,0.172,0.144)** | **0.150** | **(82,115,106)** |
| 旧蓝灰（A/B 对照） | (0.172,0.180,0.190) | — | — |
| 粗度 / 金属度（全屋面） | 0.58 / 0.42 → **0.78 / 0.10** | | |

★★ **v1 为什么作废**：`metallic 0.42 → 0.10` 之后屋面从"反射天光的**镜面**"
变成"**纯漫反射**"，**水平面吃满天光 ⇒ 成图反而比改前更亮**；
3× 放大一对比，屋面已经和近白的墙体拉不开（体量读平了）。
⇒ 定案按"明度对齐旧屋面、只换色相"重给。实测 v1→v2 屋面像素均色
`(113,129,113) → (101,116,102)`，约 **−10%**，体量重新读得出来。

**可复用教训**：**换色相时不要顺手改明度** —— `metallic` 一降，同一 albedo 的成图亮度会自己往上跑，
明度要**反着补**回来。

## 二十、这一轮踩到的 4 个"假象"（★ 都写进 skill 了）
1. ★★ **`loading="lazy"` 会让"断链自检"给出假阳性**：没进视口的 `<img>` **根本不发请求**，
   `naturalWidth` 自然是 0 ⇒ 第一次跑报"总览 63 张破图 / 图集 25 张破图"。
   而 `response.status >= 400` 是 **0**、文件也确实都在。
   ⇒ 判据必须分开：**破图 = 请求已发出且状态 ≥400 或解码失败**；"未完成" ≠ "破图"。
   自检前要**滚到底反复几次**把懒加载触发出来。
2. ★★ **WebGL canvas 的 `drawImage` 采样恒为 0**：默认 `preserveDrawingBuffer:false`，
   帧呈现后读的是**空缓冲** ⇒ 我的探针报"与背景不同 0.0% / 非黑 0.0%"，
   看起来像"3D 没画出来"。**真实合成器截图不受影响**。
   ⇒ 判 WebGL 页面"有没有出图"，要么用**页面自己的就绪标志**，要么**真截图**，别读 canvas。
3. ★ **就绪标志是模块内变量，不在 window 上**：`preview.js` 里 `let __ready` 是模块私有，
   对外暴露的是 **`window.__preview().ready`**。我写成 `window.__ready` ⇒ 永远 `false`，
   差点把"通过"误判成"失败"。**探针要找页面自己公开的那个入口**。
4. ★ **`make_overview_html.py` 要跑 ~2 分钟**（71 张图逐像素算下 55% 区域统计）：
   超过前台默认 120 s 超时 ⇒ 被 SIGTERM 杀掉，而且 Python 的 stdout 是**块缓冲**，
   一杀就把已打印的内容全丢了 ⇒ 表现为"**exit 1、零输出**"，看起来像脚本自己崩了。
   ⇒ 这个脚本**一律放后台跑**；`| tail` 也别用来判"有没有输出"。

## 22.5 改了什么
1. **阴影只算一次**：`shadowMap.autoUpdate = false` + `needsUpdate = true`（载入后渲一次，
   必须放在 `scene.add(model)` **之后**，否则渲的是空场景 ⇒ 阴影凭空消失且不报错）。
   `mapSize` 保持 2048（只算一次 ⇒ 对每帧代价无影响，**零视觉回归**）。
2. **画质分级 + 自适应分辨率**：`?quality=high|balanced|perf`，单项覆盖 `?dpr= ?shadow=
   ?smapsize= ?softshadow= ?aa= ?adapt=`。自适应**只降 dpr、不在运行时开关阴影**
   （切 `shadowMap.enabled` 会让 54 个材质程序全部重编）。
   ★ 自适应必须有两段静默期：**模型未就绪不判** + **就绪后 3 s 预热不判**，
   否则任何机器（含独显）开机瞬间都会被判"卡"而白白降分辨率（实测撞到 dpr 掉到下限 0.75）。
3. **路径特效换风格**：24 对象/23 加色 → **7 对象/6 加色**。
   贴地渐变光带（单 mesh 三角带，正面单面）+ 细芯线 + 两端各 2 个对象 + 圆点粒子。
4. **建筑高亮换风格**：每次点击新建 10 几何 + 10 材质 + 1 张 CanvasTexture（清除时全 dispose）
   → **常驻 3 个对象、零分配**；标签贴图按名字缓存；拾取改**纯射线–球数学**
   ⇒ 场景里少了 22 个不可见 Sphere。
5. 顺手修的 bug：① 特效动画 `update()` 写在 `render()` **之后** ⇒ 永远晚一帧；
   ② `performance.timing.navigationStart` 已废弃（恒 0）⇒ 换页面自己的单调时钟；
   ③ `resize` 里 `setPixelRatio` 会把自适应降下来的分辨率"还原"回去。

## 22.6 ★★ 三个「看不见」的静默失效（都是旧版就有的）
1. ★★ **贴地特效整体埋在地下**：地面光斑在 `y = 0.2~0.8`，而场地基准 `Z_TOP = 3.0`。
   射线实测（`_probe_ground.py`，自 y=3000 垂直向下打 GLB）：中轴各点首命中 y = 3.06/3.05，
   其下 3.0 是地形面 ⇒ **旧版那 3 层脉冲圆环 + 地面光斑全部被深度剔除、画面上根本没有，
   而且不报错**。修法：统一 `GROUND_Y = 3.0` + 贴地抬高 0.45 m。
2. ★★ **高亮光环埋在楼底下**：固定半径 25 m 光斑 + 18/26/34 m 三个环，
   而亭兰图书馆半宽就有 `shx 32 px × 2.4 = 76.8 m` ⇒ 环整个被楼体遮挡。
   修法：按 `shx/shy` 算外接圆，`ringScale = √2 × halfMax × 1.12 / 0.77`。
3. ★★ **光柱半径只有 6~20 cm**：`CylinderGeometry(0.06, 0.20, 1, …)` 只 scale 了 Y。
   而且**径向渐变贴图贴在圆柱侧面**会被 UV 裹一圈，渲染成一个带白方块的硬边柱子。
   修法：几何改成"半径 1 的标准柱"、用**纵向**渐变贴图
   （`CylinderGeometry` 是 `uv.y = 1 - v` ⇒ **图像第一行 = 柱顶**，第一行要透明）。
4. ★ **流动粒子是 25 个白方块**：`PointsMaterial` **不给 `map` 时渲染成实心方块**；
   且 `sizeAttenuation: true` 时 `size` 是世界尺度，近处放大到 ~70 px。
   修法：`map: _texRadial` + `size: 9` + `sizeAttenuation: false`。
5. ★ **标签读不出来**：`SpriteMaterial` 用**加色**混合时，白字叠在亮绿地上被冲成淡黄；
   且 Sprite 的 scale 是世界尺度，鸟瞰 1400 m 外只剩 36×9 px。
   修法：`NormalBlending` + 深底白字 + `_updateLabelScale()` 按相机距离做**恒定屏幕大小**补偿。

  分项固定（base 40 + source 5 + crowd 0 + commonSense 5 + text 5）⇒ **UGC 永远 < 65% 阈值**，

- **时空去重从不触发**：`randomEvent` 全园均匀取点，相邻两条动辄 300–600 m，进不了 150 m 窗口。
- **文本 ↔ 地点不对应**：13 条里 7+ 条矛盾（「图书馆西侧路口剐蹭」→ 智谷谷底；

### ★★ 其他实测
