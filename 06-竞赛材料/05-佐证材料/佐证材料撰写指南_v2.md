## 一、佐证材料的定位

### 1.1 赛规原文

> 佐证材料：提交能够进一步凸显作品优势、创新点或团队实力的材料，如发表的论文报告（首页）、专利证书、软件著作权证书、获奖证书、**用户使用反馈、媒体报道**等，**合并为一个 PDF 文件**。

软著、专利是"如"字举例，**不是必选项**。评委核实三件事：**原创权属、效果真实、落地成熟**。

### 1.2 与评分项对应

| 评分项 | 分值 | 佐证如何帮分 |
| --- | --- | --- |
| 创新性 | 25 | 同类对比 + 创新检索报告（证明方案差异与新颖性） |
| 需求分析 | 15 | 真实需求调研记录、用户痛点反馈 |
| AI 技术应用 | 20 | 事件提取/意图分类/位置 grounding 的评测报告、接口实测 |
| 项目实施 | 15 | 版本迭代记录、测试报告、部署证据 |
| 应用成效 | 15 | 在线服务、真实用户反馈、使用数据 |
| 总结与展望 | 10 | 主要靠技术报告 |
| **附录附加分** | **5** | 数据资料、注释代码、规范参考文献、补充材料，每项 1–2 分 |

## 二、2D APK 的真实能力（佐证围绕这些展开）

### 2.1 产品功能（以源码为准）

| 模块 | 功能 |
| --- | --- |
| 二维地图 | 腾讯 2D 地图（默认 17 级）、地点搜索、GPS 定位、校园路径规划、跳转腾讯导航 |
| 地点服务 | 地点分类筛选（热点/失物/全部/教学）、地点详情卡、位置反馈 |
| 账号 | 邮箱注册/登录/验证码/重置/会话恢复 |
| 大厅 | 多人实时聊天、地区筛选、历史分页、撤回 |
| 校园信息 | 餐厅评价、热点、失物招领、附近设施、反馈报修、收藏、课表导入 |
| **AUV AI 助手** | 事件结构化提取、校园问答、意图识别、安全引导 |

### 2.2 AI 技术内核（Edge Function `auv-assistant`，真实代码）

1. **意图分类（确定性规则）**：`classifyMessage` 把输入分为 emergency / community / event / other，决定路由
2. **事件结构化提取（LLM + 确定性校验）**：大模型输出 8 字段 JSON（type / building / floor / severity / description / wait / time_window / advice），再经 `validateExtractedEvent` 校验
3. **位置 grounding（防幻觉）**：`mentionedLocations` 用权威地点表做确定性匹配，**模型自报地名不用于定位**，杜绝编造地点
4. **RAG 实时上下文**：从后端拉取实时事件（campus_events）、服务信息（campus_services）、地点目录注入 prompt
5. **安全护栏**：紧急场景强制引导 120/119、限流（每用户 8 次/分钟）、防提示词注入、越权/异常拦截
6. **人格化表达**：结论先行、给选项不给命令、情绪先接住再建议

## 四、需要额外调查/论证的事项（★重点，细节如下）

### 4.1 技术报告查重（初赛形式审查硬性环节）

**为什么要做：** 赛规明确初赛进行"技术报告查重"，复制比过高会被形式审查拦下，进不了复赛。

**查什么：**
- 主查：**技术报告 PDF 全文**（3000–5000 字）
- 建议自查：佐证材料中的文字部分（声明、报告、案例），避免与网络/他人成果撞车

**用什么系统（按与官方接近度排序）：**

| 系统 | 入口 | 价格（约） | 特点 |
| --- | --- | --- | --- |
| 知网个人查重 | pcheck.cnki.net | 按篇计费，通常 100–200 元 | 与高校/官方库最接近，定稿用 |
| 万方数据 | wfw.wanfangdata.com.cn | 30–60 元 | 初稿 + 定稿，性价比高 |
| 维普 | vpcs.cqvip.com | 40–80 元 | 算法类/工程类收录较全 |
| PaperPass / PaperYY | 官网 | 10–30 元 | 初稿粗筛，结果偏松或偏严，仅作参考 |

**目标口径：**
- 总文字复制比 **≤ 15% 稳妥，≤ 20% 可接受，> 25% 必须改**
- 单篇文献复制比不要过高（避免大段抄某一篇）
- 引用部分要正确标注（参考文献规范），系统会区分"引用"与"抄袭"

**降重方法（真实有效）：**
1. 改写：把长句拆短句、主动被动互换、同义词替换但保持术语准确
2. 转述：用自己的话复述原理，不照抄定义
3. 图表化：流程、架构、对比尽量转成图/表（图表不计入文字复制比）
4. 增加原创内容：自己的测试数据、实现细节、踩坑记录（这部分天然原创）
5. 规范引用：确需引用的加引号 + 角标 + 参考文献
6. 代码/公式不计入常规查重，但不要大段复制网络文档

**流程建议：** 初稿用万方/维普粗查 → 降重 → 定稿前用知网个人查一次 → 保留查重报告（**报告本身可放佐证材料，证明原创性**）。

### 4.2 创新性论证（novelty search，支撑"创新程度"）

**为什么要做：** 创新性占 25 分，"提出全新方案得 18–25 分"。但"全新"不能自说自话，需检索证明。

**三路检索（缺一不可）：**

**① 学术文献检索**
- 中文：知网（cnki.net）、万方、维普
- 外文：Google Scholar、arXiv、IEEE Xplore、ACM Digital Library
- 关键词组合：
  - "校园事件 结构化提取 大模型"
  - "UGC 可信度 众包 位置"
  - "意图分类 意图识别 校园 问答"
  - "LLM 信息抽取 地理 地点  grounding"
  - "campus event extraction LLM"
  - "crowdsourcing credibility geospatial"
  - "intent classification mobile assistant"
- 重点参考：SceneCraft（arXiv:2403.01248）、SimWorlds（arXiv:2607.01766）、UrbanWorld

**② 专利检索**
- 官方：国家知识产权局专利检索 pss-system.cponline.cnipa.gov.cn（免费）
- 辅助：Soopat、智慧芽（PatSnap）、incoPat
- 检索与上述相同的技术点，看是否已有"校园事件提取 + 可信度 + 位置"的授权专利

**③ 现有产品检索**
- 应用商店：华为应用市场、小米应用商店、应用宝、App Store、Google Play
- 搜："校园""智慧校园""校园地图""校园助手""超级课程表""今日校园"等
- 记录它们的功能边界，证明本作品差异

**产出：**
1. 《创新检索报告》：写明检索数据库、关键词、时间范围、检出文献/专利/产品数量、结论
2. **同类成果对比表**（见第四部分）
3. 3–4 条创新点，每条写"现有方案是 X，本作品是 Y，差异证据见 Z"

**可主张的创新点（结合真实代码，较稳）：**
- 事件提取"**LLM 生成 + 确定性校验 + 位置 grounding**"的双保险机制（模型地名不用于定位，防幻觉）
- 意图分类前置路由，把"该不该提取/该不该由模型回答"与"如何提取"解耦
- 实时校园上下文（事件/服务/地点）注入的 RAG 问答，答案可溯源
- 面向 2D 校园 App 的"上报—提取—校验—应答"闭环（对比通用聊天机器人）

### 4.3 科技伦理审查（初赛有"科技伦理审核"）

**为什么要做：** 赛规明确初赛有科技伦理审核，App 涉及位置、课表、聊天等个人信息。

**自查清单：**

| 维度 | 要求 | 材料 |
| --- | --- | --- |
| 个人信息 | 位置、课表、邮箱最小化收集，明示用途 | 隐私政策 |
| 数据存储 | 密码/敏感信息加密，不明文 | 建表 SQL/说明 |
| UGC 内容 | 有审核/限流/举报机制，防不良信息 | 安全护栏说明 |
| AI 输出 | 防幻觉、防误导、紧急场景正确引导 | 护栏测试报告 |
| 数据来源 | 训练/测试数据合法，不盗用 | 数据集来源说明 |
| 第三方 | 地图/模型/SDK 有合法授权 | 开源依赖清单 |

**产出：** 隐私政策 + 用户协议（可基于腾讯/阿里/标准模板改写）、数据来源说明、伦理自查表。

### 4.4 技术指标的"坐实"（防数据造假质疑）

**原则：技术报告里每个数字都要能在原始日志/文件中找到。**

- 现有方案书里若有"准确率 94.7%、F1 92.6%"等数字，**必须通过真实评测生成对应日志**才能写；否则改用实测值
- 为每个指标建《指标溯源表》：数值 → 原始证据文件 → 复现命令
- 宁要"保守但真实"，不要"漂亮但一戳就破"——伪造是取消资格红线

## 五、用户反馈：真实快速采集（不编造）

**为什么不能编：** 伪造问卷/邮件是提交虚假证据，赛规"严禁伪造，一经发现取消资格"，且问卷平台有后台数据、邮件有真实信头，编造的材料在答辩追问时极易穿帮。

**真实采集其实很快（2–3 天可达 30 份）：**

### 5.1 问卷（问卷星/腾讯问卷）

8–12 题，覆盖：
- 使用场景多选（找路导航 / 食堂排队 / 校园事件 / 报修反馈 / 聊天 / 课表）
- 各功能满意度 1–5 分量表（地图、搜索、路径规划、AUV 助手）
- 与现有方式（公众号/班级群/2D 地图）相比是否更有效
- 推荐意愿 0–10 分（算 NPS）
- 开放题：最有用功能 / 最需改进 / 一句话评价

分发：APK 链接 + 问卷发到室友群、班级群、社团群、其他院系群，目标 **30 份以上**。

产出：后台统计图表截图 + 10–15 条真实文字评价（匿名化）+ 汇总（份数、满意度、NPS）。

### 5.2 邮件/渠道反馈（真实来信）

- 准备一封**真实反馈邀请邮件**（模板可由执行路线提供），发给真实使用者/同学
- 收集真实回信，挑选具体、有内容的，脱敏（去掉姓名/邮箱/学校线索）后放入
- 没有真实回信就不做这一项，**不要伪造**

### 5.3 红线

- 问卷标题、截图、群名、邮件中不出现学校名称、真实姓名
- 头像昵称打码

## 八、一句话总结

不堆证书、不编数据，用"**区块链存证 + 授权/隐私清单**"补权属，用"**单元测试 + 接口实测 + 提取/分类/grounding 评测 + 护栏测试**"补技术，用"**查重报告 + 三路创新检索**"补原创与新颖，用"**30 份真实问卷 + 真实邮件**"补成效——一份句句可溯源的佐证 PDF，比任何编造材料都经得起答辩追问。
