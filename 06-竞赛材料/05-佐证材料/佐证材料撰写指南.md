## 一、先搞懂：佐证材料到底在"佐证"什么

### 1.1 赛规原文

> 佐证材料：提交能够进一步凸显作品优势、创新点或团队实力的材料，如发表的论文报告（首页）、专利证书、软件著作权证书、获奖证书、**用户使用反馈、媒体报道**等，**合并为一个 PDF 文件**。

注意：赛规列举的是"**如**"，即**举例不穷尽**。软著、专利只是可选项，不是必选项。评委真正要核实的是三件事：

1. **原创性与权属** —— 这东西是不是你们自己做的（初赛有查重 + 科技伦理审核）
2. **真实性与效果** —— 报告里的指标是不是真的、能不能复现
3. **成熟度与落地** —— 有没有人用过、是否在线可访问

### 1.2 佐证材料与评分项的对应关系

| 评分项 | 分值 | 佐证材料如何帮分 |
| --- | --- | --- |
| 创新性 | 25 | 同类成果对比表（证明方案差异）、区块链存证（证明方案提出时间） |
| 需求分析 | 15 | 需求调研问卷、访谈记录、用户痛点反馈 |
| AI 技术应用 | 20 | 模型微调验收报告、训练日志、测试集评测结果 |
| 项目实施 | 15 | Git 提交记录、迭代版本对照、测试报告 |
| 应用成效 | 15 | 在线服务、用户反馈、安装/访问数据 |
| 总结与展望 | 10 | ——（主要靠技术报告） |
| **附录附加分** | **5** | **完整数据资料、注释代码、规范参考文献、其他补充材料，每项 1–2 分** |

> 结论：**佐证材料直接影响约 15 分（应用成效 + 附加分），间接影响全部 95 分的可信度。** 没有证书不等于丢分，材料空洞、数据不可核验才会丢分。

#### 1.2 区块链电子数据存证证书（★最高性价比，1 天，15–100 元）

软著来不及，**用区块链存证替代"官方确权"**，法律效力获《最高人民法院关于互联网法院审理案件若干问题的规定》认可。

**做法：**
1. 把要存证的内容打包成一个 ZIP 或准备好关键文件：
   - 源代码（`OurCampus/src/`、`02-三维资产/blender/scripts/`）
   - 技术报告 PDF
   - 全园 GLB、APK
2. 选择存证平台（任选其一）：
   - **易保全·微版权**（www.ebaoquan.org）：最低 15 元，最快 1 天出证，可申请电子数据存证证书
   - **保全网**（www.baoquan.com）：区块链存证 + 司法鉴定
   - **权利卫士 App**：手机拍照/录屏即存证，适合过程材料
   - **中国版权保护中心 DCI 体系**：官方数字版权登记
3. 上传后平台生成**唯一哈希值 + 时间戳 + 区块链存证编号**，出具《电子数据存证证书》。
4. 把证书 PDF 原样放入佐证材料。

**证明逻辑（写在证书前一页）：** "本作品源代码及成果文件已于 2026-10-__ 经第三方区块链存证固化，存证编号 ____，哈希值 ____，任何第三方可通过该编号在司法区块链节点核验，证明作品完成时间与内容完整性。"

#### 1.3 软件著作权申请（可选，现在提交，先放受理材料）

- 官方审查周期：**自受理日起 60 个工作日内**审查完成（中国版权保护中心），实际拿证普遍 2–4 个月，**赶不上 10-15 提交**。
- 但**现在立即申请**，可在佐证材料中放入：
  - 《软件著作权登记申请表》
  - 提交成功截图 / 《受理通知书》
  - 附一行说明："本作品软件著作权已于 2026-10-__ 提交登记申请（受理号 ____），目前处于审查阶段，证书将在后续补充提交。"
- 学生自己官网申请**官费 0 元**；代办 400–600 元；加急另收费。
- 价值：进复赛/总决赛（11 月底）时受理材料可证明"正在确权"，且明年拿证后长期可用。

#### 3.2 用户使用反馈（★必做，1–2 天，核心成效证据）

**没有真实用户是"应用成效"最大的软肋，现在补还来得及。**

**做法：**
1. 用**问卷星/腾讯问卷**做一份反馈问卷，题目控制在 8–12 题：
   - 使用场景（多选）：导航找路 / 食堂排队参考 / 查看校园事件 / 报修反馈 / 社交 / 其他
   - 各功能满意度（1–5 分量表）：3D 地图、导航、事件上报、AI 助手

   - 推荐意愿（0–10 分，可算 NPS）

2. 把 APK 公网链接 + 在线网址发给**同学、室友、社群、其他班级群**，目标 **20–30 份有效反馈**（越多越好，30 份以上统计才有意义）。
3. 收集后：
   - 问卷后台自动生成的统计图表（满意度分布、NPS）截图
   - 挑选 10–15 条**真实、具体、正面为主**的文字评价（可匿名化处理，截掉头像昵称）

| **SceneCraft**（学术，2024） | LLM 生成 Blender 代码场景 | CLIP 分数较 BlenderGPT 提升 45.1%，约束通过率 88.9 | 面向影视叙事场景，无真实地理/建筑约束，不产出可导航可运营资产 | 本作品面向真实校园规划，场景满足路网连通、建筑尺度、锚点对接等工程约束，产物可直接被 App 消费 |
| **SimWorlds**（学术，2026） | 多智能体生成动态 Blender 场景 | planner/coder/reviewer 协作，含物理一致性基准 | 研究原型，无 C 端产品与用户闭环 | 本作品打通"场景建造 → C 端应用 → 用户反馈"全链路 |
| **UrbanWorld**（学术） | 城市级 3D 世界模型 | 文本/图像生成城市，5 项视觉指标 | 宏观城市尺度，无单体建筑细节与运营 | 本作品聚焦校园单体建筑 + 七区格局，精度到楼层/锚点 |
| **像素南开 VoxelNKU**（高校实践） | Minecraft 复原校园 + 大模型导览 + 小程序 | 21 名学生精确复原八里台校区 | 手工复原为主，依赖人工逐块搭建 | 本作品采用 AI 脚本化参数建模，改语言/改尺度只需调参数，可 2 周复制到新校园 |
| **高校数字孪生平台**（中科大/同济/北师大等） | 官方数字孪生 | 三维底座 + 物联数据 + 事件治理 | 依赖校方经费与测绘数据，B 端管理导向，学生不参与共创 | 本作品 C 端导向、UGC 众包 + AI 可信度治理，学生即用户即数据源 |
| **Meshy / Tripo / 混元3D**（商业） | 单体 text/image-to-3D | 快速生成单体模型 | 生成的是孤立资产，不成场景、不可导航、无运营 | 本作品产出的是有道路、有分区、有锚点、可运营的完整场景 |

#### 4.2 差异化结论（可直接写进报告）

> 现有同类成果要么"只造场景不做运营"（学术/商业 3D 生成），要么"只做平台不做共创"（官方数字孪生），要么"靠人工堆"（Minecraft 复原）。本作品的独特性在于：**以 AI 脚本化参数建模为"场景建造"内核，以"事件众包 + AI 可信度治理"为运营闭环，首次把"AI 造场景"与"C 端用场景"连成自生长循环**，且方案具备跨校快速复制能力。
