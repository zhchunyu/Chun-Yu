# 共享仓库地图接入（B 方案）设计

> 状态：已获用户确认，2026-09-26
>
> 本文针对当前 CampusTwin 的地图替换和共享仓库能力接入。它补充并覆盖此前“山西农大地图作为主地图”的实施方向；旧方案仍保留为历史记录，不再作为本次改造的地图来源依据。

## 1. 目标

把当前 CampusTwin 改造成“3D 主视角 + 2D 总览”的校园数字孪生演示版：

- 3D 是首屏和日常操作主界面；
- 2D 使用共享仓库的山河大学总平面图，作为快速总览和回退场景；
- 2D、3D、地点详情、热点、当前位置和路线共用同一套地点 ID、锚点和道路数据；
- 结合共享仓库的事件、路网封闭、位置来源和演示模式设计；
- 保留当前管理员发布和本地演示数据，预留真实 API，不在本阶段引入登录或真实 GPS。

## 2. 已确认的来源和边界

共享仓库 `zhchunyu/Chun-Yu` 的主线是完全虚构的“山河大学”，包含：

- `02-三维资产/web-demo/assets/campus.glb`：可在浏览器加载的全园模型；
- `02-三维资产/web-demo/preview.html`：独立 3D 模型预览和导航页面；
- `02-三维资产/web-demo/src/`：校园场景、地标、事件和预览逻辑；
- `04-应用开发/实时输入接入设计.md`：事件数据源、位置来源、可信度和封路重算方案；
- `site/src/navigation.campus.js`：97 个路网节点、109 条边、A*、路线平滑和建筑锚点约定。

因此本次改造统一采用“山河大学”身份。山西农业大学的 2D 图片和模型不再作为主地图，但历史资源保留在项目中，便于未来建立真实校园数据适配器。

本阶段不做：

- 不重新建模；
- 不把共享仓库的整套独立 HTML 页面嵌入 React；
- 不直接复制仓库中的前端全局状态；
- 不接真实后端、WebSocket、PostGIS 或真实定位；
- 不改变当前设置、角色切换、管理员发布和本地持久化的基本入口。

## 3. 产品形态：B 方案

### 3.1 首屏

首屏默认打开 3D 山河大学全园模型：

```text
顶部：校园名称 / 搜索 / 角色 / 状态同步
左侧：可收起工具栏
中央：3D 主地图、标签、热点、当前位置、路线
右侧：地点详情或事件详情
底部：路线预览与分段信息
地图工具：查看 2D 总览、重置视角、图层、我的位置、设置
```

3D 上完成搜索、选点、路线规划和管理员发布。用户点击“2D 总览”时，切换到共享仓库 SVG；返回 3D 时保留当前选中地点、路线和过滤条件。

### 3.2 2D 辅助视图

2D 视图是共享仓库总平面图的快速查看器，不承担独立的一套业务状态：

- 进入时显示地图来源和版本；
- 资源加载失败时保留 3D 主界面，并给出明确错误提示；
- 从 3D 选中的地点可在 2D 总览中保持同一地点状态；
- 当前路线、起点、终点和热点作为覆盖层叠加；
- 低性能设备可切换到 2D 总览；
- 2D 退出后回到 3D，不丢失路线和筛选状态。

## 4. 统一空间数据模型

所有地图功能消费同一份领域数据，禁止 2D 和 3D 各维护一份地点表。

```js
{
  id: 'library',
  name: '图书馆',
  aliases: ['中心图书馆', '主图书馆'],
  category: 'learning',
  anchorId: 'ANCHOR_Library',
  mapPosition: {
    '2d': { x: 0.52, y: 0.36 },
    '3d': { x: 64, y: 30, z: -86 }
  },
  entryNodeId: 'library_entrance',
  status: 'open',
  services: ['reading', 'self-study'],
  source: 'local-demo'
}
```

约定：

- 2D 坐标使用归一化平面坐标，避免地图图片尺寸变化导致标签漂移；
- 3D 坐标使用 GLB 对应的 Three.js 坐标；
- `anchorId` 是未来接入仓库锚点和真实后端的稳定键；
- `entryNodeId` 负责把建筑入口连接到路网；
- `source` 记录数据来自本地演示、共享仓库适配器或未来 API。

## 5. 路线规划

### 5.1 数据来源

优先建立共享仓库路网适配器，把仓库中的节点、边、建筑入口和路线计算封装成当前项目的领域接口：

```text
shared navigation data
  → campusNavigationAdapter
  → routeGraph / createCampusRoute
  → RouteDock + 2D overlay + 3D overlay
```

当前路线模式继续保留：最短、无障碍、避开施工、避雨、夜间安全。

### 5.2 动态封路

事件不能只显示热点颜色，还要影响路线：

```text
管理员发布施工/阻断事件
→ affectedEdgeIds / blockedEdges
→ buildGraph(blockedEdges)
→ A* 重新规划
→ 2D / 3D 同步显示新路线和绕行原因
```

不修改 A* 核心算法；动态状态进入图构建阶段，便于后续接入真实 API 和恢复封路。

### 5.3 结果反馈

路线面板必须显示：起点、终点、距离、预计时间、路线模式、已避开路段、受影响事件、不可达原因和重新规划入口。起点和终点相同则显示“已到达目的地”，不绘制 0 米路线。

## 6. 事件和热点

采用共享仓库的可插拔数据源思想，但首版只实现本地数据源：

```text
MockSource   本地预置事件和自动演示
ManualSource 管理员手动发布/关闭
RealSource   只定义接口，不在本阶段连接后端
```

事件模型至少包含：

- `id`、`type`、`locationId`、`anchorId`；
- `status`：draft、pending、published、closed、expired；
- `severity`、`credibility`、`source`、`createdAt`；
- `affectedEdgeIds`、`message`、`updatedAt`。

事件状态会投影到三处：地点详情、地图热点、路线约束。首版不实现真实 AI 抽取，但保留与共享仓库一致的处理边界：未来只替换事件输入层，地图和路线消费方不变。

## 7. 组件和文件边界

### 7.1 数据与领域层

- `src/data/campusMap.js`：切换山河大学地图资源和版本信息；
- `src/data/locations.js`：重建共享仓库地点、别名、锚点和入口数据；
- `src/data/routeGraph.js`：接入共享路网或建立等价适配器；
- `src/data/events.js`：统一事件字段和受影响路段；
- `src/data/campusDataSource.js`：保留本地数据源接口，新增共享仓库适配层；
- `src/domain/route.js`：只负责路线结果，不直接读取 UI 或模型文件；
- `src/domain/mapScene.js`：管理 2D/3D 场景切换状态。

### 7.2 地图层

- `src/features/map/Campus2DViewer.jsx`：2D 总览、标签、路线和热点；
- `src/features/map/Campus3DViewer.jsx`：共享 GLB、3D 标签和路线覆盖层；
- `src/features/map/MapWorkspace.jsx`：统一传递地点、事件、路线和场景状态；
- `src/features/map/MapSceneSwitcher.jsx`：切换 2D/3D，并管理 3D 加载状态；
- `src/features/routes/RouteDock.jsx`：两种场景共用的路线面板。

### 7.3 资产

- 共享仓库 GLB 进入 `public/assets/campus.glb`；
- 共享仓库总平面图进入 `public/assets/shanhe-campus-plan.svg` 或等价转换后的 Web 资源；
- 资源入口只通过 `campusMap.js` 配置，不在组件内硬编码路径。

## 8. 错误、性能和兼容

- 2D 资源失败：显示错误状态，但允许搜索和查看基础地点列表；
- 3D 资源失败：回退 2D，保留路线和当前选择；
- GLB 加载中：显示进度、文件版本和取消/返回 2D 操作；
- WebGL 不支持：不阻塞 2D 使用；
- 模型性能：按共享仓库已有 high/balanced/perf 思路预留质量档位；
- 2D 仅在用户主动切换时加载，不影响 3D 主视角体验；
- 所有标签、路线和热点都使用稳定的 `locationId`，避免模型版本变化时组件互相引用坐标。

## 9. 分阶段实施

### 阶段一：地图身份和资产切换

1. 接入共享仓库 2D 总平面资源；
2. 将首屏标题、来源和地点数据统一改为山河大学；
3. 将 3D 入口切换为共享 `campus.glb`；
4. 完成 2D/3D 资源加载、失败回退和版本显示。

### 阶段二：统一标签与路线

1. 建立共享地点 ID、锚点和入口表；
2. 将路线图适配到共享节点和边；
3. 让路线在 2D 和 3D 之间同步；
4. 加入动态封路和重新规划反馈。

### 阶段三：共享事件能力

1. 管理员发布热点和施工事件；
2. 事件投影到 2D/3D；
3. 事件影响路线；
4. 增加 readonly / interactive 演示模式开关；
5. 预留 Mock / Manual / Real 数据源替换点。

## 10. 验收标准

- 首屏默认 2D，页面不等待 GLB 加载；
- 2D 和 3D 显示同一校园名称、地点名称和事件状态；
- 2D 选择图书馆后进入 3D，能聚焦到图书馆附近；
- 同一组起点终点在 2D 和 3D 显示一致的路线信息；
- 发布阻断事件后，路线距离或状态发生可见变化；
- 3D 加载失败时仍能使用 2D 搜索和路线；
- 刷新页面后设置、模拟位置和管理员本地修改仍可恢复；
- 单元测试覆盖地图资源、地点锚点、路线适配、封路重算和 2D/3D 状态切换；
- `npm test -- --run` 和 `npm run build` 均通过。
