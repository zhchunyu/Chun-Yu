# CampusTwin 手机横屏与工具栏布局设计

## 背景

当前移动端样式主要按竖屏尺寸定位控件。地图搜索、场景切换、地图工具栏、路线面板等元素会叠在地图区域上，横屏时容易互相遮挡。普通浏览器打开网页时会沿用设备方向，网页无法可靠地在页面加载时自行转为横屏。

## 目标

- 在手机竖屏打开时提供清楚的“进入横屏地图”入口。
- 点击入口后请求全屏，并在浏览器支持时锁定为横屏。
- 锁定不受支持或失败时说明需要手动旋转；设备进入横屏后自动显示地图。
- 横屏下把工具栏和路线操作放入独立布局区域，展开工具栏时地图缩小，不被工具栏覆盖。
- 为用户提供退出横屏全屏状态的控件。

## 方案

### 横屏进入

手机竖屏打开时显示进入提示和按钮。按钮在用户手势内请求全屏并尝试调用 `screen.orientation.lock('landscape')`。如果全屏或方向锁定失败，提示用户手动旋转手机；检测到横屏后隐藏提示并显示地图。若页面打开时已经是横屏，则直接显示地图。桌面布局不请求方向锁定。

方向锁定能力因浏览器而异，通常需要移动设备和全屏上下文；失败是预期分支，应用必须保留手动旋转的路径，不应阻塞地图访问。依据：[MDN ScreenOrientation.lock()](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock)。

### 横屏工具区

- 页面使用动态视口高度并计入设备安全区，不产生页面级滚动。
- 地图工作区采用两列结构：左侧是保留宽度的工具栏，右侧是地图区；折叠工具栏时窄列显示图标，展开时增加左列宽度并压缩地图区。
- 搜索和场景切换放入地图区顶部控制行。
- 路线面板放入地图区下方的预留行；地图视口不延伸到路线面板下面。
- 3D 地图控制按钮留在地图区边缘。状态来源等次要信息在手机横屏下收起或隐藏，避免争用地图面积。
- 地点详情与路线预览继续按现有状态流切换：规划路线后关闭地点详情，避免两个面板同时占用视口。
- 横屏全屏状态提供退出操作，解除方向锁并退出全屏。

### 未采用的方案

- **竖拿手机时旋转整页内容：**不依赖方向锁，但浏览器栏、输入法和触控方向会让操作不自然。
- **只提示用户手动旋转：**兼容性最好，但没有尝试浏览器提供的横屏锁定能力。

## 代码范围

- 在应用外壳增加移动横屏进入/退出状态和方向变化处理。
- 调整 `MapWorkspace` 的移动横屏结构，让工具栏宽度参与布局计算。
- 调整 `RouteDock` 的横屏定位，使其占用独立底部区域。
- 保留桌面布局和既有竖屏布局；不增加 PWA、服务端或跨设备同步功能。

## 失败处理

- `requestFullscreen()` 或方向锁返回拒绝时捕获错误，不显示未处理异常。
- 方向锁失败时显示“请将手机旋转至横屏”，并监听方向变化；页面仍允许退出全屏。
- 横屏过程中用户退出全屏或方向锁定时，恢复对应按钮和提示状态。

## 验收

1. 390×844 竖屏下显示横屏入口；点击后能锁定的浏览器进入横屏，不能锁定时出现手动旋转提示。
2. 844×390 和 932×430 横屏下地图、搜索、场景切换、工具栏、路线面板均可见且不会互相覆盖。
3. 工具栏展开时地图区域缩小；页面无横向或纵向滚动，控件不进入设备安全区。
4. 路线面板出现时占用独立布局空间，地图内容不被其遮挡；退出横屏后可继续使用应用。
5. 桌面端既有布局保持不变。

## 实施约束

- 使用现有 React 与 CSS，不新增运行时依赖。
- 不把浏览器横屏锁定描述成所有设备都保证可用。
- 不修改路线算法、地图数据或本地存储行为。
