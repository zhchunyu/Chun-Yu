> 基于 2026-09-19 的 13 轮问答整理。**这是当前唯一的需求事实来源**，有偏差请直接改这份文件。

## 一、产品定义

| 项 | 内容 |
| --- | --- |
| **一句话定位** | 面向全体在校学生的**实时校园态势社区** —— 把散落的信息聚合成一张可看见、可互动、可预警的 3D 校园地图 |
| **产品形态** | 3D 数字孪生校园 ＋ AI 内容社区 ＋ 生活服务聚合，三者融合 |
| **终端** | **手机 App**（Flutter / React Native 方向） |
| **核心痛点** | **校园信息孤岛**：<br>① 实时校园信息不共享（堵车、排队、突发状况没人知道）<br>② 校园安全事故不知情<br>③ 办事必须去官网逐个查询，极其麻烦 |

### 核心闭环（待确认）

```
学生上报事件（带位置）
      ↓
AI 判断：分类 / 去重 / 可信度评分 / 聚合
      ↓
在 3D 校园地图上实时打点标记
      ↓
其他学生看见 → 互动、跟帖、验证、前往
      ↓
官方新闻经 AI 分析后进入同一信息流
```

---

## 二、AI 能力内核（两条主线）

### 主线 1：AI 生成 3D 校园资产 ★ 差异化亮点
- 文本 / 图片 → 校园建筑、场景、道具的自动化生成
- 工具链已就绪：`cad` skill → STEP/DXF；`cad-viewer` 实时预览；Blender MCP 实时场景
- **这是「技术实现 20 分」与「创新性 20 分」的主要得分点**

### 主线 2：多模态内容生成与推荐
- 信息聚合与去重、可信度评分
- 官方新闻的 AI 分析与结构化发布
- 内容生成（帖子、活动、海报）与个性化推荐

### 技术路线：**混合路线**
- 开源小模型 → 专项任务（分类 / 去重 / 可信度评分 / 推荐）
- 大模型 API → 生成类任务
- ⚠️ 显卡 / 算力情况**尚未确认**，暂按不依赖本地大算力设计

## 三、数据来源（三路汇聚）

| 来源 | 说明 |
| --- | --- |
| **学生 UGC 众包** | 学生发帖上报，AI 做去重、验证、聚合 |
| **官方系统对接** | 教务 / 后勤 / 保卫处等系统的数据与通知 |
| **公开渠道抓取** | 校园官网、公众号、通知公告 → AI 分析后发布 |

> ⚠️ **合规提醒**：UGC 上报安全事件存在虚假信息风险，发布错误的安全预警可能引发法律责任。
> AI 的**可信度评分与交叉验证机制**必须做实，这是「合规与知识产权」要求项的关键。

## 四、3D 校园地图方案

| 维度 | 决策 |
| --- | --- |
| **场景性质** | **真实校园骨架 ＋ 未来感改造**（智慧灯杆、数据可视化光带、AR 标记等） |
| **建模精度** | **LOD 融合策略**：<br>· 骨架层：体块化建筑 ＋ 道路/绿化，位置关系准确<br>· 精细层：重点建筑（校门、图书馆、主教学楼）做细节<br>· 降级层：2.5D 平面地图 ＋ 3D 点缀，用于移动端性能兜底 |
| **建模依据** | **先搭示意版** —— 不追求地形真实，优先把 AI 打点与交互跑通，细节后补 |
| **渲染方案** | App 内 **WebView 内嵌 Three.js 场景**（生态成熟、性能可控） |
| **技术栈** | 前端 App：Flutter / RN；3D：Three.js；后端：待定（建议 Python/FastAPI） |

## 七、近期目标

**第一优先级：3D 演示 Demo（单场景闭环）** —— 做出 3D 校园 ＋ 实时打点的可运行效果

Demo 内容：聚焦一个区域（如食堂 / 操场），完整演示
**学生上报 → AI 判断去重 → 地图打点 → 他人看见并互动** 的闭环。

**Demo 形态**：**先做网页版**（Three.js 可交互原型，能漫游 + 点击/自动弹出事件标记），
**最后再打包**进 App 的 WebView。网页版优先的好处是评审点开链接即可验证，队友也能直接集成。

> ⚠️ **修正（2026-09-19）**：本团队**没有校赛**（校赛由学校自行组织，本校未举办），
> 直接进入省赛/区域赛。演示视频是省赛/区域赛的提交物，**当前阶段无需准备视频**，
> Demo 先作为**内部验证与叙事工具**使用。

## 九、已识别的风险

| 风险 | 说明 | 建议 |
| --- | --- | --- |
| **范围蔓延** ⚠️ 最高 | 产品同时要覆盖 3D 孪生 + 内容社区 + 生活服务，三者都做极易做不完 | 校赛阶段**只深做「实时信息地图」一条主线**，其余作为"已规划"呈现 |
| **AI 深度不足** | 若核心能力只是调 API，会被质疑算法创新性 | 可信度评分、去重聚合、校园资产生成为自研亮点 |
| **UGC 虚假信息** | 错误的安全预警有法律风险 | 建立可信度分级 + 官方源交叉验证 |
| **提交材料赶工** | 7 项材料集中在最后做容易漏 | 材料随开发同步积累，不等到最后 |
| **学校信息泄露** | 材料中出现校名/Logo 直接扣分或取消资格 | 3D 场景中也不要出现校名门牌、校徽 |
