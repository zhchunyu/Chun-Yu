# AutoDL 服务器部署清单 —— 把两个 LoRA 变成可调用的接口

> 方案前提：**长期租服务器，权重不下载，模型留在服务器上**。
> 目标产出：**一个公网调用地址** + 三个可用模型名（`extract` / `persona` / 基座）。

---

## 0 ★ 先说清楚三件事（避免白花钱）

### ① 成本：长期租 GPU 跑 14B 推理不便宜

| 卡型 | 大约单价 | 一个月（7×24） |
|---|---|---|
| RTX 4090 24G | ¥1.8~2.5 / 小时 | **¥1300 ~ ¥1800** |
| **RTX 5090 32G**（本机） | 以 AutoDL 控制台实时价为准 | 按单价 × 730 小时自己算 |
| A100 40G | ¥5~8 / 小时 | ¥3600 ~ ¥5800 |

> ★ 上表是**参考量级**，实际以 AutoDL 控制台显示为准。

**省钱做法（推荐）**：AutoDL 支持**无卡模式开机**（约 ¥0.1 / 小时）。
- 平时 → **无卡模式挂着**：环境不丢、数据不丢、地址不变，成本近乎为零
- 演示 / 联调前 → 切成**有卡模式**，起 vLLM，队友开调
- 用完 → 切回无卡模式

> ★ 无卡模式下 GPU 不可用，vLLM 起不来 —— 这是预期行为，不是故障。

### ② 显存：**决定你能不能直接跑**（★ 本机实测结论）

Qwen2.5-14B 用 fp16 加载约 **29.4 GB 权重**，再加两个 LoRA（rank 128 / target=all，fp16）约 **2.2 GB**，
再加 KV cache ⇒ **合计约 32 GB 起步**。

| 显存 | 方案 |
|---|---|
| **≥ 70 GB**（A100 80G / H100） | 直接用 fp16 基座，`serve_vllm.sh` 开箱即用 |
| **38 ~ 70 GB**（A100 40G） | fp16 勉强，需压小 `--max-model-len`；或直接走 AWQ 更稳 |
| **< 38 GB**（**RTX 5090 32G** / 4090 24G / 3090 24G） | ★ **必须用 AWQ 4bit 基座**（约 9.5 GB） |

> ★★ **5090 32GB 也装不下 fp16** —— 29.4（权重）+ 2.2（LoRA）+ KV cache > 32 GB，
> `--gpu-memory-utilization 0.92` 只给 29.4 GB，**光加载权重就 OOM**。
> 走 AWQ 后基座只占 ~9.5 GB，**剩余约 17 GB 全给 KV cache** ⇒ 长上下文 + 高并发都很宽裕。

**怎么换 AWQ 基座：**

```bash
pip install -U modelscope
modelscope download --model Qwen/Qwen2.5-14B-Instruct-AWQ \
  --local_dir /root/autodl-tmp/models/Qwen2.5-14B-Instruct-AWQ
```

然后把 `serve_vllm.sh` 里的 `BASE` 指向 `/root/autodl-tmp/models/Qwen2.5-14B-Instruct-AWQ`
（脚本默认已经是这个值）。AWQ 模型 vLLM 会**自动识别**；若没识别再加 `--quantization awq`。

> ★★ **AWQ 基座要复测**：你的 LoRA 是在 **nf4 量化基座**上训的，挂到 AWQ 基座上会有轻微精度损失。
> 上线前**必须重跑一次地点合法率验收**（V10 的核心指标是 6/6 = 100%，见 `V10验收与三路对比_结论.md`）。

### ②b ★ RTX 50 系 = Blackwell 架构（sm_120），版本有要求

5090 比 4090 新一代，**PyTorch / vLLM 太旧会直接跑不起来**：

- 需要 **PyTorch ≥ 2.7（CUDA 12.8+）**
- vLLM 版本要够新（Blackwell 支持是后期版本才加的）
- `pip install -U vllm` 拉最新版一般没问题
- **报 `no kernel image is available for execution on the device`** ⇒ 就是版本太旧，**不是卡坏了**

### ③ 环境放在哪：**别装到系统盘**

`pip install` 默认装进系统盘。**释放实例 ⇒ 环境全没，但数据盘 `/root/autodl-tmp` 还在。**

两个选择：
- 装到数据盘：`pip install -U vllm -t /root/autodl-tmp/pylibs`，并 `export PYTHONPATH=/root/autodl-tmp/pylibs:$PYTHONPATH`
- 或装完用 AutoDL 的**「保存镜像」**把整个环境固化成自定义镜像（换机器也能用）

## 0.5 ★★ 先选路：WebUI 能问答 ≠ 有接口

### 先分清三个东西

| | LLaMA-Factory **WebUI** | LLaMA-Factory **API** | **vLLM** |
|---|---|---|---|
| 端口 | 7860 | **6006** | **6006** |
| 给谁用 | **人**：打开网页点着聊 | **程序** | **程序** |
| 协议 | Gradio 界面 | ✅ **OpenAI 兼容** | ✅ **OpenAI 兼容** |
| 队友能用吗 | ❌ **不能** | ✅ 能 | ✅ 能 |
| 要装新东西 | — | 不用 | 要装 vLLM |
| 量化 | — | **nf4（与训练一致）** | AWQ（有精度损失） |
| 并发吞吐 | — | 低 | **高（10 倍级）** |

> ★ **端口统一用 6006**（AutoDL 自定义服务默认映射这个口），两条路都省得记。

> ★★ **WebUI 能聊天只证明一件事：训练环境是好的**（torch / CUDA / bitsandbytes / LoRA 加载都正常）。
> **它不是接口** —— 队友拿到 7860 那个地址没法用代码调。

### 两条路，建议按顺序走

| | **路 A：LLaMA-Factory API**（先走） | **路 B：vLLM**（按需升级） |
|---|---|---|
| 脚本 | `start_api.sh` | `serve_vllm.sh` |
| 要装新东西 | **不用**，环境现成 | 装 vLLM + 拉 AWQ 基座 |
| 量化 | **nf4 —— 与训练完全一致，无精度损失** | AWQ —— 有损失，**必须复测** |
| 显存 | ~10 GB | ~9.5 GB |
| 今天能用吗 | **能** | 要等下载 + 装环境 |
| 适合 | **演示、联调、低并发** | 生产、高并发 |

**建议**：先用**路 A** 把链路打通（今天就能给队友地址），
等真有高并发需求（多人同时上报、要压首 token 延迟）再升级到**路 B**。

### ★★★ 但有一条硬约束：路 A 只能挂一个 LoRA（2026-10-05 查源码确认）

队友的代码是**按 `model` 名区分**的（`model: "extract"` / `model: "persona"`）。
查 LLaMA-Factory 官方源码 `src/llamafactory/api/app.py`：

```python
@app.get("/v1/models", ...)
async def list_models():
    model_card = ModelCard(id=os.getenv("API_MODEL_NAME", "gpt-3.5-turbo"))
    return ModelList(data=[model_card])          # ← 只返回一个名字

@app.post("/v1/chat/completions", ...)
async def create_chat_completion(request: ChatCompletionRequest):
    return await create_chat_completion_response(request, chat_model)   # ← 不读 request.model
```

⇒ **路 A：`model` 字段被完全忽略，一个进程只有一个 adapter。**
给 `model: "persona"` 会**静默用 extract adapter 回答** —— 不报错，但人设失效。

| | 路 A | 路 B |
|---|---|---|
| 按 `model` 名切 LoRA | ❌ **不支持** | ✅ `--lora-modules extract=… persona=…` |
| 能同时服务 extract + persona | ❌ | ✅ |
| 适合 | **单适配器联调 / 分别验证两个 LoRA** | **正式给队友联调** |

> ★ **结论修正**：早先写「两条路协议相同 ⇒ 队友代码不用改」**只对了一半**。
> 协议格式确实相同，但**能按 model 名切 adapter 的只有路 B**。
> ⇒ 队友要**同时**用 extract 和 persona，就**必须走路 B**（vLLM）。
> ⇒ 若只是想**今天先验证 extract 通不通**，路 A 仍然最快。

> ★ 顺手记住：`/v1/models` 返回的名字由 `API_MODEL_NAME` 决定，默认是 `gpt-3.5-turbo`。
> 它只是个**标签**，不影响路由 —— 别拿它当「实际可用模型名」填回执。

## 1 确认资产都在（1 分钟）

```bash
# 基座（★ 5090 32G 要用 AWQ 版，见 §0②）
ls -la /root/autodl-tmp/models/Qwen2.5-14B-Instruct-AWQ | head
# 原来那份 fp16 基座（大显存机器才用）
ls -la /root/autodl-tmp/models/models/qwen--Qwen2.5-14B-Instruct/snapshots/master | head

# 两个 LoRA
cd /root/autodl-tmp/output && ls -la qwen25-14b-auv-v10-extract qwen25-14b-auv-v7
```

两个 LoRA 目录里**必须有**：
```
adapter_model.safetensors    ← 权重本体
adapter_config.json          ← ★ 关键：里面有 r=128 / lora_alpha=256 / target_modules
```

> ★ `serve_vllm.sh` 会自动读 `adapter_config.json` 并把 `r` / `alpha` 打出来核对。
> 如果 `r` 不是 **128**，脚本里的 `--max-lora-rank` 要跟着改（否则直接报错）。

## 2 装 vLLM（5~10 分钟）

### ★ 先搞清楚 vLLM 是干什么的

你那两个 LoRA 训完之后，本质就是**两个几十 MB 的参数文件**，它们自己不会说话。
**vLLM 是推理引擎**，负责：

| 它做什么 | 对你的意义 |
|---|---|
| 把基座 + LoRA **装进显存**，高效并发处理请求 | 队友的请求不用排队 |
| 把模型**包装成 HTTP 接口**（OpenAI 兼容） | 队友用 `requests` / OpenAI SDK 就能调，不用懂模型 |
| **同时挂多个 LoRA**（`--lora-modules`） | ★ 两个 LoRA **共用一份 14B 基座**，不然显存直接翻倍 |
| 提供 `--api-key` 鉴权 | 防止别人白嫖你的 GPU |

**不装它 ⇒ 模型只是硬盘上的一堆文件，队友拿不到任何东西。**

（备选：`transformers` + FastAPI 自己写 —— 但并发和多 LoRA 切换都要自己实现，没必要。）

### 装

```bash
python -c "import vllm; print(vllm.__version__)" 2>/dev/null || \
  pip install -U vllm -t /root/autodl-tmp/pylibs
export PYTHONPATH=/root/autodl-tmp/pylibs:$PYTHONPATH
python -c "import vllm; print('vLLM', vllm.__version__)"
```

> AutoDL 有些镜像（如 `vllm` 官方镜像）已预装，先测再装。
> ★ **RTX 5090 是 Blackwell（sm_120）**，对版本敏感 ⇒ 一定要 `-U` 拉最新。
> ★ **vLLM ≥ 0.6** 才完整支持 `--max-lora-rank`；**50 系显卡建议直接上最新版**。

## 3 起服务

把 `serve_vllm.sh` 上传到 `/root/autodl-tmp/`，**先改一个地方**：

```bash
API_KEY="auv-你定一个别人猜不到的长串"    # ★★★ 必改
# BASE 默认已指向 AWQ 版（5090 32G 的正确配置），不用改
```

然后：

```bash
cd /root/autodl-tmp
bash serve_vllm.sh
```

看到这几行就说明起来了：
```
INFO:     Uvicorn running on http://0.0.0.0:6006
INFO:     Application startup complete.
```
★ 首次加载 14B 约需 **2~4 分钟**，属正常。

后台常驻：
```bash
nohup bash serve_vllm.sh > serve.log 2>&1 &
tail -f serve.log
```

## 4 本机自测（服务器上跑）

```bash
# ① 健康检查
curl -s http://127.0.0.1:6006/v1/models -H "Authorization: Bearer auv-你定的那个串"

# ② 试 extract（结构化提取）
curl -s http://127.0.0.1:6006/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer auv-你定的那个串" \
  -d '{
    "model": "extract",
    "temperature": 0,
    "messages": [{"role":"user","content":"三食堂二楼窗口排队太久了，等了快二十分钟"}]
  }' | python -m json.tool

# ③ 试 persona（人设回应）
curl -s http://127.0.0.1:6006/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer auv-你定的那个串" \
  -d '{
    "model": "persona",
    "messages": [{"role":"user","content":"图书馆现在人多吗"}]
  }' | python -m json.tool
```

**验收判据**：
- `extract` 返回**严格 JSON**（9 字段：type / building_id / building_name / floor / severity / description / estimated_wait_min / time_window / advice）
- 文本没提地点时 `building_name` 必须是 **`null`**（不是硬猜一个楼名）
- `persona` 返回自然语言、**不带书名/术语**

## 5 ★ 开公网端口（队友才能调）

1. AutoDL 控制台 → **容器实例** → 你的实例 → **自定义服务**
2. 端口填 **`6006`**（与脚本里 `PORT` 一致）
3. 保存后得到形如 `https://xxxxx-6006.xxxx.seetacloud.com` 的地址
4. **把这个地址填进 `队友调用说明.md`**

> ★★ **自定义服务是公网公开的、没有额外鉴权** ⇒ `API_KEY` 是你唯一的门锁，**必须设、必须长**。
> ★★ **实例重启后地址/端口可能变化** —— 每次重启后回这一步重新确认一遍，再通知队友。

## 6 上线前必须做的一件事：**复测**

部署环境和训练环境不同（尤其 24G 卡走 AWQ 的情况），**不能假设效果一样**。

```bash
# 用 V10 的评估集打线上接口，重新算「地点合法率」
python check_v10.py            # ← 改成打 http://127.0.0.1:6006 的版本
```

**门槛**：地点合法率仍须 **6/6 = 100%**，JSON 可解析率 100%。
达不到 ⇒ 说明基座换了精度掉了 ⇒ 回头找原因（换回 fp16 卡 / 调 AWQ 版本）。

## 7 给队友什么

**不是权重文件，是这三样**（都在 `队友调用说明.md` 里）：

1. **公网地址**（第 5 步拿到的）
2. **API Key**
3. **接口约定**：模型名怎么选、请求格式、`extract` 的输出 schema

## 附：常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `CUDA out of memory` | ① 基座没换成 AWQ（5090 32G 必踩）② 调低 `--max-model-len` / `--gpu-memory-utilization` |
| `no kernel image is available for execution on the device` | ★ **50 系（Blackwell sm_120）专属**：PyTorch / vLLM 版本太旧 ⇒ `pip install -U vllm`，并确认 torch ≥ 2.7（CUDA 12.8+） |
| `ValueError: max_lora_rank` | 忘了 `--max-lora-rank 128`（默认只有 16） |
| `ImportError: vllm` 重启后出现 | 环境装在系统盘且实例被释放 ⇒ 重装到 `/root/autodl-tmp/pylibs` 或改用保存镜像 |
| 队友连不上地址 | ① 服务是不是没起 ② 端口填错 ③ 实例重启后地址变了 |
| 响应特别慢（>30 s） | 首 token 冷启动正常；持续慢 ⇒ 看并发是否过高、`--max-model-len` 是否过大 |
| AWQ 基座加载后效果变差 | 见 §0② —— LoRA 在 nf4 上训的，换 AWQ 有精度损失 ⇒ 必须复测（§6） |
