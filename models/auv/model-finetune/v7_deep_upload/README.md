## 一、这套数据是什么

**人设 LoRA 的「深度诊断」增强集。** 输入是校园现场观察 / 通行数据 / 排队数据，
输出是一段**有判断力**的分析——不是泛泛而谈，而是指出主导因素、给出量化依据、敢说"不用处理"。

| 项 | 数值 |
| --- | --- |
| 训练集 `v7_deep_train.json` | **206 条** |
| 评估集 `v7_deep_eval.json` | **22 条** |
| 合计 | **228 条** |
| 手写案例数 | **64 个**（空间 36 / 异常 14 / 排队 14） |
| 输入去重 | 100% |
| 自检 | 无书名/理论名/术语残留 · input 全局唯一 · 字段齐全 |

### 三块能力

| 块 | 条数 | 变体 | 产品功能 |
| --- | --- | --- | --- |
| **A 空间行为诊断** | 144 | 36 案例 × 4 | 场所活力评估 / 通行热度异常 |
| **B 热度异常判定** | 42 | 14 案例 × 3 | 通行热度异常检测 |
| **C 等待时间估算** | 42 | 14 案例 × 3 | 预计等待时间 |

★ A 块的 4 个变体是：完整诊断 / 一句话说清主因 / 只做一件事 / **这里面最关键的判断是什么**。
最后那个变体专门训练"抓重点"。

## 二、★★ 开工前必须先定的一件事：口吻

本集的三套 instruction 都是**专家助手口吻**：

```
你是校园空间诊断助手 / 你是校园通行热度分析助手 / 你是校园排队等待时间估算助手
```

而 V7 的 instruction 是 **AUV 同伴口吻**（"你是 AUV，校园实时态势助手……不说'您'，用'你'"）。

**产品是 C 端 App**，真实用户问"图书馆东边那条路为啥没人走"时，
AUV 该用哪种口吻回答？这决定了本集怎么用：

| 选择 | 做法 | 后果 |
| --- | --- | --- |
| **专家口吻**（现状） | 独立训，或与 V7 合并 | 信息密度高，但可能不像"同学" |
| **同伴口吻** | 需重写 228 条的 instruction 与 output 语气 | 更像 AUV，但深度分析容易被口语化稀释 |

★ **没定之前不要开训** —— 口吻会影响全部 228 条，训完再改等于白训。

## 四、怎么跑

### 1. 上传（本地 Windows）

```bash
cd models/auv/model-finetune/v7_deep_upload
python upload_v7_deep.py --host region-x.autodl.com --port 12345
```

不带参数运行会提示你输入地址和端口。

### 2. 训练（AutoDL）

```bash
cd /root/autodl-tmp
nohup llamafactory-cli train v7_deep_train.yaml > train.log 2>&1 &
tail -f train.log
```

约 228 条 × 6 epoch，14B QLoRA，视卡型 20~60 分钟。
输出在 `/root/autodl-tmp/output/qwen25-14b-auv-v7-deep/`。

**★ 不要盯 loss。** 人设回应任务的 loss 只说明"有没有练坏"，
真正要看的是生成质量（见下）。

### 3. 换个方式用：合并进 V7

如果决定把它作为 V7 的增强而不是独立模型：

```bash
cd /root/autodl-tmp/data
python -c "
import json
a=json.load(open('v7_train.json',encoding='utf-8'))
b=json.load(open('v7_deep_train.json',encoding='utf-8'))
json.dump(a+b, open('v7_train_plus.json','w',encoding='utf-8'), ensure_ascii=False, indent=2)
print(len(a),'+',len(b),'=',len(a)+len(b))
"
# 然后把 v7_train.yaml 的 dataset 改成新注册的名字（dataset_info.json 里加一条即可）
```

→ 1597 + 206 = **1803 条**。

## 五、训练完怎么验收（★ 别看 loss）

**已写成脚本，直接跑：**

```bash
cd /root/autodl-tmp && python check_v7_deep.py
```

它会跑下面 5 条测试并**自动判定命中**，最后给出 `LoRA 命中 : x/5` 的结论。

| 测试输入 | 要看什么 | 不合格的样子 |
| --- | --- | --- |
| 图书馆东侧那条小路傍晚几乎没人走（+3 条观察） | 是否**指出主导因素**（"没有视线，不是照明"） | 把三条观察逐条解释一遍 |
| 一食堂 60 人排队 / 2 个窗口 / 人均 45 秒 | 是否**给数 + 写算式** | 只说"等待较久，建议错峰" |
| 校医院五天 88/92/95/90/91 | 是否敢说**"不需要处理"** | 硬找理由说"有上升趋势" |
| 图书馆正门掉一半（第 4、5 天） | 是否看出**点位转移** | 只看单点说"人变少了" |
| 快递驿站 30 人 / 2 台 / 60 秒 | 是否指出**真瓶颈在"找件"** | 只说"建议加窗口" |

**★ 最关键的一条**：第 3 条。如果模型学不会说"不用处理"，
说明它只学会了"给结论"，没学会"什么时候不给结论"——那这套数据的核心价值就没进去。

**判据**：5 条里至少 4 条命中"要看什么"那一列 ⇒ 形态对了，可以继续加量；
不到 3 条 ⇒ 问题在数据形态，加量没用，要回头改样本。

## 六、常见坏味道

| 现象 | 对策 |
| --- | --- |
| 输出变成"客服腔"（"您好，关于您的问题…"） | 人设没注入 → 检查 instruction 是否被覆盖 |
| 输出里出现书名或术语（"根据人性化理论"） | 数据被污染 → 重跑 `build_v7_deep.py` 看自检 |
| 分析变短、只会说结论不会给依据 | epoch 不够 → 提到 8；或 cutoff_len 太小把长输出截了 |
| 输出像 JSON（串味） | 两个 LoRA 挂错了 → 检查选的是 persona 还是 extract |
| 回复高度重复训练集句子 | 过拟合（228 条 × 6 epoch 容易）→ 降到 4 epoch |
