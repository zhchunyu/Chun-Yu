## 一、哪几本书，各自管什么

当时推荐的书分三个方向，**只有一类能转成训练数据**：

| 方向 | 书目 | 能不能转数据 |
|---|---|---|
| 开发能力类 | DDIA、Hands-On LLM、AI Engineering、Real-Time Rendering | ❌ **给人读** —— 读懂去写代码，不喂模型 |
| 喂给模型类 | （v5/v6 曾试图列书名） | ❌ **已验证无效** —— 模型只学会输出术语 |
| **校园管理 + 统计学类** | **《人性化的城市》《美国大城市的死与生》** + 统计异常检测 + 排队论 | ✅ **本方案** |

★ 原则不变：**知识走 RAG，能力走 LoRA**。这里教的是「怎么想」，不是「记什么」。
所以数据里**一个书名、一个理论名都不会出现**（脚本内置自检，命中即 `exit(1)`）。

## 二、★ 什么才算「深刻」——与 V7 那 104 条的区别

V7 已有 104 条空间诊断，但那是**判据平铺**：把「实墙无视线 / 照明不足 / 不在动线上 /
无停留理由 / 尺度失衡 / 无设施 / 路权不清」七类判据套到不同空间上。
典型句式是"三个原因叠在一起：A、B、C"。

**本方案的四条硬判据**（每条样本都必须满足至少两条）：

| # | 判据 | 反例（V7 常见） | 正例（本方案） |
|---|---|---|---|
| 1 | **指出主导因素**，不平铺 | "三个原因叠在一起" | "**主导原因是没有视线，不是照明**" |
| 2 | 有**量化**或**反直觉**判断 | "照明不足导致没人走" | "15 分钟电梯最多送约 450 人，需求接近 400" / "**有灯但照不到路面，比完全没灯更危险**" |
| 3 | **承认不确定性** | 一律给结论 | "数据不足以判断时，明确说还需要观察什么" |
| 4 | 建议分**短期/长期**，短期必须低成本 | 只给一个建议 | "先补照明（成本最低）；长期开侧门或改透空围栏" |

★ 最能体现「深刻」的是第 2 条。举例：

- **反直觉**：空旷 ≠ 舒适（20 米是车的尺度）；两端亮中间黑比全程暗更糟；有灯照不到比没灯更危险
- **量化**：电梯 15 分钟运力 450 人 vs 需求 400 人；加一个窗口把等待从 22.5 分钟降到 15 分钟，但"**依然不短，因为 60 人的基数摆在那里**"
- **敢说不用处理**：热度数据在 ±6% 内波动时明确说"不需要处理"，
  并指出"**这类数据如果报警，只会消耗注意力**"

### A · 空间行为诊断（36 个案例 × 4 变体）

输入 = 问题 + 3 条现场观察；输出 = 诊断 + 建议。

★ 输出必须写出**主导因素**，而不是把观察逐条解释一遍。
★ 四个变体：完整诊断 / 一句话说清主因 / 只做一件事 / **最关键的判断**
（第 4 个变体专门训练"抓重点"——同一个案例，要求用一句话说出最关键的判断）。
★ 36 个案例按 13 个主题组织（停留理由 / 边缘依靠 / 被看见 / 尺度 / 边界地带 / 用途单一 /
速度差 / 照明 / 动线与高差 / 天气失效 / 设施缺位 / 步骤成本 / 朝向），见上方概念覆盖表。

### B · 热度异常判定（14 个案例 × 3 变体）

输入 = 地点 + 时段 + 基线 + 最近 5 天实测值。

★★ **核心是把「幅度」和「持续性」两个轴分开看**：

| 形态 | 判定 | 案例 |
|---|---|---|
| 单日突增、次日回落 | **事件型波动**，不是异常 | 三食堂周四 640（其余四天 310-330） |
| 连续多日同向、且稳定 | **趋势性异常**，置信度高 | 主校门车流连续四天 380-400 |
| 全部在 ±6% 内交替 | **正常，不处理** | 校医院 88-95 |
| 连续单调下降 | 趋势性异常，往往对应**逐步累积**的原因 | 体育馆西门 255→175 |

★ 第 3 行是这套数据最值钱的部分 —— **教模型"什么时候不要报警"**。
一个总在报警的监测系统，等于没有监测系统。

### C · 等待时间估算（14 个案例 × 3 变体）

输入 = 排队人数 + 服务点数 + 人均服务时长；输出 = **一个数** + 算式 + 前提 + 建议。

★ 三条硬要求：
1. **必须给数**，不许说"较长"
2. **写出算式**：服务能力 = 服务点数 ÷ 单人均时长；等待 ≈ 排队人数 ÷ 服务能力
3. **说明前提**：假设到达速度稳定；如果人还在不断来，实际会更久

★ 最能体现深刻的是**边际收益**：一食堂 60 人排队，加一个窗口从 22.5 → 15 分钟，
"**改善明显，但依然不短**"——加窗口有用，但要彻底解决还得靠分流。
以及**指出真瓶颈**：快递驿站的瓶颈不在窗口数，而在"找件"这个环节。

## 四、真实样本（直接取自生成结果）

**A · 空间诊断**
```
【问题】宿舍区西侧那条近道，白天有人走，天一黑就没人了
【现场观察】
- 这条道两侧是绿化带，没有建筑界面
- 全程没有照明
- 长度约 150 米

→ 白天和晚上唯一变化的变量是能见度。两侧没有建筑，也就没有「楼上有人可能
  看到我」的可能，加上全程无灯，150 米就变成一段无法预判的路。人对未知空间
  的容忍度很低，一段看不见尽头的路就足够让人改走大路，哪怕要多绕一段。

  建议：装路灯是第一优先……绿化上建议种低矮灌木而不是高大乔木——
  保持视线通透比增加绿化面积更重要。
```

**B · 热度异常**
```
【地点】教学楼B座一层通道  【时段】09:40-10:00  【基线】150 人次
【最近 5 天】148 / 152 / 149 / 151 / 150
【要求】这条要不要处理？

→ 不需要处理。这条数据更适合作为参考基线，用来和其他波动较大的点位做对照。
```

**C · 等待估算**
```
【地点】快递驿站取件  【时刻】17:30  【当前排队】30 人
【开放服务点】2 个  【人均服务时长】60 秒

→ 预计等待约 15 分钟。
  服务能力 = 2 个台 ÷ 60 秒 = 每分钟 2 人；等待 = 30 人 ÷ 2 = 15 分钟。
  注意：假设取件流程顺畅、不需要现场找件……
  建议：驿站的瓶颈往往不在窗口数量，而在「找件」这个环节——
  如果能把取件码和货架对应好，单人均时长降下来，等待会成比例缩短，
  这比加窗口更根本。
```

## 七、两个需要你拍板的问题

**1. ★ 口吻问题（重要）**

本方案的三套 instruction 都是**专家助手口吻**（"你是校园空间诊断助手"），
沿用 V7 里 `SPATIAL_INSTRUCTION` 的做法。但产品是 C 端 App，
真实用户问"图书馆东边那条路为啥没人走"时，AUV 应该用**同伴口吻**还是**专家口吻**回答？

- 用专家口吻 → 信息密度高，但可能不像"同学"
- 用同伴口吻 → 更像 AUV 人格，但深度分析容易被口语化稀释

**2. 要不要扩量？**

现在 **228 条 / 64 个案例**。如果还要更多，方向有两个：

- **加深度**：每个案例目前 3~4 变体，可以再补"反方观点"（"如果改成 X 会不会更好"）这类对抗性提问
- **加广度**：再手写 20~30 个案例 → 扩到 ~300 条

我的建议是**先训这一版**。228 条全部是手写深度样本，
如果训完发现"模型学会抓主导因素了"，那说明形态对了，再加量才划算；
如果没学会，那问题在形态不在数量，加量只是浪费。
