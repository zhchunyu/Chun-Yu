# 06 · 虚拟校园数据规范

> 这份文档是**你和 AI 改数据时的唯一依据**。数据全部是纯文本 JSON，
> 用文本编辑器或 AI 直接改即可，不需要 QGIS、不需要投影、不需要任何 GUI 工具。

## 1. 为什么用平面米坐标

校园是**虚拟构建**的，没有真实地图影像，也不需要和真实地理对应。
所以直接用一个平面直角坐标系：

| 项 | 约定 |
|----|------|
| 单位 | **米**（1 个坐标单位 = 1 米） |
| 原点 | `(0, 0)` = 全部要素的西南角 |
| 方向 | **x 向东（右）**，**y 向北（上）**——常规数学朝向 |
| 范围 | 当前约 `x ∈ [0, 691]`，`y ∈ [0, 469]`（约 691 m × 469 m） |

好处：坐标就是米，`graph.json` 里边长直接用勾股定理算；
渲染时只需把 y 翻成 SVG 的向下方向，一行代码，没有任何地理换算。

> 想接真实地理数据？`web/geo.js` 里保留了 `makeProjection()` / `haversine()`
> 作为逃生舱，`web/verify.js` 第 9 节会验证它仍然可用。
> 但虚拟校园用不上，忽略即可。

## 2. 文件清单

```
data/campus/
├── buildings.json   建筑面（Polygon）     9 个
├── roads.json       机动车道（LineString） 3 条
├── footways.json    人行步道（LineString）16 条
└── nodes.json       路网节点（Point）     17 个
data/graph.json      由上面四个文件生成，前端消费的路网图（不要手改）
```

每个文件的统一外壳：

```jsonc
{
  "format": "campus-plan/1",   // 格式版本
  "unit": "meter",             // 单位，必须是 meter
  "layer": "buildings",        // 图层名
  "origin": "原点 (0,0) = 西南角；x 向东、y 向北",
  "features": [ /* 要素数组 */ ]
}
```

坐标一律写成 `[x, y]`（如 `[260.3, 139.6]`），**不是** `[经度, 纬度]`。

## 3. 各图层字段

### buildings.json —— 建筑面

```jsonc
{
  "type": "Feature",
  "properties": { "name": "图书馆", "type": "教学", "floors": 4 },
  "geometry": {
    "type": "Polygon",
    "coordinates": [[ [220.3,259.2], [300.4,259.2], [300.4,327.9], [220.3,327.9], [220.3,259.2] ]]
  }
}
```

- `name`：显示名称，直接渲染到地图上。
- `type`：`教学` / `体育` / `生活` / …，决定填充色（见 `web/style.css`）；
  想加新配色就在 CSS 里加一条 `.building[data-type="你的类型"]`。
- `floors`：层数，目前不渲染，留给 3D/楼层功能。
- 多边形**首尾坐标必须相同**（闭合）。
- 需要中庭/挖洞时，`coordinates` 里放多个环，第 2 个起为内环
  （前端会渲染成 `.hole`）。

### roads.json / footways.json —— 道路线

```jsonc
{
  "type": "Feature",
  "properties": {
    "from": "south_gate", "to": "cross_main",
    "name": "校园主干道", "type": "road"
  },
  "geometry": { "type": "LineString", "coordinates": [ [260.3,0.0], [260.3,139.6] ] }
}
```

- `from` / `to`：**必须**是 `nodes.json` 里存在的 `id`。这是建图的关键，
  写错了 `--check` 和 `web/verify.js` 都会报出来。
- `name`：路名，用于展示。
- `type`：`road`（机动车道，画粗实线）或 `footway`（步道，画绿色虚线）。
- 线的**第一个坐标应等于 from 节点坐标，最后一个等于 to 节点坐标**——
  `web/verify.js` 第 3 节会校验（容差 6 cm）。

### nodes.json —— 路网节点

```jsonc
{
  "type": "Feature",
  "properties": { "id": "south_gate", "name": "南门" },
  "geometry": { "type": "Point", "coordinates": [260.3, 0.0] }
}
```

- `id`：英文短标识，被 `from`/`to` 引用，**改了 id 就要同步改所有引用它的边**。
- `name`：中文显示名。

## 4. 常见改动怎么做

### 加一栋楼

在 `buildings.json` 的 `features` 数组里追加一个 Polygon，
坐标写成矩形四角 + 回到起点。例如在东北角加一栋 60×40 的楼：

```json
{
  "type": "Feature",
  "properties": { "name": "新体育馆", "type": "体育", "floors": 2 },
  "geometry": { "type": "Polygon",
    "coordinates": [[[600,400],[660,400],[660,440],[600,440],[600,400]]] }
}
```

改完**不需要重建图**（建筑不参与路由），刷新浏览器即可看到。

### 加一条路 / 一个节点

两步：① 在 `nodes.json` 里加节点（若两端已存在则跳过）；
② 在 `roads.json` 或 `footways.json` 里加一条 LineString，
`from`/`to` 指向节点 id，端点坐标与节点坐标一致。
然后**必须重建图**（双击「重建路网.bat」，或跑 `scripts/build_graph.py`）。

### 移动一个节点

改 `nodes.json` 里的坐标后，**必须同步改所有引用它的边的端点坐标**，
再重建图。`web/verify.js` 第 3 节会检查三者是否一致。

## 5. 改完怎么验证

```bash
node web/verify.js        # 57 项断言；或双击「自检.bat」
```

退出码 0 = 全绿。这一步不需要开浏览器、不需要截图、不需要人眼看图，
所以 AI 改完可以自己判断对不对。

关键断言包括：

- 数据文件 `unit` 都是 `meter`、坐标是 `x/y` 而非 `lat/lng`；
- `roads/footways` 的 `from/to` 都指向存在的节点；
- **`graph.json` 与 `data/campus/*.json` 同步**（防止改了数据忘记重建图）；
- 全部节点对连通、距离对称、满足三角不等式；
- 路径几何首尾与节点坐标对位、几何长度与权重一致。

## 6. 数据是怎么映射到屏幕上的

`x` 向西/向东、`y` 向北，SVG 的 y 轴却向下，所以渲染时做一次翻转：

```
svg_x = x - minX
svg_y = (maxY - y)          // 唯一的"投影"
```

画布尺寸直接等于坐标跨度，**1 个 SVG 单位 = 1 米**。因此：

- 缩放/平移 = 改 `<svg viewBox>`；
- 每个要素都带语义属性，便于 AI 和 CSS 直接使用：

```html
<polygon class="building" data-name="图书馆" data-type="教学" data-floors="4" .../>
<polyline class="footway" data-name="中央步道" data-from="cross_main" data-to="A_s" .../>
<g class="node" data-id="south_gate" data-name="南门">...</g>
<g class="route" data-from="south_gate" data-to="E1" data-distance-m="468.2"
   data-nodes="south_gate>cross_main>lib_gate>...">...</g>
```

也就是说：**路线算得对不对，读 DOM 属性就知道**，不必去数像素。
