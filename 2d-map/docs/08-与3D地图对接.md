# 08 · 与 3D 地图对接

> **本文是 2D 与 3D 的接口契约。** 3D / 建模同学只需要读这一份 + `docs/06`。
> 文中每条约定在 `web/verify.js` 第 10 节都有对应断言，改坏了会立刻报红。

## 1. 一分钟契约（TL;DR）

> **2D 和 3D 共用同一套坐标系、同一份数据、同一个寻路算法。
> 不需要投影、不需要控制点、不需要坐标标定。**

具体来说：

| 你需要的 | 从哪来 |
|----------|--------|
| 建筑轮廓 + 高度 | `data/campus/buildings.json` |
| 道路/步道中线 | `data/campus/roads.json`、`footways.json` |
| 路牌 / POI 锚点 | `data/campus/nodes.json` |
| 寻路（3D 里也能用） | `data/graph.json` + `web/geo.js` 的 `dijkstra()` |
| 平面坐标 → 引擎坐标 | `web/geo.js` 的 `toThreeJS()` / `toBabylonJS()` |

一次性转换公式（Three.js）：

```js
three.x = campus.x        // 东
three.y = elevation       // 高程（地面 = 0）
three.z = -campus.y       // 北 → -z
```

就这一行。**不要自己手写这个变换**，用 `G.toThreeJS(x, y, elev)`，
否则手性弄反会导致整个校园左右镜像（第 10 节第 1 条）。

### 怎么把 `geo.js` 引进 3D 工程

`geo.js` 是 UMD，三种引入方式都是**同一份实现**，不会出现"2D 和 3D 算法不一致"：

```js

// 方式二：普通 <script>，零配置
//   <script src="web/geo.js"></script>
//   const G = window.CampusGeo;

// 方式三：Node 脚本（做数据预处理时）
const G = require('./web/geo.js');
```

> 建议把 `web/geo.js` + `web/geo.esm.js` + `data/` 通过 **git submodule** 或
> 直接复制到 3D 工程里。复制的话，注意记录来源版本（见第 12 节）。

## 3. 坐标系定义

这是整个项目的地基，**改之前必须全员讨论**。

| 项 | 约定 |
|----|------|
| 名称 | 校园平面坐标系（局部 ENU：East-North-Up） |
| 单位 | **米**（1 单位 = 1 米），无缩放 |
| 原点 | `(0, 0, 0)` = 校园**西南角**地面 |
| x 轴 | 向**东** |
| y 轴 | 向**北** |
| z 轴 | 向**上**（高程；地面 = 0） |
| 手性 | **右手系** |
| 范围 | `x ∈ [0, 690.9]`，`y ∈ [0, 468.6]` |
| 中心 | `(345.4, 234.3)` |

注意：**数据文件里只存 `(x, y)` 两个分量**——校园是平地的，高程由建筑高度和楼层单独表达。
`z`（高程）是 3D 侧引入的第三个维度。

## 4. 引擎坐标转换

### Three.js（y 轴向上，右手系）

Three.js 默认 y 向上、右手系，所以不能直接用"z 向上"的校园坐标：

```js
// 校园 (x 东, y 北, 高程) -> Three.js
G.toThreeJS(260.3, 139.6, 0);
// => { x: 260.3, y: 0, z: -139.6 }
```

实现（`web/geo.js`）：

```js
function toThreeJS(x, y, elevation) {
  return { x: x, y: elevation || 0, z: -y };
}
```

**为什么北映射到 `-z`**：相机放在校园南侧上方朝北看时，屏幕正上方就对应北方——
和看平面图的直觉一致；而 Three.js 里 `-z` 正是"镜头朝向的深处"。

**为什么不会镜像**：这个变换的线性部分矩阵是

```
     | 1   0   0 |
M =  | 0   0   1 |      det(M) = +1   → 保向，右手系仍是右手系
     | 0  -1   0 |
```

`det = +1` 意味着它只旋转/翻转坐标轴，不产生镜像。`verify.js` 里有断言守着这条。

### Babylon.js（y 轴向上，左手系）

Babylon 默认是左手系，映射不同：

```js
G.toBabylonJS(0, 100, 0);   // => { x: 0, y: 0, z: 100 }   北 -> +z
```

### 反算：3D 拾取点 → 校园坐标

```js
const [x, y] = G.fromThreeJS({ x: 264.5, y: 999, z: -141.2 });   // => [264.5, 141.2]
```

高程被忽略——因为这是"把 3D 里点到的位置投回平面"，用于在 2D 上高亮同一位置。

## 5. 数据交接清单

### buildings.json —— 建筑轮廓（面）

```jsonc
{
  "type": "Feature",
  "properties": {
    "name": "图书馆",     // 显示名，可直接做 3D 标签
    "type": "教学",       // 教学 / 体育 / 生活 / ...（建议用于材质分组）
    "floors": 4,          // 层数（用于推高度，见第 6 节）
    "kind": "building"    // building = 可挤出体块；ground = 贴地面状设施
    // "height": 22       // 可选：显式高度（米），给了就覆盖 floors
  },
  "geometry": {
    "type": "Polygon",
    "coordinates": [ [ [220.3,259.2], [300.4,259.2], [300.4,339.0],
                       [220.3,339.0], [220.3,259.2] ] ]
  }
}
```

| 约定 | 说明 |
|------|------|
| 外环绕向 | **逆时针（CCW）**。挤出法线依赖它，写成顺时针会导致法线朝内、面发黑 |
| 内环（洞） | 若有，第 2 个及以后的环为洞，绕向应**顺时针** |
| 环闭合 | 首尾坐标必须相同 |
| 当前数据 | 9 个面要素；8 个 `kind=building`，1 个 `kind=ground`（操场） |

### roads.json / footways.json —— 道路中线（线）

```jsonc
{
  "type": "Feature",
  "properties": {
    "from": "south_gate", "to": "cross_main",
    "name": "校园主干道",
    "type": "road"                 // road=机动车道；footway=人行步道
  },
  "geometry": { "type": "LineString", "coordinates": [ [260.3,0.0], [260.3,139.6] ] }
}
```

这是**中线**，不是路面。3D 里需要自己按宽度扩成带（第 8 节给了代码）。
2D 侧用的宽度：机动车道 13 m，人行步道 6 m——建议 3D 保持一致。

### nodes.json —— 路网节点（点）

```jsonc
{
  "type": "Feature",
  "properties": { "id": "south_gate", "name": "南门" },
  "geometry": { "type": "Point", "coordinates": [260.3, 0.0] }
}
```

3D 里适合放路牌、POI 图标、传送锚点。当前 17 个。

### graph.json —— 寻路图

```jsonc
{
  "meta": { "format": "campus-graph/1", "unit": "meter", "crs": "local",
            "walk_speed_mps": 1.2 },
  "nodes": [ { "id": "south_gate", "name": "南门", "x": 260.3, "y": 0.0 } ],
  "edges": [ { "id": "e001", "from": "south_gate", "to": "cross_main",
               "weight": 139.6, "type": "road", "name": "校园主干道",
               "geometry": [[260.3,0.0],[260.3,139.6]] } ],
  "adjacency": { "south_gate": [ { "to": "cross_main", "weight": 139.6, "edge": "e001" } ] }
}
```

- `weight` = 平面欧氏长度（米），**不是**球面距离。
- `adjacency` 是**双向**的（无向图），直接喂给 `G.dijkstra()` 即可。
- 3D 里不要自己再建一次图，直接用这个 `adjacency`，保证与 2D 结果逐米一致。

## 6. 建筑高度约定

高度有三个来源，优先级从高到低：

```
1. properties.height       显式指定（米）——有真实数据时用它
2. properties.floors × 层高  默认层高 3.5 m
3. kind === "ground"       直接为 0，不挤出
```

**请始终用 `G.buildingHeight(props)` 计算，不要自己写这段逻辑**：

```js
G.buildingHeight({ floors: 4 })                    // => 14
G.buildingHeight({ floors: 4, height: 22 })        // => 22
G.buildingHeight({ kind: 'ground' })               // => 0
G.DEFAULT_FLOOR_HEIGHT                             // => 3.5
```

> ⚠️ **为什么这么强调 `kind`**：操场、广场这类"面状设施"也放在 `buildings.json` 里，
> 但它们没有楼层。演示数据里操场原本写着 `floors: 4`——如果 3D 直接按层数挤出，
> **操场会变成一栋 4 层楼**。所以必须由 `kind: "ground"` 显式区分。
> `verify.js` 有断言专门守这条。

> 📌 **当前数据的高度是占位值**：8 栋建筑全是 `floors: 4`（→ 14 m），
> 这是从旧演示数据继承来的。3D 建模同学拿到真实层数/高度后，
> 请直接改 `data/campus/buildings.json` 的 `floors` 或加 `height` 字段。

## 8. 代码示例：Three.js 完整接入

一个可运行的最小骨架（假设已有 `scene`）。

```js
import * as THREE from 'three';
import G from './lib/geo.js';          // 即 geo.esm.js

const load = (p) => fetch(p).then((r) => r.json());
const [graph, buildings, roads, footways, nodes] = await Promise.all([
  load('data/graph.json'),
  load('data/campus/buildings.json'),
  load('data/campus/roads.json'),
  load('data/campus/footways.json'),
  load('data/campus/nodes.json'),
]);

// ---- 把校园中心挪到世界原点（可选，但相机好摆很多） ----
const bb = G.bboxOf([buildings, roads, footways, nodes]);
const CX = (bb.minX + bb.maxX) / 2;      // 345.4
const CY = (bb.minY + bb.maxY) / 2;      // 234.3
const world = new THREE.Group();
world.position.set(-CX, 0, CY);
scene.add(world);

// ---- 1. 建筑体块 ----
const bMat = new THREE.MeshLambertMaterial({ color: 0xcbd5e1 });
for (const f of buildings.features) {
  const h = G.buildingHeight(f.properties);   // kind=ground 时为 0
  if (h <= 0) continue;                       // 操场/广场不挤出

  const ring = f.geometry.coordinates[0];
  const shape = new THREE.Shape();
  ring.forEach(([x, y], i) => (i ? shape.lineTo(x, y) : shape.moveTo(x, y)));

  const geo = new THREE.ExtrudeGeometry(shape, { depth: h, bevelEnabled: false });
  geo.rotateX(-Math.PI / 2);   // (x, y, z) -> (x, z, -y)，正是 toThreeJS 的映射

  const mesh = new THREE.Mesh(geo, bMat);
  mesh.name = f.properties.name;
  mesh.userData = { name: f.properties.name, height: h, kind: 'building' };
  world.add(mesh);
}

// ---- 2. 道路：中线 -> 带 ----
function ribbon(coords, width, elev = 0.05) {
  const pos = [];
  const P = (x, y) => { const w = G.toThreeJS(x, y, elev); return [w.x, w.y, w.z]; };
  for (let i = 0; i < coords.length - 1; i++) {
    const [x1, y1] = coords[i], [x2, y2] = coords[i + 1];
    const dx = x2 - x1, dy = y2 - y1;
    const L = Math.hypot(dx, dy) || 1;
    const nx = (-dy / L) * (width / 2), ny = (dx / L) * (width / 2);
    const a = P(x1 + nx, y1 + ny), b = P(x1 - nx, y1 - ny);
    const c = P(x2 - nx, y2 - ny), d = P(x2 + nx, y2 + ny);
    pos.push(...a, ...b, ...c, ...a, ...c, ...d);
  }
  const g = new THREE.BufferGeometry();
  g.setAttribute('position', new THREE.Float32BufferAttribute(pos, 3));
  g.computeVertexNormals();
  return g;
}

const roadMat = new THREE.MeshLambertMaterial({ color: 0x64748b, side: THREE.DoubleSide });
roads.features.forEach((f) => world.add(new THREE.Mesh(ribbon(f.geometry.coordinates, 13), roadMat)));

const walkMat = new THREE.MeshLambertMaterial({ color: 0x16a34a, side: THREE.DoubleSide });
footways.features.forEach((f) => world.add(new THREE.Mesh(ribbon(f.geometry.coordinates, 6), walkMat)));

// ---- 3. 节点 -> 路牌 / POI ----
const nodeMat = new THREE.MeshBasicMaterial({ color: 0x2563eb });
const nodeGeo = new THREE.SphereGeometry(1.6, 16, 12);
nodes.features.forEach((f) => {
  const [x, y] = f.geometry.coordinates;
  const w = G.toThreeJS(x, y, 2.5);
  const m = new THREE.Mesh(nodeGeo, nodeMat);
  m.position.set(w.x, w.y, w.z);
  m.userData = { id: f.properties.id, name: f.properties.name, kind: 'node' };
  world.add(m);
});

// ---- 4. 相机：以米为单位，站在南侧上方朝北看 ----
//   校园参照系里"南"是 y 小的一侧，映射后是 three.z 大的方向
camera.position.set(0, 260, 520);
camera.lookAt(0, 0, 0);
camera.near = 1; camera.far = 8000; camera.updateProjectionMatrix();
```

## 9. 在 3D 里跑寻路

**不要重写算法**，直接用同一份 `adjacency` 和同一个 `dijkstra`：

```js
const edgesById = Object.fromEntries(graph.edges.map((e) => [e.id, e]));

function findRoute(fromId, toId) {
  const r = G.dijkstra(graph, fromId, toId);     // 与 2D 逐米一致
  if (!r) return null;

  const pts = G.routeCoords(r, edgesById).map(([x, y]) => {
    const w = G.toThreeJS(x, y, 0.3);            // 路面略抬高，避免 z-fighting
    return new THREE.Vector3(w.x, w.y, w.z);
  });

  // 'centripetal' 避免折线过冲；若要绝对直角转弯，改成"每段一根管子"
  const curve = new THREE.CatmullRomCurve3(pts, false, 'centripetal');
  const tube = new THREE.Mesh(
    new THREE.TubeGeometry(curve, Math.max(8, pts.length * 6), 0.8, 8, false),
    new THREE.MeshBasicMaterial({ color: 0xf97316 })
  );
  world.add(tube);

  return { dist: r.dist, nodePath: r.nodePath, object: tube };
}

// 与 2D 对照：这里应得到 468 m
const r = findRoute('south_gate', 'E1');
console.log(r.dist, G.fmtDist(r.dist), G.fmtTime(r.dist, graph.meta.walk_speed_mps));
```

> `routeCoords()` 会按行进方向自动拼接各条边的几何（边是双向存储的），
> 所以直接拿到的就是一条从起点到终点的连续折线。

## 10. 常见坑

| # | 坑 | 症状 | 正确做法 |
|---|----|------|----------|
| 1 | **手性/映射弄反** | 整个校园左右镜像（图书馆和实验楼位置互换） | 用 `G.toThreeJS()` / `G.fromThreeJS()`，别手写 |
| 2 | **把 y 当高程** | 建筑全躺在地上或竖错方向 | Three.js 里高程是 **y**，北是 **-z** |
| 3 | **多边形绕向反了** | 建筑面发黑、法线朝内、光照不对 | 外环保持 **逆时针**，用 `G.signedArea(ring) > 0` 校验 |
| 4 | **忘记 `kind`** | **操场被挤出成一栋 4 层楼** | 用 `G.buildingHeight()`，它会把 `ground` 判成 0 |
| 5 | **单位不一致** | 相机穿模 / 建筑小得像米粒 | 全场景 1 单位 = 1 米；相机 near/far 按米设（如 1 / 8000） |
| 6 | **UMD 引入方式不对** | `import G from './geo.js'` 拿到 undefined | 用 `geo.esm.js`（第 2 节） |
| 7 | **手改 `graph.json`** | 下次重建图就被覆盖，2D 3D 数据不一致 | 改 `data/campus/`，跑 `scripts/build_graph.py` |
| 8 | **自己重写寻路** | 2D 给的 468 m 和 3D 算的对不上 | 共用 `graph.json` 的 `adjacency` + `G.dijkstra()` |
| 9 | **z-fighting 闪烁** | 路面和地面重叠处闪 | 路面抬高 0.05 m，路线抬高 0.3 m |
| 10 | **多边形没闭合** | 三角化失败或出现破面 | 首尾坐标相同；`verify.js` 会查 |

## 11. 反向：3D 侧的改动如何回写

**单一真源原则**：`data/campus/*.json` 是唯一真源。3D 里新增/修改的东西，
必须回写到这些文件，而不是只存在于 3D 工程里。

| 3D 里做了什么 | 回写到哪 | 要不要重建图 |
|---------------|----------|--------------|
| 新增/调整一栋楼的轮廓或高度 | `data/campus/buildings.json` | ❌ 不用（建筑不参与寻路） |
| 新增/移动一条路 | `roads.json` / `footways.json`（同时可能要加节点） | ✅ 必须 |
| 新增/移动一个路口或路牌 | `data/campus/nodes.json` | ✅ 必须 |
| 只改了材质、光照、贴图 | 不回写（属于 3D 表现层） | ❌ |

回写完执行：

```bash
python scripts/build_graph.py --out data/graph.json    # 或双击 重建路网.bat
node web/verify.js                                     # 57 项断言必须全绿
```

`verify.js` 第 3 节会检查 `graph.json` 是否与源数据同步——**改了数据忘重建图会被立刻发现**。

### 2D ↔ 3D 运行时联动

// 3D 里收到后，用同一个 id 查节点坐标即可
const n = graph.nodes.find((v) => v.id === msg.nodeId);
const w = G.toThreeJS(n.x, n.y, 0);
