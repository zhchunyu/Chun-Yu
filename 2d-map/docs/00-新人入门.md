# 00 · 新人入门（10 分钟看懂并跑起来）

> 欢迎加入。这份文档目标只有一个：**让你在 10 分钟内把项目跑起来，并知道该改哪个文件。**
> 不需要 GIS 背景，不需要 3D 背景，不需要装任何 npm/pip 包。

## 1. 这个项目是什么

一个**虚拟构建的校园**的 2D 导航地图：地图上能点两个点，算出最短步行路线。

它同时是整个"三维数字校园"项目的**数据与算法基座**——

- **数据基座**：校园的建筑轮廓、路网、节点都存在 `data/campus/*.json` 里，
  用的是**平面米坐标**。3D 场景可以直接拿同一份数据去拉体块、铺路面、放路牌。
- **算法基座**：最短路（Dijkstra）跑在 `web/geo.js` 里，2D 在用，3D 也能直接用同一份代码。

一句话：**2D 和 3D 共用一套坐标系、一套数据、一套寻路算法。**

## 2. 五分钟跑起来

```bash
# 1. 克隆（换成实际仓库地址）
git clone <仓库地址> && cd <仓库目录>

#    ⚠️ 本项目通常是共享仓库里的一个子目录（如 2d-map/），
#       如果克隆后发现当前目录没有 scripts/，就再进一层：
#       cd 2d-map

# 2. 起服务并打开浏览器
python scripts/start_server.py
#    浏览器会自动打开 http://127.0.0.1:8123/web/
```

Windows 用户更省事：**双击根目录的 `启动演示.bat`**。

依赖只有 Python 3.10+（只用标准库）。**不需要 `pip install`，不需要 `npm install`。**

打开页面后：点地图上两个蓝色节点圆点 → 自动算出橙色路线，左侧显示距离和步行时间。
滚轮缩放、按住拖拽平移。

## 3. 项目结构（只需要先看这几个）

```
├── data/
│   ├── campus/          ★ 校园源数据（唯一真源，手改这里）
│   │   ├── buildings.json     建筑轮廓（面）
│   │   ├── roads.json         机动车道（线）
│   │   ├── footways.json      人行步道（线）
│   │   └── nodes.json         路网节点（点）
│   └── graph.json       ← 由上面前四个文件**生成**的寻路图（不要手改）
├── web/                 ★ 前端（零依赖，纯文本）
│   ├── index.html             一张 <svg>
│   ├── style.css              全部样式（SVG 元素就是 DOM，样式就是 CSS）
│   ├── geo.js                 纯逻辑：坐标变换 + 多边形 + Dijkstra（Node 也能跑）
│   ├── app.js                 渲染与交互（操作 DOM，不可脚本断言）
│   └── verify.js              ★ 57 项自动化断言
├── scripts/
│   ├── start_server.py        起本地服务
│   └── build_graph.py         campus/*.json → graph.json
├── docs/                      文档（你正在看的）
└── legacy/                    已退役的旧实现（不用看，除非好奇）
```

## 4. 三个必须知道的约定

理解这三条，你就理解了整个项目 80% 的设计。

### 约定一：坐标是"平面米"，不是经纬度

校园是虚拟的，所以没有用经纬度，而是直接用一个平面直角坐标系：

| 项 | 约定 |
|----|------|
| 单位 | **米**（1 个坐标单位 = 1 米） |
| 原点 | `(0,0)` = 校园西南角 |
| 方向 | **x 向东**，**y 向北**（常规数学朝向，y 向上） |
| 校园范围 | 约 691 m（东西）× 469 m（南北） |

所以一个建筑写成 `[[220.3, 259.2], [300.4, 259.2], ...]`，
就是"从西南角往东 220.3 米、往北 259.2 米"那个点。**不需要任何投影换算。**

> 想看真实地图上的这个校园？不存在，它是虚拟的。
> 但代码里保留了接真实经纬度数据的备用能力（`web/geo.js` 的 `makeProjection`），
> 现在用不上。

### 约定二：`graph.json` 是派生产物

```
data/campus/*.json   ──build_graph.py──▶   data/graph.json
   （人改这里）                                 （前端读这个，别手改）
```

`graph.json` 里是"节点 + 边 + 邻接表"，是给寻路算法用的。
**永远不要手改它**——改 `data/campus/`，然后重新生成：

```bash
python scripts/build_graph.py --out data/graph.json    # 或双击 重建路网.bat
```

改了数据忘记重建图？`verify.js` 会直接报错告诉你（第 3 节断言专门查这个）。

### 约定三：正确性靠断言，不靠肉眼

这是这个项目最特别的地方，也是为"AI 辅助开发"专门设计的：

```bash
node web/verify.js
```

57 项断言覆盖数据格式、图结构、坐标变换、最短路正确性、前端契约、3D 对接契约。
**退出码 0 就是通过，非 0 就是有问题。**

为什么能做到？因为 `web/geo.js` 被刻意写成**浏览器和 Node 都能跑**的纯逻辑层，
没有 DOM、没有依赖，所以算法可以在命令行里直接断言——不用开浏览器、不用截图、
不用人眼判断路线对不对。

> **改完任何东西，跑一遍 `node web/verify.js`。** 这是硬性要求，不是建议。

## 5. 你的第一次改动：加一栋楼

打开 `data/campus/buildings.json`，在 `features` 数组末尾追加：

```json
{
  "type": "Feature",
  "properties": { "name": "新实验楼", "type": "教学", "floors": 3 },
  "geometry": {
    "type": "Polygon",
    "coordinates": [[[600, 50], [680, 50], [680, 110], [600, 110], [600, 50]]]
  }
}
```

刷新浏览器——楼就出现了。

三个要点：

1. **多边形必须闭合**：最后一个坐标要等于第一个（`[600,50]` 出现了两次）。
2. **绕向必须逆时针**（在 y 向上的坐标里）。写成顺时针，3D 挤出时法线会朝里、面会黑。
   `verify.js` 会帮你查。
3. **加建筑不需要重建图**（建筑不参与寻路），刷新即可。

跑一下 `node web/verify.js`，57 项应该还是全过。

想加路或加节点？那就要改 `nodes.json` + `roads.json`/`footways.json`，**并且必须重建图**。
详细步骤见 `docs/06-虚拟校园数据规范.md`。

## 6. 常见问题

**Q：为什么不用 Leaflet / 高德 / Cesium？**
A：这个项目有两条硬约束——① 主要靠 AI 工具开发，源文件必须纯文本、可 diff、可 grep；
② 校园是虚拟的，不需要真实地理。地图库和影像瓦片都是"AI 读不动的黑盒/二进制"，
所以最后选了原生 SVG 手写。详见 `docs/07-技术路线与架构.md`。

**Q：`legacy/` 里是什么？**
A：项目早期走的是"真实经纬度 + QGIS + 卫星影像瓦片 + Leaflet + 打包 exe"路线，
后来整个换掉了。旧代码保留备查，**不用看，也不保证能跑**。见 `legacy/README.md`。

**Q：为什么 `.bat` 文件里全是英文？**
A：cmd.exe 按字节偏移解析批处理文件，UTF-8 中文会让它把后面的命令行吃掉
（真踩过：`node web\verify.js` 被解析成了 `e.js`）。所以 `.bat` 内容强制纯 ASCII。

**Q：页面一片空白 / 提示无法加载数据？**
A：多半是直接用 `file://` 打开了 `index.html`。必须通过 HTTP 访问，
用 `python scripts/start_server.py` 起服务。

**Q：端口 8123 被占了？**
A：`start_server.py` 会自动在 8123–8139 里找空闲端口，并在启动时检测复用已在跑的实例，
你只要看它打印的 URL 就行。
