# 03 · 路网建模与路径算法

## 1. 数据模型

路网 = 图 G = (V, E)：

- **节点 V**：交叉口、建筑出入口、地标（`data/campus/nodes.json`）。
- **边 E**：相邻节点间的可通行路段（`roads.json` / `footways.json`），
  权重 = 平面欧氏长度（米），由 `scripts/build_graph.py` 自动计算。
- 当前数据：节点 17 个 / 边 19 条，总长 2.5 km，全连通。

> **坐标系**：虚拟校园用**平面米坐标**，见 `docs/06`。
> 因为坐标本身就是米，边长直接用 `hypot()` 算，不需要 Haversine 球面公式，
> 也不需要任何 GIS 工具链。

## 2. `build_graph.py` 的两种建图模式

**显式模式**（推荐，语义清晰）：线要素属性带 `from`/`to`（对应 `nodes.json` 的 `id`），
脚本直接连线。当前数据即此模式。

**自动吸附模式**（省事）：不填 from/to，脚本取每条线的两端点，
按容差吸附到已有节点（新端点则自动建节点 `n001…`）。

```bash
# 常规：从 data/campus 重建（等价于双击「重建路网.bat」）
python scripts/build_graph.py --out data/graph.json --check south_gate,E1

# 自动吸附，容差 3 米
python scripts/build_graph.py --snap-tol 3 \
    --out data/graph.json data/campus/roads.json data/campus/footways.json

# 指定其它数据目录
python scripts/build_graph.py --out data/graph.json \
    data/campus/roads.json data/campus/footways.json \
    --nodes data/campus/nodes.json --check south_gate,E1
```

脚本自带**连通性自检**（有孤立分量会告警）。`--check A,B` 会打印一条最短路供人工核对。

## 3. 输出 `graph.json` 结构（前端消费的唯一接口）

```jsonc
{
  "meta":    { "format": "campus-graph/1", "unit": "meter", "crs": "local",
               "walk_speed_mps": 1.2, "snap_tolerance_m": 3.0 },
  "nodes":   [ { "id": "lib_gate", "name": "图书馆南门", "x": 260.3, "y": 239.3 } ],
  "edges":   [ { "id": "e008", "from": "cross_main", "to": "lib_gate",
                 "name": "图书馆步道", "type": "footway",
                 "weight": 99.7,                        // 米
                 "geometry": [[260.3,139.6], [260.3,239.3]] }  // 原始折线 [x,y]
  ],
  "adjacency": { "cross_main": [ { "to": "lib_gate", "weight": 99.7, "edge": "e008" } ] }
}
```

> `geometry` 保留折线形状，前端沿它画线；算法只用 `adjacency` + `weight`。
> **节点用 `x`/`y`，不是 `lat`/`lng`**——这是虚拟校园与旧地理方案最直观的区别。

`web/verify.js` 的第 3 节会检查 `graph.json` 是否与 `data/campus/*.json` 同步，
所以"改了数据忘了重建图"会被立刻发现。

## 4. 路径算法

- **Dijkstra**（本项目采用）：以边长（米）为权重求最短步行路。
  - 前端实现：`web/geo.js` 的 `dijkstra()`，用**二叉堆**做优先队列
    （不是每轮 sort），节点数上千也不退化；实测约 0.001 ms/次查询。
  - 算法在纯逻辑层，可用 `node web/verify.js` 直接断言正确性，
    不需要打开浏览器。验证项包括：全节点对连通、距离对称、三角不等式、
    路径几何首尾对位、几何长度与权重一致。
- 边权重接近时可用 BFS 提速，但建议统一用 Dijkstra——后续权重加入
  "时段限制/台阶减速" 后 BFS 不再正确。

### 进阶扩展点（在现有字段上直接加）

| 需求 | 做法 |
|------|------|
| 时段禁行（如上下学机动车禁行） | 边属性加 `time_windows`；查询前按当前时间过滤 adjacency |
| 机动车/步行分流 | 边已有 `type`；查询时传 `allowedTypes=['footway']` 过滤 |
| 无障碍路线 | 边属性加 `stairs: true`，无障碍模式直接剔除 |
| 室内外一体化 | 建筑门口节点 = "门户节点"，室内走廊网络单独一张 graph.json，通过门户 id 拼接两层图 |
| 多目的地（找最近食堂） | 对若干终点各跑一次 Dijkstra，或一次多终点 Dijkstra 取最小 |
| 楼层切换 | 节点加 `floor` 字段，垂直连接用 `type: "elevator"/"stairs"` 的边 |

## 5. 前端可视化要点（`web/app.js` 已实现）

- 地图是一张 **SVG**，缩放/平移就是改 `viewBox`，不需要地图库；
- 路线画在独立的 `<g class="route">` 里，橙色粗线，并带
  `data-distance-m` / `data-nodes` 属性——**算得对不对读属性就知道，不用看像素**；
- 起终点用绿/红大圆点区分，节点 hover 显示名称；
- 地图要素全部带 `data-id` / `data-name` / `data-type`，可 CSS 选择、可 grep；
- 面板显示总距离、预计步行时间、途经节点序列。
