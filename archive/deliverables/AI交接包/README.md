## 两条 LoRA 分别干什么

| LoRA | 职责 | 输入 → 输出 | 实测 |
|---|---|---|---|
| **extract**（V10） | 帖子 → 结构化 JSON | 自然语言 → 9 字段 JSON | 地点合法率 **6/6 = 100%** |
| **persona**（V7） | 人设化回应 | 问题 → 一段自然语言 | 人设/语气已训 |

部署时**同时挂载**，按请求选：

```bash
vllm serve /root/autodl-tmp/models/models/qwen--Qwen2.5-14B-Instruct/snapshots/master \
  --enable-lora \
  --max-lora-rank 128 \
  --lora-modules extract=/root/autodl-tmp/output/qwen25-14b-auv-v10-extract \
                 persona=/root/autodl-tmp/output/qwen25-14b-auv-v7 \
  --api-key <你自己定的长串> --port 6006
```

★ `--max-lora-rank 128` **不能省**（默认只有 16，会直接报错）。
★ 基础模型已在服务器上，不用重新拉。

## ★★ 三条硬约定（不遵守会出问题）

1. **后端必须以权威表校验 `building_name`**，不能直接采信模型输出。
   模型会**语义联想**编名字（"晕倒"→`校医院`、"宿舍"→`第一学生公寓A区`），
   编出来的看起来完全合理。查不到就丢弃，退回发帖人 GPS。
   → 详见 `01-接口与约定/地点字段处理约定.md`

2. **急救类不进提取 LoRA，走快速通道**（直接转 120 / 校医院）。
   判据：**"这条信息不推给附近的人，会不会有人吃亏？"**
   ★ 实测支撑：`extract` **不会拒答**，喂互助帖也硬吐 JSON ⇒ **意图分类必须前置**。

3. **`severity` 别信模型**。实测正则 / 基础模型 / 训练后 LoRA **三路全 5/10**，
   是标注口径问题不是能力问题。建议给死规则或从产品里砍掉。

## 链路里还缺两个环节

```
用户输入 → ① 意图分类  ← ★ 没实现
             ├── 急救类 → 快速通道
             └── 一般事件 → ② 提取 LoRA → ③ 系统补全 ← ★ 没实现 → ④ 推送/落图
```

- **① 意图分类**：可以先上正则/小模型，不必用大模型
- **③ 系统补全**：文本没写地点时用发帖人定位补 —— 这是**后端逻辑**，不是模型的事

## 安全

- 本包**不含任何密钥**
- ★ **AutoDL 的「自定义服务」是公网公开、无额外鉴权的** ⇒ `API_KEY` 是唯一门锁，**必须设、必须长**
