## 附：关于上次那个 AutoDL HTML 404 —— 诊断结论

你们观察到「`/docs`、`/v1/models`、`/v1/chat/completions` 都返回 AutoDL HTML 404，而根路径是 JSON 404」，
这个区分很关键，方向判断是对的。补充两点，方便你们以后自己排查：

1. **`/docs` 是 FastAPI 自带页面，不需要鉴权。** 它返回 **HTML 404** ⇒ 请求根本没到达推理服务
   ⇒ **6006 端口上没有后端在监听**（AutoDL 网关自己兜了个 404 页）。
   - 若只是**密钥错** ⇒ 会返回 **401 JSON**，不是 404；
   - 若只是**路径拼错** ⇒ `/docs` 会返回 **200**（Swagger 页面）。
2. 该地址所在的 AutoDL 实例此前处于**未启动服务 / 无卡模式**状态。
   我正在按「启动服务 → 确认端口映射 = 6006 → 取新地址」的顺序处理，最新地址会随后补上。

## 附：一条会影响你们预期的限制（重要）

你们后端是按 `model` 名区分 `extract` / `persona` 的，这个设计没问题。
但**LLaMA-Factory 自带的 API 不支持按 `model` 名切换 LoRA**（已查其源码 `api/app.py`：
`create_chat_completion()` 只读 `request.messages`，不读 `request.model`；`/v1/models` 也只返回一个名字）。

后果：如果先用 LLaMA-Factory 自带 API 起服务，
**`model: "persona"` 会被静默当成 `extract` 处理 —— 不报错，但人设失效**。

所以我会改用 **vLLM**（`--lora-modules extract=… persona=…`，这是官方支持按 `model` 名选 LoRA 的方式），
保证 `extract` 和 `persona` 在同一个地址上都能真正生效。
**你们的代码不需要改**，只需要换 `AUV_BASE_URL`。

进度安排：
1. 先起服务、确认端口，把 **extract** 打通并给你们实测结果；
2. 并行准备 vLLM 环境（需要下载一份 4bit 基座，约 9.5 GB），完成后 **persona** 一起开；
3. 两个都通了再交给手机端做真实联调。
