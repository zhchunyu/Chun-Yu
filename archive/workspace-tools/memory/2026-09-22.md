## 2 ★★ Git Data API 不会继承本地提交信息

`push_via_api.py` 原先用**硬编码** `MSG_LIGHT` / `MSG_BLEND` 当提交信息。
而 Git Data API 建的是**新的 commit 对象**，不会继承本地那条 ⇒
"本地认真写了一条准确的提交信息，推上去变成另一条"，且**完全不报错**。

修法：
- 提交信息默认取本地 HEAD（`git log -1 --format=%B`），硬编码降为兜底
- 新增 `--message-file` 指定、`--amend` 用**祖父提交**当 parent 替换远端 head
  （只改提交信息，tree 不变；需 `force: True`）
- 已用 `--amend` 把 `c418be8`（错误信息）替换成 `f50a73d9`（正确信息），
  历史保持 5 条线性，没有留下"错误信息 + 修正信息"两条冗余提交

## 3 ★★ Release 资产续传必须判 `state`，不能只判 `size`

`push_blend_release.py` 原先的跳过条件是 `have.get(name) == size`。
**上传被打断会留下 `state == "starter"` 的残缺记录，而它的 `size` 仍等于目标大小**：
实测 `archfix_r4.blend` 本地 50609801 / 远端 size 50609801 / **state starter**
⇒ 被判为"已存在"**永久跳过**，仓库里留下一个下不下来的坏文件。

修法：`existing_assets()` 连 `state` 一起取；跳过条件收紧为
`size 相符 且 state == "uploaded"`；对"存在但不可用"的残留**先 DELETE 再重传**
（同名直接上传会被拒）。新增 `delete_asset()`。

## 6 顺手修的工具缺陷
`_measure_layout.cjs` 的溢出判据：元素自身不滚动、但**祖先**在滚动
（`.tw{overflow-x:auto}` 包宽表格）时会被误报成 `[!溢出]`。
改为向上遍历祖先判断，输出区分 `[自身可滚动]` / `[被父级裁切]` / `[!真溢出]`
并给出"真溢出"计数。修后：手机版 63 个超宽元素里**真溢出 0 个**。

### 7.2 `.gitattributes`（统一行尾）
本机 git 开了 `core.autocrlf`，每次 `git add` 刷几十条
`LF will be replaced by CRLF` 警告，且同一文件在不同机器 checkout 出的字节不同。
新增 `.gitattributes`：`* text=auto eol=lf` + 文本/二进制显式分类。

★ **先核对再动手**：`git ls-files --eol` 显示索引里 **CRLF 文件数 = 0**
（文本本就以 LF 存储）⇒ **不需要 `--renormalize`**，不会产生大规模重写提交。
加完警告数归零。
（注：旧分支 `feat/2d-map-initial` 的名字就是 "Create .gitattribute" ——
 这事本来就该做，只是当时建在了孤立分支上。）
