### Visualizer diagram 模块关键约束（已实测）

- 每个 SVG 必须内联 arrow marker（`context-stroke` 才能跟随线色）
- 禁止渐变/阴影/发光；字号 ≥ 11px；禁止旋转文字
- 外层容器必须透明；文字说明写在响应正文而非工具调用内

**太阳方位角约定**（`render_campus_site.py:254`，务必记住）：
```python
to_sun = Vector((cos(el)*cos(az), cos(el)*sin(az), sin(el)))
```
→ **az 0° = 东(+X)、90° = 北(+Y)、180° = 西(−X)、270° = 南(−Y)**
要让**南立面**受光，方位角取 **236°~288°**（西南 ~ 南偏东）。
（阶段 0 记录里"118° 是西北"是同一个约定的换算结果。）

## 云遮罩 bug（跨阶段共性，已修）
`render_campus_site.py` 的程序化积云用 `Generated.Z`（≈ 仰角正弦）做水平遮罩，
原值 `MapRange(0.03 → 0.24)` 对应仰角 **1.7° ~ 13.9°** 渐显。
本项目建筑立面机位普遍只有 **1° ~ 7°** 仰角 → 正好落在渐显区，云量被压到 0~0.5，
渲出来是一整片均匀灰蓝（这就是"5 张图 4 张灰"的真正原因，不是曝光）。
→ 改成可覆盖参数 `cloud_horizon`，默认 **`(0.010, 0.105)`**（仰角 0.6°~6° 满量）。

## 流水线 bug（重要，会影响所有后续阶段）
`run_campus.py` 的 `build_extra` 循环原先**没把 `run()` 的返回值回填给 `g`**：
```python
for extra in (...):
    run(os.path.join(HERE, extra), g)     # ← 错：返回值丢了
```
`run()` 是往**一份新字典**里 exec 的（`g = {'__name__', '__file__'}` + `g.update(extra)`），
不回填的话，阶段 2 就拿不到阶段 1 定义的 `emit_to` / `roof_ring` / `pyramid_roof` / `disc`，
直接 `NameError`。阶段 1 侥幸能跑，只因为它是第一个 extra（g 里有 stage0 的全部）。
→ 已修成 `g = run(os.path.join(HERE, extra), g)`。

# 阶段 3 技术收获（与方案修订无关，经验仍然有效）

## 本轮修掉的四个形制 bug

**① 机位被同区其它建筑挡住（最隐蔽，白跑两轮）**
首版大礼堂/美术馆机位从正南 160 m 处拍，**正中书院 A / 书院 B 的背面**（相距仅 46 m），
主体完全没入画。肉眼从渲染图归因失败（图里是"一片大白墙 + 一排方窗"，
误以为是占位体块或大礼堂自身）。
→ 靠一次**几何诊断**定位：写临时脚本打印所有 `BLD_*` 对象的世界包围盒，
一比对就看出"书院 A 的 Y 范围 162~240，正好卡在机位与目标之间"。
**教训：机位设计不能靠读代码猜，要么先算包围盒，要么做射线诊断。**

**② 大礼堂大屋顶坡度只有 14.6°**
内环 Z 定 38.00、外环 29.40，高差 8.6 m 而水平跨 33 m → 屋面渲成一块水平板。
内环抬到 40.60（高差 11.2）后坡度 20.4°，才立得住。
**规律：中式大屋顶的"陡"只由 `(内环Z − 外环Z) / (外环半宽 − 内环半宽)` 决定，
跟"建筑有多大"无关 —— 平面越大越要抬内环。**

**③ 美术馆屋面是倒坡（符号写反）**
```python
GZ + _h + 1.90 - 0.70    # 外环 Z = 22.20
GZ + _zr                 # 内环 Z = 21.20  ← 比外环低 1.0 m
```
**檐口比脊还高**，渲出来是三片"黑斜板"。
→ 已改为四坡攒尖（`pyramid_roof`，mid=0.62 让屋面下陡上缓）。
**教训：`roof_ring` 的 `z_in` 必须严格大于 `z_out`，写完之后扫一眼这两个参数。**

**④ 书院屋面被压成平顶（长条建筑的形制坑）**
首版把内环收成"小矩形"（48×8），**长边方向也去放坡**（48→56 只有 8 m 水平、2 m 垂直 = 14°），
整个屋顶塌成"平顶 + 一圈薄檐"，鸟瞰看四栋书院全是**没有屋顶的白盒子**。
→ 长条殿堂应做**悬山**：`roof_ring` 的 `hw_in = hw_out`（长边方向不产生坡度），
两端自然落成**垂直山面**；出檐加大到 5.5 m 让坡降到 40° 左右。
**规律：屋面内环 Z 必须高出墙顶 ≥1.2 m，否则墙顶会从屋面里钻出来（阶段 1 老坑）。**

## 新增可复用方法：几何诊断脚本
写一个临时 `_diag_boxes.py` 挂进 `build_extra` 尾部，打印所有 `BLD_*` 的
世界包围盒 + 面数，按 Y 排序。用于：
- 确认占位体块是否清干净
- 给机位设计提供**真实尺寸依据**（不用读代码猜）
- 查"这个建筑到底建出来没有、多大、多高"
用完即删。**比重渲一轮便宜得多。**

## 新增可复用规则：TREE_EXCLUDE 要按实建尺寸重排
阶段 0 的通用循环 `for _nm,_zone,_sx,_sy,_w,_d,_h,_rot in BLD:` 是按**占位体块**尺寸
（`_w*0.5+7`）算排除区的。实建台基比占位体块大得多
（大礼堂台基 134×100 对占位体块 58×44），
**不按实建台基重排一遍，行道树会直接长进台基和大台阶里。**
→ 每完成一个阶段，把该区实建建筑的包围盒追加进 `TREE_EXCLUDE`。

## 三条最重要的结论（后续 R1~R6 必须沿用）

1. **"陈旧"不是材料问题，是构图法则问题。**
   第 1~4 版把黛瓦换钛锌、朱漆换铜，读起来还是塔 —— 因为
   **层层出檐 + 逐层收分 + 塔刹** 这套法则没动。删掉这三条，塔形当场就破了。
   → 后续凡遇"坡屋顶 + 檐口"的做法，先问：**这是在换材料，还是在换法则？**

2. **"斗拱 → 编织格构"的落点是楼板边带，不是立面外挂。**
   斗拱本质是**层层出挑的受力构件**，属于楼板边缘。罩在立面外 → 铁丝笼；
   移进楼板边带（0.90 混凝土 + 1.25 钢桁架）→ 结构腰带。
   **同一种杆件，位置错了就全错。**

3. **"错位堆叠"必须靠"每层自成完整的盒"，不能靠"层层相接"。**
   楼板一错位，本层立面的顶边就落在上层楼板轮廓之外。
   不处理 → 竖翼像断头筷子。处理方式**不是取消错位**，
   而是给每层加一条**压顶钢轨**，把本层立面收成一个完整体量。

## 顺带解决的"观感"根因
仰视图一直读成"一摞灰纸片"，根因：**楼板底面是一整片浅灰平面，没有结构表达**。
加一组板底结构肋（墨灰钢，每层 6 根）即解决。
→ **大面积的单一平面，永远要给它一点结构**，否则再好的体量也会读成"纸"。

## 四条最重要的结论
1. **竖直镜面对天空是隐形的（几何光学，不是口味）。** 站在地面仰视 38~53 m 高的竖直镜面，
   反射光线朝上打到地平线天空 —— 镜面把天空还给天空，整片腹板在画面里消失。
   镜面只在两个位置成立：**① 人眼高度、正对观看者（映广场与人）；② 细杆件 / 掠射角、深色背景（勾亮边）。**
   → **"大面镜墙"这个想法本身就是错的。**
2. **地形是零厚度平面，任何下挖必须显式补三样**：① 挖洞（`SITE_半岛地形` 是 `cap(P0)` 的
   单个平铺 n 边形，无内部顶点 → 用**半平面切开 + 边缘开缺口**，不能用零宽锁孔缝）；
   ② 封头（南北端各一块 YZ 截面拉 0.50 m 的实体）；③ **查隐形盖板**
   （`SITE_水面` Z 0 整片 4000×8000、`SITE_分区_中轴人文区` 南边缘 Y 153.6 都横跨谷口）。
3. **"玻璃"要分清两种**：`make_mat` 做的是不透明深蓝灰面板（远景读作玻璃够用）；
   要真透（谷壁后面是地下实验层）必须用 Principled `Transmission Weight = 1.0`
   + `Roughness 0.03` + `IOR 1.45` → 单独 `M_GLASST`。
4. **"拱"的读法由下弦决定，不由上弦。** 首版上弦拱 53、下弦平 38 → 读成"桥面 + 桥拱 + 桥肚子"；
   下弦也做成拱（38.5 → 44.0）后，腹板成为**两端薄中间厚的月牙**（= 拱的弯矩图），洞口才成"山口"。

# R1 第 4 版：材质静默失效 + 光照重标（收尾，已定稿）

## 触发
出完 8 张定稿图逐张验收时发现两处问题：
1. `R1_山口_仰视` 机位废掉 —— 相机距山门仅 19.6 m 却配 24 mm，画面里只剩一条拱带 + 天空，
   两片崖体完全出画。
2. **崖体读成"白塑料"** —— 而 M_CONC 明明已经压到 0.400。

## 根因（连查 3 轮）
第一轮判断：以为是"光照按旧配色标定"→ 压反照率 0.400 → 0.272 + sun 4.2 → 2.9，**画面几乎没变**。
第二轮怀疑：`make_mat` 按名字缓存。

读 `build_campus_r0.py` 确认 —— **R0 已经建过 `M_清水混凝土` (0.585)**。
`make_mat` 开头是：

```python
m = bpy.data.materials.get(name)
if m: return m          # ← 传进去的 color / rough / metal / noise_scale 全部丢弃
```

各阶段脚本在**同一个 Blender 会话**里顺序 exec，所以 R1 再调一次
`make_mat('M_清水混凝土', (0.272, ...))` 只会把 R0 那份 (0.585) 拿回来。
**色值从 0.585 → 0.400 → 0.272 连压三轮，一次都没生效。**

## 修法
1. `build_campus_r0.py`：M_CONC 0.585 → **0.272**，col_b → (0.226, 0.219, 0.204)，
   并在注释里写明"这是清水混凝土的唯一色值来源"。
2. `build_campus_r1.py`：改成 `M_CONC = bpy.data.materials['M_清水混凝土']`（只取引用），
   并写明踩坑经过。
3. 渲染配置：`sun_strength` 4.2 → **2.9**（`r1_final.json` + `r0_final.json`）。
4. `R1_山口_仰视` 机位重设：`[0,-62,3.8] → [0,33.6,40]`，lens 24 → 26。
   （验算：崖体外缘 X ±65.5 → 需 131 m 水平视野；lens 26 半角 34.7°，93.6 m 处半宽 64.7 m ✓）
5. `R1_智谷_谷口` 曾试改 `[0,86,4.2]→[0,195,0.5]`，反而把前景铺装从 27% 涨到 36% →
   **回退原机位**。

## 结果
- R1 8 张 1600×900 重出；R0 6 张**也重出**（材质全局改动，必须保持一致）
- 崖体读作真实清水混凝土；`R1_中轴_全景` 里 山门 → 下沉智谷 → 图书馆 → 垂直书院 的
  新中轴序列一眼可读

## 新增可复用规则
- **材质色值只在第一次定义它的阶段写**，后续阶段一律 `bpy.data.materials['M_xxx']` 取引用。
  `set_in(principled(M), ...)` 是修改已有材质，**会**生效（可安全用于补 Specular IOR Level）
- **换配色必须同时重标 sun_strength**。判据：如果"反照率压掉一半画面几乎没变化"，
  那不是材质问题，是光照过曝
- **仰视机位要先验算水平视野**：`半宽 = 距离 × tan(hFOV/2)`，`hFOV = 2·atan(18/lens)`
- **改了全局材质，之前所有阶段的成图都要重出**，否则同一个项目会出现两种混凝土

## 四条结论
1. **纯几何对称的退台 = 金字塔。给它一个方向性（南低北高）就变成"台地"。**
   破塔要三样一起破：**檐口 0 + 塔刹 0 + 轴对称破**。轴对称一旦打破，塔的读法回不来。
2. **薄壳只要外挑，就一定会挡掉自己正下方的光庭带。**
   起拱方向是"向内向上"，外缘最低。壳外缘比光庭环顶低 4.43 m 时，
   水平看过去光庭环完全不存在。→ 壳不外挑，外缘落在光庭环顶，两者一起倾斜。
3. **画面里出现"来历不明的板"，用射线投射问场景，不要猜。**
   讲堂左侧水面上的灰板，我先猜"竖直镜面"、再猜"对岸远山"、再猜"对岸陆域切断"，全错。
   `diag_ray.py` 一条射线命中 **`BLD_讲堂_玻璃幕`**。
4. **变曲率薄壳的环数不够，会被读成"多边形攒尖"。**
   `zf = 起拱 × (1 − s^1.9)` 在 s→1 处斜率最大，均匀 5 环时外缘折出一圈可见棱带。
   → **9 环**在 1600 px 下才读得出"连续曲面"。

## 两个静默 bug
1. **`fin_facade` 的 ±X 面玻璃整体错位 ±hy**
   `side_frames()` 返回的 `(ax,ay)/(bx,by)` 是边的**两个端点**，不是中点。
   玻璃盒在 ±X 分支错把 `_gy`（起点 y）当中点：
   `box((_gx+_ex)*0.5, _gy, ...)` → 应为 `box(_mx, _my, ...)`，`_mx/_my` 各自取两端中点。
   后果：讲堂 hy=19 → 西侧玻璃幕从 Y 842 伸到 880（北立面才 861），**多出 19 m 悬在水面上空**；
   图书馆每层错位 28 m。**两个分支都要取中点。**
2. **树会穿过漂浮建筑的楼板**
   `diag_vol.py` 实测：树冠顶点最高 **Z 13.1**，讲堂楼板顶才 6.90 → 树直接长进玻璃幕里。
   修法：场地阶段 `TREE_EXCLUDE.append((0.0, 838.0, 40.0, 38.0))`
   （漂浮讲堂 + 连接桥 + 尽端广场）。树在场地阶段一次性合并成 `SITE_树干`/`SITE_树冠`，
   **晚阶段再按位置删就晚了。**

## 五条最重要的结论
1. **"盒子扣壳"一定读成机库 —— 缺的不是曲面，是檐。**

## 新增可复用规则
- **筒壳剖面 `z = z0 + H·(1 − t^1.8)`（t=|v|/b）= 脊平檐陡 = 中式"举折"**；
  半圆拱 `1 − sqrt(1−t²)` 是"檐平脊陡" = 罗马式。**这个指数决定屋顶的民族属性。**
- **壳体形式跟着平面长宽比走**：集中式 → 四坡壳（庑殿/攒尖）；线性 → 筒壳（悬山/硬山）

- **多段脚本共享 globals ⇒ 可以"跨阶段补对象"**：R3 能直接用 R2 的 `_lib_prof`/`_lib_z`
  给自己补瓦垄，**不必改 R2 脚本**。这是 `build_extra` 架构的红利。
- **材质列表必须按材质分开收**：把铜收边 / 正脊 append 进"木肋"列表 → 整条脊变成胶合木色

  1.2~1.4 m 在 100 m 以上的立面上会读成高频条纹
- **立面语言要按建筑性格分家**，否则四批建筑越长越像：
  图书馆=细密遮阳翼 / 大礼堂=粗疏柱廊 / 美术馆=实墙条窗+壁柱 / 书院=疏排格栅
