### 3.1 `extract` —— 事件结构化提取

**instruction（原文，一字不改）：**

```
你是校园事件分析助手。请从用户描述中提取事件的结构化信息，输出JSON格式，包含以下字段：type(事件类型，取值safety/congestion/service/notice)、building_id(建筑ID，与building_name同步，没有则为null)、building_name(建筑名称，描述中未提及地点时填null)、floor(楼层，没有则为null)、severity(严重程度，取值low/medium/high)、description(事件摘要)、estimated_wait_min(预计等待或持续时间，单位分钟，没有则为null)、time_window(时间段，取值morning/noon/afternoon/evening/night/unknown)、advice(行动建议)。注意：描述中没有明确提到的地点、楼层等信息一律填null，不要推测或编造。
```

**input** = 学生原话，例如 `教学管理楼2F门口有个大坑，晚上走路注意点`

**输出示例：**
```json
{
  "type": "safety",
  "building_id": "teaching-management-building",
  "building_name": "教学管理楼",
  "floor": "2F",
  "severity": "medium",
  "description": "教学管理楼2F楼路面有坑洞，存在跌倒风险",
  "estimated_wait_min": null,
  "time_window": "night",
  "advice": "途经时请特别注意脚下，夜间尤其小心"
}
```

**字段值域表：**

| 字段 | 类型 | 值域 / 说明 |
|---|---|---|
| `type` | string | `safety` / `congestion` / `service` / `notice` |
| `building_id` | string \| **null** | 与 `building_name` 同步；**★ 不可信，见 §5①** |
| `building_name` | string \| **null** | 文本没提地点 ⇒ **必须 null**，模型不该猜 |
| `floor` | string \| null | 如 `"2F"`、`"B1"` |
| `severity` | string | `low` / `medium` / `high` —— **★ 建议不用，见 §5③** |
| `description` | string | 事件摘要 |
| `estimated_wait_min` | number \| null | 分钟 |
| `time_window` | string | `morning` / `noon` / `afternoon` / `evening` / `night` / **`unknown`**（★ 合法第 6 值） |
| `advice` | string | 行动建议 |

### 3.2 `persona` —— 人设化回应

**instruction（原文）：**

```
你是AUV，校园实时态势助手。你为大学生提供校园信息的解读与建议。

【你的表达原则】
- 结论先行：第一句给出最重要的判断，不铺垫
- 先给事实再给判断：说清楚发生了什么，再讲意味着什么
- 给选项不给命令：提供 2-3 个可选的行动，让对方自己决定
- 说人话：不用术语，不贴标签，不说"你需要""你应该"
- 该短就短：能一句话说清的不说三句
- 情绪场景先接住再建议：先承认对方的感受是真实的，再谈怎么办

【禁止】
- 不称呼对方为"您"，用"你"
- 不说"没关系""会好起来的""下一个更好"这类空话
- 不引经据典，不提任何书名或理论名称
```

> ★ 数据集里还有一套 `你是校园空间诊断助手…` 的 instruction（用于空间问题分析）。
> 如果要做「这条路为什么没人走」这类诊断，向我要那一份。

**input** 示例：`{"type": "notice", "building_id": "BLD_Supermarket", "building_name": "校园超市", "event_name": "营业时间"}\n【要求】极简`

**输出示例：** `超市周末开到晚上十一点，比平时晚一小时。`

### 4.2 Python（requests）

```python
import os, json, requests

BASE = os.environ["AUV_BASE_URL"]      # 后端环境变量，别硬编码
KEY  = os.environ["AUV_API_KEY"]

EXTRACT_INSTRUCTION = """你是校园事件分析助手。请从用户描述中提取事件的结构化信息，输出JSON格式，包含以下字段：type(事件类型，取值safety/congestion/service/notice)、building_id(建筑ID，与building_name同步，没有则为null)、building_name(建筑名称，描述中未提及地点时填null)、floor(楼层，没有则为null)、severity(严重程度，取值low/medium/high)、description(事件摘要)、estimated_wait_min(预计等待或持续时间，单位分钟，没有则为null)、time_window(时间段，取值morning/noon/afternoon/evening/night/unknown)、advice(行动建议)。注意：描述中没有明确提到的地点、楼层等信息一律填null，不要推测或编造。"""

def extract(text: str) -> dict:
    r = requests.post(
        f"{BASE}/v1/chat/completions",
        headers={"Authorization": f"Bearer {KEY}"},
        json={
            "model": "extract",
            "temperature": 0,
            "messages": [
                {"role": "system", "content": "You are a helpful assistant."},
                {"role": "user", "content": EXTRACT_INSTRUCTION + "\n" + text},
            ],
        },
        timeout=60,
    )
    r.raise_for_status()
    raw = r.json()["choices"][0]["message"]["content"]
    return json.loads(raw)          # ★ 见 §5④：可能不是合法 JSON，要兜底

print(extract("三食堂二楼窗口排队太久了，等了快二十分钟"))
```

## 5 ★★ 四条必须遵守的约定

### ① 地点不能直接信模型 —— **必须查权威表**

```
模型输出 building_name（只当"候选"）
   ↓
查 campus_locations.json 的 name / aliases
   ↓
查得到 → 用表里的真实 id + 坐标落图
查不到 → 丢弃，退回发帖人 GPS / 地图选点
```

**原因**：模型会**语义联想** —— 输入"有人晕倒了"，它会输出 `校医院`；输入"宿舍"，它输出某个具体宿舍名。
这些名字**看起来完全合理**，但文本里根本没提。V9 时代实测出现过完全不存在的楼名。
权威表：`campus_locations.json`（66 地点 / ~167 别名）。

### ② 急救类不要走模型 —— **走快速通道**

判据：**"这条信息不推给附近的人，会不会有人吃亏？"**

| 类型 | 处理 |
|---|---|
| 急救（晕倒 / 受伤 / 火情） | 直接转 120 / 校医院，**不走 extract**（保命优先，JSON 链路慢 3 秒） |
| 互助（拼车 / 求借 / 组队 / 失物） | **不进 extract**，走论坛 |
| 一般事件 | 走 extract |

★ **实测支撑**：`extract` **不会拒答** —— 喂它互助帖、纯情绪文本，它照样硬吐一个 JSON。
所以**意图分类必须前置**，这是链路第一环，不是可选项。

### ③ `severity` 建议不用模型

实测三路（纯正则 / 未训练基座 / 训练后 LoRA）**全部 5/10** —— 三个完全不同的方法同一个分数，
说明这是**标注口径问题，不是模型能力问题**。建议给死规则（比如按 `type` + 关键词映射），或从产品里砍掉。

### ④ 输出要做容错

`extract` 偶尔会返回带 ```json 代码块或前后有说明文字的内容。**`json.loads` 前先剥壳**：

```python
def parse_json_safe(raw: str) -> dict | None:
    s = raw.strip()
    if s.startswith("```"):
        s = s.split("```")[1]
        s = s[4:] if s.lower().startswith("json") else s
    try:
        return json.loads(s)
    except json.JSONDecodeError:
        return None          # ★ 兜底：宁可退回人工，不要抛异常
```

## 6 常见报错

| 现象 | 原因 |
|---|---|
| `{"detail":"Not Found"}` | ★ **正常** —— 你打开的是根路径 `/`，服务没有首页。改开 `/docs` |
| `401 Unauthorized` | Key 不对 / 没带 `Authorization` 头 |
| `404 model not found` | `model` 字段拼错（只能是 `extract` / `persona` / `qwen25-14b-base`） |
| 连接超时 | 服务没起、或实例重启后**地址变了** —— 找我重新要地址 |
| 第一次请求特别慢（10~30 s） | 冷启动，正常；第二次就快了 |
| 返回的不是合法 JSON | 见 §5④，加剥壳 + 兜底 |
