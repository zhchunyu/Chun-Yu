## 获取与修改

已有仓库先保存自己的改动，再在仓库根目录执行 `git pull --ff-only`。随后进入应用目录，按 [README](../README.md) 配置环境并运行。

建议每个功能使用独立分支：在仓库根目录执行 `git switch -c feat/功能名`，修改后只提交相关文件，推送该分支并创建 Pull Request。不要覆盖其他模块、强制推送 main 或提交 `.env.local`。出现分支分叉时先与队友核对，不用 `reset --hard` 丢弃改动。

## 私密配置交接

每台开发机从 `.env.example` 复制 `.env.local`，向负责人单独索取配置。仓库内示例均留空。

- `VITE_TENCENT_MAP_KEY`：前端腾讯地图 Key，需配置相应使用权限。
- `VITE_SUPABASE_URL`：同一 Supabase 项目的根地址，无 `/rest/v1/`。
- `VITE_SUPABASE_PUBLISHABLE_KEY`：前端 Publishable key；数据库安全依靠用户 JWT 和 RLS。
- `AUV_BASE_URL`、`AUV_API_KEY`：仅供 Node 服务读取，或设置在 Supabase Functions Secrets 中。
- `VITE_AUV_GATEWAY_URL`：可选的公开 HTTPS 网关地址；留空时手机生产版使用 Supabase `auv-assistant`。

Supabase service_role、Secret key、数据库密码、SMTP 密码及模型私钥不进入前端、APK、截图、共享文档或 Git。Publishable key 不能用于部署函数或创建服务器 Secrets，部署同学需要自己的项目权限。

## 服务器配置与联调

1. 按 `docs/supabase/真实账号与聊天联调.md` 检查邮箱认证、SMTP、数字验证码模板、`profiles`、`hall_messages`、`campus_regions`、角色 RPC、RLS 及实时 publication。
2. 按 `docs/supabase/餐厅窗口管理-给队友.md` 检查窗口表和管理员授权。不要让普通账号自行修改角色。
3. 部署 `supabase/functions/auv-assistant`，后端设置 AUV 地址和密钥。自行部署 Node 网关时配置 HTTPS 和实际可访问地址，不把手机指向开发电脑的 localhost。
4. 用两个真实账号在不同设备上确认注册、登录、消息互相收到、历史恢复、本人撤回及断网重连。模型服务单独确认实际回复。
5. 按 `docs/校园信息推送交接-2026-10-08/README-先看这里.md` 部署校园报告、异步 AI、审核通知、个推配置及云端评价；已有库先执行只读预检。历史本机信息不自动上传。
6. 地名展示映射由 `supabase/functions/_shared/campus-presentation.js` 共用，需重新部署 `auv-assistant` 和 `campus-information-worker` 使 AI、系统通知名称一致。地图默认 17 级、范围 14–20 级；标签逐建筑校准仍未完成。

以上是上线核对步骤，不表示本次上传重新验证了云端配置或双设备行为。

## 构建与资料

运行 `npm run build` 检查网页生产构建；需要安装包时运行 `npm run android:apk`。当前共享 APK 为 1.11、versionCode 12，位于 `docs/apk/OurCampus-1.11-队友图标与开屏.apk`。debug APK 的签名由构建电脑决定，其他电脑重新生成的 debug 签名可能不能覆盖已有安装；保留数据的升级应使用一致签名，不要上传签名私钥。

`docs/superpowers/` 和阶段交接文档记录历史方案，可能含旧名称、旧版本和未完成项；判断当前能力以源码和 README 为准。`output/pdf/` 是此前生成的技术方案书，正式参赛提交前应核对版本及学校名称脱敏要求。

共享时保留源码、SQL、素材、安卓工程和可编辑资料；忽略依赖、缓存、真实环境配置、旧 APK、个人截图和重复压缩包。忽略规则不会删除这些本机文件。
