# 手机与 AUV 转发函数的接口

路径：`POST /functions/v1/auv-assistant`。本机开发时对应 `/api/auv-assistant`。

请求头的 `Authorization` 使用当前登录用户的 `Bearer <access_token>`；`apikey` 使用现有 Supabase 项目 Publishable key。AUV 模型密钥只在后端读取，不由手机提供。

请求体：

```json
{
  "mode": "extract",
  "text": "谷园餐厅现在排队很久",
  "locationId": null,
  "history": []
}
```

`mode` 为 `chat`（校园建议）或 `extract`（事件分析）；`text` 为 1–1000 字；`locationId` 可为空或合法校园地点 ID，用户手动选点优先；`history` 为最近的 AI 对话，最多 6 条。初次请求用空数组。

成功回复类型：

- `kind=answer`：persona 模型的自然语言建议。
- `kind=event`：extract 模型的事件分析草稿，含已校验的地点字段。
- `kind=emergency`：应急规则提示，`generated_by=safety_rule`，没有调用模型。
- `kind=redirect`：互助或不适合事件提取的内容，`generated_by=intent_rule`。

只有真实模型调用成功时，`generated_by` 才为 `auv`。`locations` 只提供校内合法地点，用于“查看地点”和“去这里”。事件分析不自动发布到大厅。

错误格式：

```json
{
  "error": {
    "code": "model_unavailable",
    "message": "AI 服务地址或模型当前不可用，请联系管理员更新服务地址。"
  }
}
```

以上请求与错误文本是协议说明样例，不是线上模型成功记录。
