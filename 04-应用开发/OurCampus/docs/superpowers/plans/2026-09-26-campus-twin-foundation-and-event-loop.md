# CampusTwin 新版实施计划：软件基础层、地图主界面与动态事件闭环

> 本计划是当前项目的唯一实施入口，替代 `2026-09-21-model-anchored-labels-and-routes.md` 的总体计划。旧计划中的模型锚点、路线图和第一人称细节仍可作为历史实现参考，但执行顺序以本文为准。

## 实施原则

- 先改数据契约和状态边界，再改 UI，再补 AI；不在组件里临时塞字段。
- 先保证本地演示完全可运行，再接真实接口。
- 地图是主界面，侧栏功能必须可收起。
- 管理员发布先用结构化表单，未来自然语言上报只接入事件输入适配器。
- 每完成一个阶段都运行测试和构建，避免文件变大后无法定位回归。

## 目标文件分层

```text
src/app/              应用状态和设置
src/domain/           数据契约、校验、路线和事件规则
src/data/             本地数据、仓库、模型绑定和路线图
src/services/         local/http/AI 适配器
src/features/map/     3D 主视图和图层
src/features/events/  动态事件和管理员发布
src/features/settings/设置与演示恢复
```

如果现有文件已经承担多个职责，采用小步拆分；不要一次重写整个 `App.jsx` 或 `Campus3DViewer.jsx`。

## 阶段 0：建立新方案入口和数据契约

### 任务 0.1：保留并替代旧计划

- 将新版总体方案作为 `docs/superpowers/specs/2026-09-26-campus-twin-product-and-technical-roadmap-design.md`。
- 将本文作为新版实施计划。
- 旧文档保留历史内容并明确标记 superseded，不删除现有实现参考。

### 任务 0.2：收敛领域对象

优先检查并统一：

- `Location`：`id/name/category/modelAnchorId/entryNodeId/status/aliases/services/updatedAt`。
- `RouteEdge`：`from/to/distance/accessible/covered/safeAtNight/blocked/blockedByEventIds`。
- `CampusEvent`：`id/type/title/rawText/locationId/anchorId/affectedEdgeIds/severity/startAt/endAt/sourceType/trust/moderationStatus`。
- `Settings`：主题、地图质量、图层、默认路线模式、数据源和演示状态。

验收：所有地点、事件、路线都能用 id 互相引用；没有组件私有的同义字段。

### 任务 0.3：增加基础校验

增加纯函数或测试，覆盖：

- 地点 id 不重复。
- 地点锚点和路线入口存在。
- 事件引用的地点、锚点和路线边存在。
- 事件时间有效，关闭/过期状态不能继续影响路线。
- 路线不可达时结果明确为 `unavailable`，不保留旧折线。

## 阶段 1：P0 软件基础底座

### 任务 1.1：统一应用状态分组

不要继续把所有状态都堆在一个 reducer 里。先按四个语义组整理，组件通过 selectors 读取：

```text
settings  地图显示、导航偏好、性能和演示设置
session   当前角色、模拟位置、选中地点、最近路线、收藏
map       相机、侧栏、图层、第一人称和全屏状态
data      地点、事件、路线、加载/同步/错误状态
```

在现有 reducer 基础上补充：

- `settings`：从 `settingsRepository` 初始化。
- `dataSourceStatus`：local/loading/synced/error。
- `toast` 或轻量反馈状态。
- `lastUpdatedAt`。
- `viewState`：侧栏、图层、相机、移动端抽屉。

不要让 `App.jsx` 继续增长为所有业务的容器；只保留组合和 dispatch。

### 任务 1.2：设置面板

新增 `src/features/settings/SettingsPanel.jsx`，按以下分组实现真实控件：

- 地图显示：日间/夜间、建筑标签、热点、路线、当前位置、状态颜色。
- 地图操作：重置视角、全屏、鼠标灵敏度、默认视图、自动旋转、操作提示。
- 导航偏好：默认路线、优先遮雨、默认避开施工。
- 数据与演示：保存演示状态、恢复默认、清空路线、清空模拟位置、更新时间、模型版本。
- 关于系统：软件版本、地图版本、数据来源、快捷键说明。

设置修改要能立即反映地图或路线；取消/关闭面板不应丢失已保存设置。

### 任务 1.3：设置仓库与浏览器存储

新增 `src/data/settingsRepository.js`，提供：

```js
load()
save(patch)
reset()
```

先使用 `localStorage`，对损坏值回退默认设置。除了设置，还要持久化：

- 当前角色。
- 模拟当前位置。
- 管理员事件和地点修改。
- 最近路线和收藏地点。

所有存储 key 集中定义在 `src/data/storage.js`，不允许组件直接拼接 key。未来真实 API 或账号配置只替换 repository。

### 任务 1.4：基础地图控制

新增 `src/features/map/MapControls.jsx`，提供：

- 放大、缩小、重置视角。
- 聚焦当前地点、聚焦当前位置、聚焦路线。
- 全屏。
- 图例。
- 比例/距离信息。

这些控制与 Three.js viewer 通过命令式 ref 或明确回调通信，不把摄像机对象写进业务数据。

### 任务 1.5：状态组件

统一添加并复用：

- `LoadingState`：模型、数据和路线计算中。
- `ErrorState`：模型/数据/路线失败，并提供重试。
- `EmptyState`：无地点、无热点、无可用路线。
- `Toast`：发布成功、保存设置、恢复数据等短反馈。

验收：刷新页面后设置、角色、模拟位置和管理员修改仍保留；点击恢复演示数据后状态回到初始值；模型加载失败不会让搜索和错误提示消失。

### 任务 1.6：搜索基础

扩展搜索索引，使以下内容都可被检索：

- 建筑名称和别名。
- 拼音或关键词。
- 服务：打印、快递、充电、医务室等。
- 活动和通知。
- 快捷操作。

增加无结果状态、清空搜索和后续可接入最近搜索/收藏的接口。搜索不直接遍历组件数组，由 `searchCampusResources()` 统一提供结果。

### 任务 1.7：撤销与操作记录

管理员修改和发布事件保存：

```js
{ actionId, actionType, operator, createdAt, before, after }
```

首版实现最近一次或最近若干次撤销即可；必须支持保存、取消、撤销和恢复默认。

### 任务 1.8：移动端基础布局

- 侧栏变为抽屉。
- 地点详情和路线面板变为底部弹窗。
- 地图支持触摸旋转和缩放。
- 重要按钮保持可触摸尺寸。
- 不把关键操作设计成只依赖 hover。

第一人称虚拟摇杆放到后续阶段，但 `cameraMode` 和输入适配器保持可扩展。

## 阶段 2：P0 导航基础体验

### 任务 2.1：侧栏功能变成真实控制项

检查 `MapToolbar` 当前的占位项：

- 地点分类实际控制筛选状态。
- 图层实际控制地点标签、热点、路线、我的位置。
- 设置打开设置抽屉。
- 我的位​​置继续使用模拟地点，但保留 `locationProvider` 接口。
- 第一人称只切换相机，不重新加载模型。

每个打开的面板都要能再次点击关闭，移动端用抽屉样式。

### 任务 2.2：路线操作补齐

在 `RouteDock` 和路线领域层补齐：

- 起点/终点互换。
- 清空路线。
- 总距离、预计时间。
- 分段指引。
- 已避开施工和无障碍说明。
- 路线不可达原因。
- 聚焦路线。
- 重新规划。

路线面板必须显示解释性 `notices`，例如“已避开图书馆东侧施工”，而不是只展示折线。

### 任务 2.3：统一地图覆盖层

所有覆盖层都以领域 id 为来源：

- 地点标签：`location.modelAnchorId`。
- 热点：`event.locationId` → 地点锚点。
- 路线：`routePlan.points`。
- 我的​​位置：`currentLocationId` → 地点锚点。

禁止新增基于随机百分比、数组索引或固定 CSS 斜线的地图业务定位。

### 任务 2.4：基础视图设置

给 Three.js viewer 增加低风险设置：

- 默认/低性能像素比。
- 标签密度。
- 阴影开关或质量档位。
- 夜间场景颜色和灯光档位。
- 重置视角。

先使用 WebGL；只有性能测试明确证明需要时再评估 WebGPU。

## 阶段 3：地点与动态事件闭环

### 任务 3.1：地点详情成为单一状态消费方

`LocationDetail` 统一读取地点、有效事件和当前设置；不从地图组件复制状态。增加：

- 开放/关闭状态。
- 当前人流。
- 热点/活动列表。
- 服务标签。
- 到这里去、从这里出发。
- 数据来源和更新时间。

### 任务 3.2：路线结果增加解释字段

在现有 A* 结果基础上补充：

```js
{
  status: 'preview' | 'unavailable',
  originId,
  destinationId,
  mode,
  distance,
  durationMinutes,
  nodeIds,
  points,
  avoidedEventIds: [],
  notices: []
}
```

路线面板显示 `notices`，例如“避开图书馆东侧施工”。

### 任务 3.3：路线回归测试

至少覆盖：

- 最短路线使用真实模型坐标。
- 避雨路线优先遮雨边。
- 无障碍路线排除不可访问边。
- 避开施工路线排除动态封闭边。
- 夜间模式考虑安全属性。
- 无路可走时清空地图旧路线并显示原因。

## 阶段 4：管理员动态闭环

### 任务 4.1：事件仓库升级

保留当前 `eventRepository` 的本地实现，补充：

```js
create(event)
update(id, patch)
close(id)
expire(now)
loadAll()
reset()
```

写入 `localStorage` 时保留事件来源和原始文本，确保刷新后管理员发布结果仍存在。

### 任务 4.2：管理员发布表单

管理员表单必须支持：

- 事件类型：活动、拥挤、施工、关闭、服务异常。
- 标题和原始描述。
- 地点/楼层。
- 开始和结束时间。
- 严重程度。
- 影响道路或路线边。
- 预览地图影响。
- 发布、保存草稿、关闭事件。

发布前校验地点和时间；发布后生成 `verified` 的管理员事件，不能生成只有颜色的假热点。

### 任务 4.3：动态事件对地图和路线生效

- 地点关闭：详情卡状态变化，地点标签变灰。
- 拥挤：热点显示橙色，人流状态变更。
- 活动：地点显示活动标识，详情出现时间信息。
- 施工：受影响边标记 `blocked`，路线重新计算并给出绕行原因。
- 事件关闭或过期：地图与路线恢复。

验收：管理员发布“图书馆东侧施工”，切换回访客后，避开施工路线与最短路线产生可见差异。

## 阶段 5：为未来真实接口和 AI 留口

### 任务 5.1：HTTP 数据源适配器

新增 `src/services/httpCampusDataSource.js`，暂不要求真实服务在线，但接口与本地数据源一致：

- `GET /api/snapshot`
- `GET /api/locations`
- `GET /api/events`
- `POST /api/events`
- `PATCH /api/events/:id`
- `POST /api/routes/preview`
- `GET/PATCH /api/settings`

使用环境变量配置 base URL；接口失败时回退本地演示数据，并明确显示“本地演示数据”。

### 任务 5.2：事件输入适配器

定义但先用规则实现：

```js
normalizeEventInput(input)
extractEventFromText(rawText, context)
matchLocation(reference, locations)
deduplicateEvents(events)
verifyEvent(event, evidence)
```

自然语言抽取暂时可以返回“待核实的结构化结果”，不能绕过 Schema 校验直接进入地图。

### 任务 5.3：证据和可解释性

为每个事件保留：来源类型、原文、处理时间、可信度结论和原因。地图只显示已确认或明确标注待核实的事件。涉及安全、封路和重大服务异常的低置信度事件不能自动改变路线。

## 阶段 6：性能、测试和比赛包装

### 任务 6.1：测试门槛

每阶段完成后运行：

```powershell
npm test -- --run
npm run build
```

关键业务必须有纯函数测试：地点匹配、事件状态转换、去重、路线模式和设置持久化。

### 任务 6.2：模型性能检查

先测量再优化，记录：模型加载时间、首帧时间、FPS、draw calls、三角形数和移动端表现。优先使用 GLB 压缩、实例化和像素比控制，不在没有数据时引入复杂渲染框架。

### 任务 6.3：比赛文档

最终准备：

- 系统架构图。
- 地图坐标/锚点/路线/事件数据流图。
- 角色权限矩阵。
- 事件可信度和审核流程图。
- 一键演示数据说明。
- 性能和测试结果。
- 后续真实接口、知识图谱和人流预测路线。

## 第一批实际开发顺序

在用户确认新版方案后，按以下顺序写代码：

1. 整理 `Location / RouteEdge / CampusEvent / Settings` 数据契约和测试。
2. 拆出 `settings/session/map/data` 状态语义和 selectors。
3. 新增 `storage.js`、设置仓库和设置面板，完成 localStorage 持久化。
4. 增加地图放大、缩小、重置、聚焦、全屏、图例和距离控制。
5. 补齐 Loading/Empty/Error/Toast，覆盖模型、数据、搜索和路线。
6. 完善地点/别名/服务/活动搜索、无结果提示和清空操作。
7. 补齐起终点互换、清空、分段指引、聚焦路线、重新规划和不可达提示。
8. 完善管理员事件表单、本地持久化、取消、撤销和恢复默认。
9. 让事件关闭/施工影响地图状态和 A* 路线。
10. 增加移动端抽屉、底部弹窗和触摸地图基础交互。
11. 增加 HTTP/AI 适配器接口，但默认仍使用本地数据。
12. 最后做性能调优和一键演示包装。

## 完成定义

只有同时满足以下条件，才认为新版基础版完成：

- 地图是主界面，侧栏可以收起。
- 搜索地点、查看详情、规划路线全链路可用。
- 管理员能发布、关闭和恢复事件。
- 事件能影响地点状态、地图热点或路线。
- 设置能保存并恢复，演示数据可以一键重置。
- 本地数据源和未来 API 的调用边界已经固定。
- 测试和构建通过，浏览器完成访客→管理员→访客主流程。
