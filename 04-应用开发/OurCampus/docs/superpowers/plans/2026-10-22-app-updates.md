# App 新版提示与下载 Implementation Plan

> **For agentic workers:** 按已批准设计分工实施、针对回归并最终独立验证。

**Goal:** 将 Android 启动检查、设置检查与 APK 下载接入现有应用，并与头像、主页修复一起交付。

**Architecture:** 客户端读取受 RLS 保护的公开发布元数据；原生插件提供真实版本并仅在点击下载后打开受限 HTTPS 地址。版本发布与普通账号写权限分离。

**Tech Stack:** React 19、Supabase Postgres/Storage、Capacitor 8、Android Java、Vitest。

- [x] 元数据：创建 app_releases 和独立 APK 下载桶；anon/authenticated 只读已发布且已到发布时间的元数据，不能写或上传。
- [x] 回归：SQL事务内验证草稿/未来不可见及客户端无写权限，回滚测试行；撤回版本由相同status策略排除。
- [x] 客户端：appUpdates.js 校验原生版本、元数据、受控HTTPS地址与24小时稍后；自动失败静默，手动检查有结果。
- [x] 界面：useAppUpdates、非阻塞AppUpdateNotice、AppUpdateSettings；App与MePanel接线，已有弹层覆盖时不展示更新提醒。
- [x] 原生：CampusUpdates.getInfo/openDownload，不申请安装/存储权限；原生同样限制项目下载URL。
- [x] 一致性：补餐厅云端评价作者头像和主页入口，本机/示例评价不伪造用户；成员页返回层覆盖餐厅父页。
- [x] 版本与签名门禁：保留包名，递增到1.17/18；已发现本机默认签名与仓库旧APK不同，用户确认由队友/另一台电脑打包，已停止发布替代签名的覆盖包。
- [x] 本机交付：177项定向回归、前端生产构建、44项原生URL断言、签名配置门禁及独立复审通过；完整测试基线失败已单独记录，交接文档已完成。
- [ ] 原签名APK：由队友在原打包环境构建，核对实际手机证书、包名、版本和覆盖安装；本机未生成APK。
- [ ] 真实发布：核验最终APK资源、签名、SHA-256/大小、公开下载后再发布元数据；当前已发布记录为0。
- [ ] 设备验收：原手机首次手动覆盖安装，双端核对头像/主页，再验证后续已发布新版提示。

用户于2026-10-21确认设计，2026-10-22继续实施。原1.16 APK证书与当前默认debug.keystore不一致，必须查明原签名来源后才能发布可覆盖升级的安装包。
