# Supabase 真实账号与大厅接入

**目标：** 用户通过真实邮箱注册、确认、登录，登录后查询和发送持久化大厅消息，并通过 Supabase Realtime 同步多个设备。

**方案：** 保留现有手机界面，增加一个 Supabase 客户端、一个账号 hook 和一个大厅 hook。数据库沿用交接包的 `profiles`、`hall_messages`、`campus_regions` 和 `campus_my_role`，只用 Publishable key 与用户会话访问 RLS；不修改远端权限。邮箱方案已由用户确认，手机号与校园统一认证本次不接。

**技术：** React 19、官方 `@supabase/supabase-js`、现有 Capacitor Android 工程。

## 约束与核对

服务器只读检查：2026-10-04，邮箱开启、自助注册允许、邮箱确认开启、手机号关闭；地区表可读，游客不能读取资料或消息表，游客角色 RPC 返回 `visitor`。公开 API 无法配置 Auth 邮件模板或验证已登录角色授权，本次不调用管理员接口。

注册保留邮箱确认要求。默认确认邮件用链接，确认后返回软件登录；若队友将邮件模板加入 `{{ .Token }}`，手机软件可直接填写验证码。密码找回也支持验证码模板，网页确认链接的重定向需服务器配置正确。真实账号和消息需要用户的有效邮箱进行最终双账号、双设备联调；不凭空生成或对外发送测试邮件。

历史分页查询服务器时间与 UUID 组合游标，消息插入只提交获准列，不冒充 author_id。发送重试复用 UUID，唯一约束冲突查询原消息确认；任何网络失败不能显示发送成功。昵称不可写入角色字段。已有失物/热点/设施仍为本机数据，本次不宣称其已多人同步。
