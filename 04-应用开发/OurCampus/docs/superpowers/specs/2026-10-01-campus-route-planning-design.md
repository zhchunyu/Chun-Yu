# 校园地图路线规划设计

## 目标

让手机端用户可以从校园地图直接选择目的地、查看校内路线，并在地图上跟随路线位置理解走向。界面采用已选定的 A 方案：地图留在主视野，路线信息放在底部抽屉。

## 腾讯地图参考范围

- 保留当前本校区校园导览图，不替换为腾讯地图底图。
- 只借鉴地图优先的路线呈现：起终点标记、醒目的路线线条、底部路线方案卡片。
- 不加载腾讯地图 SDK，不调用腾讯路线 API，不复制腾讯地图图块；此方案不需要腾讯 API Key。
- 项目继续使用本地校园地点和路网。路线距离与耗时显示为校园演示估算，不标示成腾讯或实时导航数据。

## 用户流程

1. 地图首页的起点默认取当前已选的模拟校园位置；未设置时使用现有演示默认起点，并明确其为模拟位置。
2. 用户搜索目的地，或点击地图上的校园地点，在地点详情中选择“到这里”。
3. 规划后留在地图首页：起点和终点带有明显标记，地图上显示选中的路线，底部抽屉展示路线方案。
4. 用户可在抽屉内更换起终点、交换方向、选择其他路线方案、展开分段指引或清除路线。
5. 用户点击其它路线方案后，地图路线与路线摘要同步切换；拖动和缩放地图时路线保持在地点对应的位置。

## 路线方案

- 校内以步行为固定出行方式；保留项目已有的最短、无障碍、避开施工、避雨和夜间安全策略。
- 每个可用方案显示距离、估计步行时间和简短策略说明。多个策略若计算出相同路径，只展示一条，避免重复路线卡片。
- 路线指引复用已有的分段指引数据。当前版本不提供实时 GPS、语音引导或后台导航。
- 关闭地点、无可行路径和路线数据不完整时，底部抽屉说明原因并给出修改起终点或策略的入口。

## 路线与地图数据

- 继续使用项目的 `campusRouteGraph`、`createDemoRoute` 和校园地点数据，不增加运行时依赖或服务端。
- 当前路网节点的二维投影来自旧的校园 SVG，而当前首页使用另一张校园导览图；不能直接启用旧投影。
- 在显示路线前，为当前导览图校准路网节点到地图图像坐标的映射，并检查路线是否沿图中道路通过。坐标不完整或校准不可靠时，不画路线线条，并显示校准状态，不能用直线猜测路线。
- 路线坐标使用与地点标记相同的地图变换，使平移、缩放和双指旋转始终保持同步。
- 地点坐标、路线网络及距离仍属于项目演示数据；后续可单独评估真实校园道路数据来源。

## 界面与组件

- 复用 `MapWorkspace`、`Campus2DViewer`、`RouteDock`、`TripPanel` 与现有校园 reducer；路线状态只保留一份。
- 手机地图首页负责选点与结果抽屉；行程页保留完整的起终点编辑入口。
- 路线结果抽屉包含起终点摘要、交换/编辑操作、可用方案列表、距离与估时、分段指引和清除操作。
- 桌面端布局和 3D 路线能力不在本次范围内。

## 验收标准

1. 搜索地点或从地图地点详情可以将其设为目的地，起点默认遵循模拟当前位置规则。
2. 规划完成后仍在地图首页，底部显示路线抽屉，起终点与路线方案状态一致。
3. 选择不同路线方案时，摘要和地图路线同步更新；无效或关闭的地点有明确恢复操作。
4. 路线几何沿当前校园导览图道路校准，且在缩放、平移、旋转后保持位置一致；未完成校准时不显示猜测路线。
5. 搜索、地点标记、路线清除和已有 3D 路线流程保持可用。
6. UI 明确标注模拟位置及估算距离/耗时，不声称提供真实导航或腾讯实时服务。

## 不包含

- 腾讯地图底图、SDK、路线 API、地图图块或开发密钥。
- 真实 GPS 定位、实时路况、语音导航、校外路线和路线服务端。
- 校园 GIS/道路数据采集或完整重绘；如果本地图无法可靠校准路网，需先获得可验证的道路数据再启用路线线条。
