# CampusTwin 手机浏览器访问设计

## 目标

提供一个手机浏览器可以直接打开的 HTTPS 链接，并确保校园地图的主要查看、搜索、地点详情和路线操作适合窄屏触控。

## 当前项目边界

- 应用是 Vite + React 静态前端，仓库没有配置线上托管，也没有 Git 远程地址。
- 当前校园演示数据和管理员改动保存在各浏览器的本地存储中，没有后端同步；手机与电脑的数据彼此独立。
- `public/assets/campus-extracted.glb` 约 42 MB，当前地图配置未引用，但 Vite 会将 `public/` 内容复制到构建产物。
- 页面已有 760px 手机断点，但地图固定最小高度、控件占位和面板布局仍需按手机浏览器重新检查。

## 范围

1. 优化 360–430 CSS 像素宽的竖屏体验，兼顾浏览器安全区和动态视口高度。
2. 让搜索、2D/3D 切换、地图工具、地点详情和路线面板在手机上可触控、可滚动，不相互遮挡。
3. 保留现有 3D 主地图和 2D 兜底场景；手机上维持本地演示数据与本地存储行为。
4. 生成可静态托管的生产构建，并确保构建只包含实际运行所需资源；保留未使用的模型源文件，但不将其放入发布产物。
5. 在上线目标可用后生成手机可访问的 HTTPS 链接。实际发布目标和公开链接在发布前确认。

## 不包含

- 新建账号系统、后端 API、跨设备数据同步或真实 GPS。
- PWA 离线缓存、应用商店封装或重制地图模型。
- 把演示数据描述为真实校园实时数据。

## 界面与行为

- 地图继续作为页面主区域；手机布局避免桌面固定高度强制产生额外滚动。
- 搜索和场景切换保持易达；工具及详情面板采用适合手机的折叠或底部面板布局。
- 路线预览保留起终点、模式切换、指引和清除操作；小屏下控制项换行或在面板内滚动。
- 3D 模型继续显示加载和错误状态，加载失败时用户可重试或切换到 2D。
- `localStorage` 行为不变，手机新浏览器中不会自动出现电脑上保存的管理员更改。

## 发布与资源策略

- 托管生产静态文件并提供 HTTPS，不启动开发服务器作为公开站点。
- 只发布应用配置实际引用的校园 GLB、平面图和 Draco 解码器资源。
- 未引用的 42 MB 模型仍保留在仓库源目录；生产产物不包含它。
- 选择具体托管目标时，说明链接是临时访问还是可持续访问；不把本机地址当作手机可访问的公网链接。

## 验收

1. 360×800 与 390×844 竖屏下无横向溢出，地图和主要控件能正常使用。
2. 搜索、地点筛选、地点详情、2D/3D 切换、路线预览和路线清除可通过触控操作。
3. 生产构建成功，未引用的 42 MB 模型不在 `dist/` 中，地图需要的 GLB、SVG 与 Draco 资源仍在。
4. 通过手机浏览器访问最终 HTTPS 链接，3D 加载正常或提供可操作的 2D 回退。
5. `npm test` 通过；报告构建包体积和演示数据的本地存储边界。
