# 大厅头像与成员主页修复设计

## 已核实的原因

实际发行代码位于 GitHub `release/ourcampus-1.16-20261016`，并非当前 main 的旧个人页面。`PersonalHome` 将头像保存在本机 localStorage；大厅仅查询昵称并硬编码首字；访客视角是本机预览，没有互访入口。

线上 `profiles.avatar_path` 和公开 `avatars` 存储桶已存在。2026-10-21 检查：9 份资料均没有头像路径，桶内无头像对象。事务验证普通登录用户可读基础资料、可更新本人、不能更新他人，全部回滚。无需放宽 RLS。

## 修复后的行为

1. 在现有个人主页选择并保存头像时，将压缩后的图片上传到本人目录，成功更新 `profiles.avatar_path` 后显示“头像已同步”。保存失败保留旧头像并允许重试。恢复默认头像同步清空路径。
2. 旧版仅保存在本机的头像提供明确的“同步本机头像”入口，不悄悄上传其他本机装扮。大厅、本人主页与访客页统一使用云端头像；无头像或图片加载失败时降级显示昵称首字。
3. 大厅头像和昵称可点击，按消息作者 UUID 打开成员主页。主页显示昵称、头像及最近未撤回的公开大厅发言，有加载、空内容、重试和返回状态。
4. 其他人更新头像或昵称后，实时更新该作者全部已加载消息；重新联网或回到前台补取资料。分页结果和迟到请求不得覆盖更新资料，切换账号时清理旧状态。
5. 访客页只读取基础身份与公开大厅发言。封面、签名、标签等已有本机装扮继续遵循其现有“仅自己可见”说明；邮箱、课表、收藏、路线、定位和私人报告不进入访客接口。

## 取舍

推荐沿用既有头像字段、存储桶与权限，修复客户端并增加只读成员页，范围清楚且无需数据库迁移。单改权限无法让本机头像上云；完整开放封面和签名需要另行定义公开范围与云端字段，不作为本次故障修复的前提。

## 验证和交付

先复现上传失败、资料字段缺失、旧历史头像不刷新和访问错误作者的回归用例，再完成修复并运行测试与生产构建。核对普通账号资料读取和所有者写入权限。真实双账号/手机验收、源码提交及新版 APK 分别报告状态，不把本地构建视作手机已更新。保留当前工作区其他尚未发布的修改，使用发行分支作为修复基线。
