# （历史）山河大学三维地图：模型建筑标签与地图路线设计

> **已被新版方案替代。** 当前总体产品和技术规划以 `2026-09-26-campus-twin-product-and-technical-roadmap-design.md` 为准；本文只保留模型锚点、三维标签和路线图实现细节，便于回看已有代码。

## 1. 背景

当前页面已经能加载队友上传的山河大学 GLB 模型，但地点标签、热点标签和路线仍然使用固定的百分比位置与 CSS 演示线。镜头旋转或缩放后，这些元素不会跟随真实建筑和道路，因此需要将它们绑定到模型坐标。

队友模型已经提供了 19 个独立的 `ANCHOR_*` 节点。锚点是根节点，坐标单位为米，和模型使用同一套坐标系。例如：

- `ANCHOR_Library`：`(0, 3, -518.4)`
- `ANCHOR_Teaching_A`：`(201.6, 3, -321.6)`
- `ANCHOR_Canteen`：`(302.4, 3, -76.8)`
- `ANCHOR_Gymnasium`：`(-336, 3, -187.2)`
- `ANCHOR_Main_Gate`：`(0, 3, -33.6)`

本次只改应用层，不修改队友的 GLB 文件，也不接入真实后端接口。

## 2. 目标与非目标

### 目标

1. 地点、建筑和热点标签绑定 GLB 中的真实锚点。
2. 旋转、缩放、拖动地图时，标签跟随对应建筑移动。
3. 点击标签可以选中对应地点，并与详情面板联动。
4. 路线使用模型坐标中的道路节点和建筑入口节点，在三维地图上绘制。
5. 五种路线模式继续可用，并能依据道路属性选择不同路径。
6. 数据结构为将来接入 `/api/locations`、`/api/routes`、`/api/events` 保留兼容边界。

### 非目标

1. 本次不从道路网格几何中自动识别完整道路图。
2. 本次不修改 Blender 模型或重新导出 GLB。
3. 本次不实现登录、真正权限校验和后端持久化。
4. 本次不扩展全部 19 个锚点的业务详情，先覆盖当前页面的 6 个核心地点。

## 3. 方案概览

```text
locations.js                  routeGraph.js
    │                              │
    ├─ modelAnchorId               ├─ 路口节点 / 建筑入口节点
    │                              ├─ 道路属性
    ▼                              ▼
GLB ANCHOR_* 节点 ───────► Three.js 场景坐标
    │                              │
    ├─ 相机投影                   ├─ A* / Dijkstra
    ▼                              ▼
三维跟随标签                  三维发光路线
```

采用“模型锚点 + 配置化道路图”，而不是依赖浏览器中的固定像素位置或第三方地图 API。道路图的节点和路线点使用 GLB 坐标，后续可以由真实接口返回同样的数据结构。

## 4. 地点数据绑定

在现有地点数据上增加模型绑定字段：

```js
{
  id: 'library',
  name: '图书馆',
  modelAnchorId: 'ANCHOR_Library',
  entryNodeId: 'library-entry'
}
```

首版映射如下：

| 页面地点 | 模型锚点 | 路线入口 |
| --- | --- | --- |
| 图书馆 | `ANCHOR_Library` | `library-entry` |
| 第一教学楼 | `ANCHOR_Teaching_A` | `teaching-a-entry` |
| 学生食堂 | `ANCHOR_Canteen` | `canteen-entry` |
| 学生宿舍 | `ANCHOR_Dorm_West` | `dorm-west-entry` |
| 体育馆 | `ANCHOR_Gymnasium` | `gymnasium-entry` |
| 东门服务中心 | `ANCHOR_Main_Gate` | `main-gate-entry` |

“学生宿舍”首版使用西区锚点作为路线入口；数据结构预留 `modelAnchorIds`，以后可以扩展为东西宿舍两个标签。现有业务名称暂时保留，模型名称作为绑定依据。

如果锚点名称不存在，页面不应崩溃：该地点显示“模型锚点待校准”，路线按钮禁用，并在开发环境输出清晰警告。

## 5. 三维标签实现

### 5.1 标签位置

`Campus3DViewer` 加载 GLB 后，通过 `scene.getObjectByName(modelAnchorId)` 取得锚点，再使用 `getWorldPosition()` 获得世界坐标。每帧将世界坐标通过 `Vector3.project(camera)` 投影到地图容器的屏幕坐标。

标签由地图覆盖层渲染，位置使用 `transform: translate3d(...)` 更新，不再使用 `left/top` 百分比。标签至少包含：

- 建筑名称
- 地点分类
- 当前状态色
- 可点击区域
- 从标签到锚点的细引导线或定位点

标签在镜头外时隐藏，在地图容器边界附近做安全裁切。标签默认随镜头移动，不强行保持在屏幕中央。

### 5.2 选中反馈

点击地点标签或详情面板中的“定位到这里”时：

1. 更新 `selectedId`。
2. 对应建筑或锚点显示选中光环/脉冲点。
3. 相机可以平滑移动到该锚点，但不强制改变用户的观察角度。
4. 详情面板继续使用现有数据源。

首版不做复杂的建筑材质替换，以免影响 GLB 性能；使用锚点光环、标签高亮和相机聚焦完成反馈。

### 5.3 热点绑定

热点事件已经通过 `locationId` 关联地点，因此热点标签也使用地点的模型锚点，不再按事件索引生成随机百分比位置。多个事件在同一地点时合并为一个地图热点入口，详情列表中显示事件数量。

## 6. 路线图与路径算法

### 6.1 路线图数据

新增本地路线图配置，节点使用模型的 `x/y/z` 坐标：

```js
{
  id: 'library-entry',
  kind: 'location-entry',
  locationId: 'library',
  position: [0, 4, -518.4]
}

{
  from: 'axis-library',
  to: 'library-entry',
  distance: 80,
  accessible: true,
  covered: false,
  blocked: false,
  safeAtNight: true
}
```

节点分为：

- 建筑入口节点：和地点数据的 `entryNodeId` 对应。
- 道路路口节点：沿模型中的 `SITE_主路`、`SITE_步道` 和广场连接关系布置。
- 校门节点：作为访客模式默认起点。

每条边保留距离、无障碍、遮雨、施工和夜间安全属性。距离以米为主，不从当前页面文案反推路线长度。

### 6.2 路径计算

使用 A* 计算节点路径；启发函数使用节点坐标的 XZ 平面欧氏距离。若图规模很小，算法退化为 Dijkstra 也应得到同样结果。

不同模式的处理规则：

- 最短路线：以 `distance` 为代价。
- 无障碍路线：过滤 `accessible === false` 的边。
- 避开施工：过滤 `blocked === true` 的边。
- 避雨路线：优先 `covered === true`，没有完全遮雨路线时再选择可达的次优路线。
- 夜间安全：优先 `safeAtNight === true` 的边，并保留可解释的路线结果。

如果起点或终点没有可达路径，详情面板显示原因，不绘制旧路线，避免用户误以为路线仍然有效。

## 7. 三维路线显示

路径计算得到的节点序列转换为模型坐标，传给 `Campus3DViewer`。路线在地面上方使用固定高度绘制，避免和道路模型发生深度冲突：

- 路线主体：蓝绿色发光折线。
- 起点：圆形起点标记。
- 终点：带名称的终点标记。
- 当前选中路线：动画流光或短虚线效果。
- 施工边：不进入结果；若管理员刚设置施工，路线重新计算。

路线统计仍显示距离、预计时间和路线模式，但数值来源改为实际节点路径。旧的固定 CSS `.map-route-line` 只在迁移期间保留，完成后删除。

## 8. 组件与数据边界

建议职责划分：

- `src/data/locations.js`：地点业务信息与模型锚点映射。
- `src/data/routeGraph.js`：首版校园道路图配置。
- `src/domain/route.js`：路径搜索、模式约束和路线结果格式。
- `src/features/map/Campus3DViewer.jsx`：GLB、锚点注册、相机投影和三维路线渲染。
- `src/features/map/MapWorkspace.jsx`：地点/事件筛选、标签交互、路线结果传递。

统一的路线结果格式：

```js
{
  originId,
  destinationId,
  mode,
  distance,
  durationMinutes,
  nodeIds,
  points,
  status: 'preview' | 'unavailable'
}
```

未来真实 API 只需要返回相同的数据语义，前端不应依赖 API 的具体字段名。可以通过现有 `campusDataSource` 增加 `routeSource`，首版继续使用本地实现。

## 9. 分阶段实施

### 第一步：绑定地点

- 为 6 个地点增加 `modelAnchorId` 和 `entryNodeId`。
- 读取 GLB 锚点并建立注册表。
- 移除固定建筑卡片位置，改为锚点投影标签。
- 将热点标签改为地点锚点。

### 第二步：建立路线图

- 创建主轴、校门、图书馆、教学楼、食堂、宿舍、体育馆之间的道路节点。
- 编写 A* / Dijkstra 路径函数。
- 用单元测试覆盖五种模式、施工封闭和不可达情况。

### 第三步：接入三维路线

- 在 Three.js 场景绘制路线折线、起终点。
- 路线模式切换时重新计算和重绘。
- 删除固定 CSS 演示线。

### 第四步：联动验收

- 点击图书馆标签，确认标签、建筑、详情和终点一致。
- 旋转、缩放地图，确认标签跟随建筑。
- 选择避雨/无障碍/避施工路线，确认路线沿模型道路变化。
- 发布热点或关闭建筑后，确认热点、状态和路线同步。

## 10. 验收标准

1. 页面中不存在用于地点定位的固定百分比位置。
2. 图书馆标签投影点与 GLB 的 `ANCHOR_Library` 对齐，旋转和缩放后仍保持绑定。
3. 当前 6 个地点均能正常选中；缺失锚点时有明确降级提示。
4. 起点和终点使用地点入口节点，路线折线出现在三维模型道路附近，而不是页面平面上。
5. 五种路线模式至少产生两种可观察的路线差异，施工边不会被选中。
6. 现有搜索、分类筛选、详情面板、管理员发布热点功能继续可用。
7. `npm test -- --run` 和 `npm run build` 均通过，且没有新增运行时错误。
8. 大模型加载失败时仍显示错误状态，标签与路线逻辑不会导致页面崩溃。

## 11. 风险与取舍

- GLB 没有完整的语义道路图，因此首版道路节点需要按模型道路人工配置；这是可控且便于比赛演示的取舍。
- 模型锚点是根节点，当前获取世界坐标比较稳定；若未来 Blender 改名，需要在数据校验中报告缺失锚点。
- 每帧更新多个标签会增加少量 DOM 更新；首版只展示 6 个核心地点，并使用引用直接更新样式，避免高频 React 状态刷新。
- 路线线条位于地面上方，不追求精确贴合每个道路网格三角面；后续如果有 GIS 路网，再替换 `routeGraph` 数据而不改 UI。

## 12. 模拟我的位置与第一人称漫游附录

### 12.1 模拟我的位置

由于当前版本没有 GPS 或真实用户定位接口，增加一个“我的位置”选择器，使用校园地点入口模拟当前位置。用户可以从东门、图书馆、教学楼、食堂、宿舍和体育馆中选择一个位置。

选择结果写入应用状态 `currentLocationId`，并通过相同的模型锚点体系在三维地图中显示蓝色“我的位置”标记。没有选择时保持默认起点 `east-gate`，不影响原有演示流程。

路线规划的默认起点改为 `currentLocationId ?? 'east-gate'`。切换模拟位置后，如果当前已有目的地路线，使用新的起点重新计算路线；如果当前没有路线，只更新位置标记。

### 12.2 第一人称模式

在三维地图上增加“俯视 / 第一人称”切换按钮。第一人称模式使用当前模拟位置对应锚点的 XZ 坐标，将相机放在地面上方的观察高度，并使用 `PointerLockControls`：

- WASD 移动。
- 鼠标环顾。
- Esc 退出指针锁定并返回俯视模式。
- 未选择模拟位置时从 `ANCHOR_Main_Gate` 开始。
- 第一人称下隐藏地点标签，但保留模式提示和退出按钮。
- 退出后恢复原有 OrbitControls 与镜头目标，不销毁 GLB 场景。

第一人称移动只在校园模型范围内启用基础边界限制，不做碰撞检测；后续有碰撞数据时可以在控制器层替换。切换模式仅属于地图视图状态，不进入未来地点/路线 API。

### 12.3 新增验收标准

1. 选择图书馆后，地图显示“我的位置”蓝色标记，路线起点变为图书馆。
2. 有路线时切换模拟位置，路线自动重新计算；无路线时不生成假路线。
3. 未选择位置时，路线仍默认从东门开始。
4. 第一人称从当前模拟位置附近进入，WASD 和鼠标可控制视角，Esc 可返回俯视。
5. 第一人称和俯视切换不会重新加载 GLB，也不会产生控制台错误。
