# 数据字段与来源

以下字段核对自当前项目 `docs/supabase/01-CampusTwin-schema.sql`。**表被定义、表已在线、页面已接入、数据真实有效是四个不同状态**；服务器队友需要分别核对。下面不把 SQL 预留结构当作已上线业务。

## 1. AI 需要的数据

| 数据 | 表及主要字段 | 当前状态与使用边界 |
| --- | --- | --- |
| 地区 | `campus_regions(id,label)` | 5 个地区有种子数据；此前已只读核对在线地区数据。`all` 为前端筛选值，不是数据库地区 |
| 校园地点 | `campus_locations(id,name,aliases,keywords,category,region_id,description,external_url)` | 种子含 66 个地点；线上导入与修正情况需核对。名称可能重复，关联必须用 `id` |
| 地点坐标 | `latitude,longitude,coordinate_system,geo_source,geo_verified,map_position` | 经纬度为 GCJ-02；`map_position` 是图片比例坐标，不能当经纬度。种子坐标未现场核验，不用于精确室内/道路判断 |
| 地点状态 | `open_status,crowd_status,activity,updated_at` | `unknown` 表示未知；`updated_at` 不是现场核验时间，不能单凭更新时间称“实时拥挤/开放” |
| 校园服务 | `campus_services(id,title,location_id,summary,hours,phone,phone_note,website,source_url,keywords,updated_at)` | 种子含 4 项服务。`hours` 可能为 null；部分电话来源较早，保留 `phone_note` 和来源，使用前需核实 |
| 用户资料 | `profiles(user_id,nickname,avatar_path,created_at,updated_at)` | 账号代码已接入。当前没有专业、班级、宿舍、课程、常用路径字段；不应把公开昵称表扩展为公开个人画像 |
| 用户角色 | 私有角色表；RPC `campus_my_role()` | 返回 `visitor/student/manager`。角色由服务端取得，不接受客户端自报；普通用户无法直接读写私有角色表 |
| 校园事件 | `campus_events(id,location_id,type,title,impact,status,heat_level,start_at,end_at,affected_edge_ids,visible_to,source,source_url,is_demo,updated_at)` | SQL 已定义；手机仍使用本机事件数据。`is_demo=false` 不自动证明真实，还需要受控发布和可追溯来源 |
| 设施 | `facility_contributions(id,type,name,location_id,detail,status,reviewed_by,review_note,created_at,updated_at)` | 公开事实只用 `verified`；页面目前本机原型 |
| 地点反馈/报修 | `place_feedback(id,location_id,type,description,status,crowd_status,open_status,repair_category,reported_end_at,reviewed_at,approved_event_id)` | 页面目前本机。普通反馈 `pending/approved/rejected`；报修 `pending/processing/completed`。审核并不自动生成真实事件；需要后端业务流程 |
| 失物招领 | `lost_found_posts(id,type,title,description,location_id,location_detail,occurred_at,status,contact,image_path)` | 页面目前本机。后续 AI 如检索，按权限读；普通摘要不携带联系方式、照片或其他用户身份信息 |
| 聊天 | `hall_messages(id,author_id,region_id,content,client_message_id,reply_to,deleted_at,created_at)` | 已接入云端代码，双账号实机联调待完成。聊天内容不作为官方通知来源，也不默认作为 AI 训练或事实上下文 |
| 个人通知 | `notifications(id,recipient_id,type,title,body,related_type,related_id,read_at,created_at)` | SQL 已预留；消息中心/推送未接入。现有类型含 `campus-event`，没有 `ai-reminder`；新增类型须显式迁移 |

## 2. 枚举和关联

- 地区：`teaching` 教学区、`living` 生活区、`dorm` 宿舍区、`sports` 运动区、`gate` 校门周边。
- 地点分类：`learning/dining/living/service/transport`。
- 事件类型：`activity/crowd/notice/closure/construction`；状态 `active/scheduled/closed`。
- 地点开放：`unknown/open/limited/closed`；拥挤：`unknown/low/normal/busy`。
- 设施审核：`pending/verified/rejected`。
- 关联链：`campus_services.location_id → campus_locations.id`；`campus_events.location_id → campus_locations.id`；`campus_locations.region_id → campus_regions.id`。
- 服务 `location_id` 可为空，例如线上办事入口；这种卡片可以打开官网，不能强行生成地图导航动作。
- SQL 使用 snake_case，已有前端对象使用 camelCase；适配时显式映射，例如 `location_id → locationId`、`start_at → startAt`。
- 时间使用含时区的时间值，界面按 Asia/Shanghai 展示；事件有效窗口为 `[start_at,end_at)`。

## 3. 首版读取范围

建议先读取地点、地区、校园服务，以及按角色可见、时间有效、来源可追溯的非演示事件。用户资料只需本人昵称。课程、长期位置轨迹、其他用户消息和联系方式不在这份最小上下文范围内。

普通查询使用实际登录用户的权限。公共数据也可按现有游客规则查询；本包拟定的 AI 接口要求先登录。若服务端另有管理员凭据，不能让用户问题触发任意 SQL 或任意表查询。后台身份不自动代表请求者有管理员权限。

## 4. 目前缺失的数据

| 想实现的能力 | 还需要什么 | 目前不能直接承诺什么 |
| --- | --- | --- |
| 课前提醒 | 本人课程、具体日期/时间、教室到地点 ID 的映射、个人提醒设置 | “明天 8 点你有课” |
| 从宿舍到教室的规划 | 用户主动选择起点或授权当前位置、目的地、可靠路线与耗时 | “你住某宿舍”“你习惯走某路” |
| 施工绕行并计算提前量 | 实际受影响道路/区域与导航路线的可靠空间关联、可用绕行路线 | “绕行多花 15 分钟” |
| 天气提醒 | 有来源、观测/预报时间与覆盖区域的天气接口 | “今晚下雨” |
| 实时拥挤程度 | 可信数据采集、审核流程、明确的时效定义 | “食堂现在排队 20 分钟” |
| 室内导航 | 可靠楼层图、通道和室内定位/起点 | “上二楼左转到某室” |
| 主动手机通知 | 明确授权、服务端调度、接收人、去重记录、推送通道 | “已在后台提醒所有同学” |

这些能力如纳入范围，需要先确定数据来源与权限，再做迁移或接口。本包没有新增课表/用户画像表。

## 5. 本地代码入口

- `src/data/supabaseClient.js`：SDK 初始化、环境变量名和错误处理。
- `src/features/account/useCampusAuth.js`：真实会话、个人昵称、角色读取。
- `src/data/hallService.js`、`src/features/mobile/useRealtimeHall.js`：消息查询及实时订阅的当前用法。
- `src/data/events.js`：含随启动时间生成有效窗口的**演示事件**，不可当作校园实时公告。
- `src/domain/campus.js`：已有本机热点有效期与角色展示判断。
- `src/data/campusDataSource.js`：当前本机数据源。
- `src/data/httpCampusDataSource.js`：预留 HTTP 适配器；其 `/api/snapshot` 等路径不是当前已部署接口。
