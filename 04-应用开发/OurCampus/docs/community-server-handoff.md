# 大厅与附近设施：服务器对接说明

## 已有前端入口

- 大厅：聊天、校园热点、失物招领；按校园地区筛选。
- 我的：账号登录原型、我的失物发布。
- 地点：附近设施，补充设施与本机模拟确认。
- 地图：热点标记、可选的寻找中失物标记、地点详情与现有导航联动。

当前实现使用本机数据，没有真实账号，也不向其他设备广播。服务器就绪后，替换 App 中集中处理的提交、状态更新、删除和审核操作；验证与存储逻辑在 `src/data/campusCommunity.js`，不需要改变页面布局。尚未确定接口地址、数据库或认证方案，因此以下是业务约定，不是已经可调用的 API。

## 稳定字段

地点使用项目现有 `locationId`，不要靠建筑名称关联（同名车间等地点可能重名）。地区 ID：`teaching`、`living`、`dorm`、`sports`、`gate`；`all` 只用于筛选。

| 对象 | 字段与状态 |
| --- | --- |
| 失物信息 | `id, authorId, type(lost/found), title, description, locationId, locationDetail, regionId, occurredAt, contact, image, status(active/resolved), createdAt, updatedAt` |
| 设施贡献 | `id, authorId, type, name, locationId, detail, status(pending/verified/rejected), createdAt, updatedAt` |
| 校园热点 | 沿用现有事件的 `id, locationId, type, title, impact, startAt, endAt, status`；封路等字段沿用 `src/data/events.js` |

日期使用含时区的 ISO 字符串。真实作者 ID 从登录会话中获取，本机的 `local-device` 不是账号。照片在正式接入时改为上传返回的地址；当前本机照片是压缩后的 data URL。设施位置当前仅关联建筑，导航到所属建筑；如要导航到室外设施本身，先采集并注明坐标系与精度。

## 建议服务器按顺序支持

1. **真实账号**：沿用已确认的登录界面，确认登录方式、会话有效期与退出流程；身份、作者和管理员权限均由服务器验证。
2. **失物与热点**：列表筛选／分页、失物详情、发布／编辑／完成／删除、照片上传；校验地点 ID、时间、文本长度、作者所有权。热点由授权管理者维护，服务端处理到期状态。
3. **设施贡献**：提交待确认记录、管理者确认或拒绝；公开查询只返回已确认设施。现场未确认的开放时间、电话或位置仍标记未知。
4. **多人聊天**：地区消息历史、发送确认、实时订阅、断线重连和去重；发送失败保留输入，不能把仅在客户端显示当作已送达。
5. **消息中心**：认领联系／发布状态变更／审核结果／聊天回复等通知，提供未读数量、分页、已读状态和返回对应条目的入口；服务端校验收件人。

消息中心的具体通知类型和认领沟通方式可在服务器联调时确定。正式环境不复用前端的角色切换作为管理权限；联系方式由详情查看流程展示，不需要暴露在列表摘要中。没有网络或保存失败时，应向页面返回明确错误，不自动降级成“已同步”的本机记录。

## 联调前需要的信息

服务器访问地址（手机需可达）、认证方式、接口请求与返回示例、实时连接方式、图片上传限制、校园地点 ID 映射及通知事件定义。提供这些后可先完成登录和一条失物信息跨设备同步，再接聊天和消息中心。
