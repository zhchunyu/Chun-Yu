## 队友需要检查的配置

### 1. 允许其他同学接收认证邮件

在 Dashboard 的 Authentication 邮件/SMTP 配置中检查是否已有可用的自定义 SMTP。Supabase 默认邮件服务只向项目团队授权邮箱发送，不能据此保证普通同学收到邮件。请配置实际的 SMTP 主机、端口、用户名、密码和发件人，检查真实收件、垃圾箱及发送限制。SMTP 密码只填后台，前端不需要。[官方 SMTP 说明](https://supabase.com/docs/guides/auth/auth-smtp)

### 2. 手机端使用纯数字验证码邮件

用户已确认邮件只显示数字验证码。具体主题、正文文件与保存步骤见 [邮件数字验证码设置](email-templates/邮件数字验证码设置.md)。在 Authentication → Emails → Templates 的 **Confirm signup** 邮件中用验证码正文替换原内容：

```html
<h2>确认你的校园账号</h2>
<p>你正在注册数字校园孪生，邮箱验证码为：</p>
<p style="font-size:24px;font-weight:bold">{{ .Token }}</p>
<p>请返回软件填写。不是本人操作，请忽略本邮件。</p>
```

在 **Reset Password** 邮件中添加同样的 `{{ .Token }}`，正文改为密码重置。软件支持 6–10 位数字验证码，实际长度与有效期由 Supabase 配置决定。注册确认调用 `verifyOtp({email, token, type:'email'})`，密码重置用 `type:'recovery'`。[官方邮箱验证接口](https://supabase.com/docs/reference/javascript/auth-verifyotp)

这两项认证邮件使用 `{{ .Token }}`，删除默认确认链接。软件已按数字验证码提示用户，后台保存后才会按新模板发送邮件；之前收到的邮件不会改变。当前 APK 没有新增 Auth 深链接。

### 3. 网页确认链接的地址

核对 Authentication → URL Configuration 的 Site URL 与允许的 Redirect URLs，填写实际用于确认邮件的网页地址。当前开发预览为 `http://127.0.0.1:5173/`，只在开发电脑可访问；`localhost` 或 `127.0.0.1` 不能作为其他同学手机可访问的正式网站。发布 HTTPS 网站后填正式地址。手机 APK 推荐直接输入邮箱验证码。

### 4. 数据库与实时广播

继续使用前次交接包结构，不要重新执行建表 SQL 覆盖现有数据。确认 `profiles`、`hall_messages`、`campus_regions` 和 `campus_my_role` 已按指南配置。地区种子应该有 5 行，缺失才补执行 `02-CampusTwin-seed.sql`。

检查 Realtime publication 中包含 `public.hall_messages`：

```sql
select schemaname, tablename
from pg_publication_tables
where pubname = 'supabase_realtime'
  and schemaname = 'public' and tablename = 'hall_messages';
```

无记录时由队友在 SQL Editor 执行一次：

```sql
alter publication supabase_realtime add table public.hall_messages;
```

不要为了让游客进入聊天而撤销 RLS 或把消息表改成公开可读。已登录用户的必要权限是：SELECT 消息/昵称；INSERT `region_id,content,client_message_id,reply_to`；本人 UPDATE `deleted_at`。作者由默认 `auth.uid()` 产生，不接受客户端冒充账号。[官方数据库实时变更说明](https://supabase.com/docs/guides/realtime/postgres-changes)

## 双账号、双设备联调顺序

1. 用两个真实邮箱注册账号 A、B，完成邮箱确认，给出不同昵称。如果暂时没有 SMTP，队友可在 Auth Users 创建两个专用测试账号并确认邮箱；不要关闭全项目邮箱确认来掩盖邮件问题。
2. A、B 分别登录网页/两部手机。在大厅点“聊天”，确认显示“实时聊天已连接”。不需要两台设备在同一 Wi-Fi，均需能访问 Supabase。
3. A 选择生活区发送，B 的“全部”和“生活区”出现相同内容；B 的“教学区”不出现。B 回复，A 收到。
4. 刷新或重开软件，历史存在、会话恢复。点“查看更早消息”按地区取历史。
5. A 撤回本人消息，两台都移除；B 不能撤回 A 的消息。
6. 关闭网络后不宣称实时连接；发送失败保留草稿。联网重试不产生重复消息。切换地区或重新进入前台后同步最近消息。
7. 修改大厅昵称后新消息读取新昵称；退出登录后消息清空，不能读取或发送大厅消息。普通账号不能切换到管理者。

若只有定时更新，先检查 Realtime publication、WebSocket 访问和消息表权限。若注册报“邮箱服务不允许”或发送频率错误，先查 SMTP、授权邮箱及额度。若资料加载或发送报权限错误，核对 SQL 和 Auth 新用户触发器，不修改前端假装成功。
