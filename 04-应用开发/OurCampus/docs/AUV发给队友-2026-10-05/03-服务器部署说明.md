# 部署 AUV 转发函数

这是给已有 Supabase 项目接入 AUV 的增量部署包。函数需要现有用户登录会话，校园事件和服务信息按用户的数据库权限读取。无需重建原来的账号或聊天表。

## 准备

- 项目 ID：`hkdblizadnkskxslyjyq`。
- 负责部署的同学需要已有 Supabase 项目的部署权限；手机端 Publishable key 不能用于部署。
- 从 AI 同学取得当前可用的 HTTPS 服务根地址。
- 从负责人私聊取得 `.env.auv-secrets`，补上最新的 `AUV_BASE_URL`。
- 手机端调用的函数名固定为 `auv-assistant`。

## 1. 合并代码

将共享包中的 `supabase/functions/auv-assistant/` 与 `supabase/functions/_shared/` 放入现有部署工程。

`supabase/config.toml` 只提供本函数配置段，把它合并到原配置中，保留其他项目设置：

```toml
[functions.auv-assistant]
verify_jwt = true
```

## 2. 配置 Secrets

后端需要的私密配置只有这两项：

| 名称 | 如何填写 |
| --- | --- |
| `AUV_BASE_URL` | AI 同学最新地址，例如 `https://服务域名:端口`，不带 `/docs`、`/v1` 或 `/v1/chat/completions` |
| `AUV_API_KEY` | 负责人私聊提供的密钥 |

在 Supabase 项目的 Edge Functions Secrets 中配置。也可以在已经安装并登录 Supabase CLI 的电脑上，将负责人提供的环境文件放到当前部署工程目录，再运行：

```sh
supabase secrets set --env-file .env.auv-secrets --project-ref hkdblizadnkskxslyjyq
```

先填写最新地址，再运行命令。这个共享包内的 `auv-secrets.example.env` 只有字段模板，没有真实密钥。

函数还读取平台自动提供的 `SUPABASE_URL`、`SUPABASE_ANON_KEY`。模型密钥不使用 `VITE_` 前缀。

## 3. 部署函数

在包含 `supabase/` 的工程目录运行：

```sh
supabase functions deploy auv-assistant --project-ref hkdblizadnkskxslyjyq
```

预期访问地址：

```text
https://hkdblizadnkskxslyjyq.supabase.co/functions/v1/auv-assistant
```

该地址是 POST API，不是网页，不能用“直接打开后没有首页”判断部署失败。

## 4. 验收与回执

- 无登录凭据的 POST 请求应返回 401。
- 已登录用户的请求应进入函数，服务器侧继续核验用户身份。
- 模型可用时，校园建议回复 `kind=answer`、`generated_by=auv`。
- 事件分析回复 `kind=event`、`generated_by=auv`，地点由原文或手动选点核验。
- 模型服务关闭、地址过期时应显示可操作的错误，不返回假模型回复。
- 只检查并转发去掉密钥、Authorization 头和用户资料的错误信息。

用 `04-联调回执模板.txt` 告知负责人完成状态。手机端随后用真实登录会话联调；无需把用户 token 发进群聊。

## 数据与事实范围

调用 `persona` 时读取的事件只包含 `is_demo=false`、`status=active` 且处于有效时间内的记录。读取失败会标注动态数据未取得，不把示例人流当成实时数据。

地点表在 `_shared/campus-catalog.js`，66 个 ID 与手机项目对应。两个车间标准名称与软件一致，历史名称保留为别名。`extract` 结果不会自动写入热点或触发通知。

## 故障处理

| 现象 | 检查项 |
| --- | --- |
| 函数未部署 / 404 | 函数名、项目 ID 与部署结果 |
| Supabase 401 | 登录会话、项目 JWT 配置和函数日志，不关闭用户校验 |
| 模型鉴权失败 | `AUV_API_KEY` 是否与 AI 同学一致 |
| 模型服务 404 | `AUV_BASE_URL`、推理服务启动状态和端口映射 |
| 超时 | GPU 是否在线、冷启动、上游网络 |
| 动态数据不可用 | `campus_events`、`campus_services` 是否存在以及当前用户读取权限 |

本次提供了代码与本地验证结果，尚未取得真实模型成功回复或云端函数部署结果。部署后保留原函数版本，以便有问题时回退这一个函数。

参考：[Supabase 函数鉴权](https://supabase.com/docs/guides/functions/auth)。
