# OurCampus 个人管家：AI 与数据库开发交接包

日期：2026-10-15。面向负责 AI、数据库及后台服务的同学。

**目标：把今日安排、一句话规划、事项持续跟进、冲突和遗漏提醒、校园办事助手、可编辑的个人偏好，接成一套能持续处理个人事务的校园管家。**

## 先区分状态

| 内容 | 当前状态 |
| --- | --- |
| 地图、账号、社区、课表导入、校园服务、失物与报修入口 | 当前项目已有；保留现有功能和地点 ID |
| 重要/相关通知、失物候选匹配、收藏和兴趣偏好、个人 AI 上下文 | 已有本地代码和独立测试，基础包见下；本次未核验云端部署状态 |
| 上述六项个人管家功能 | **待开发**；本包是需求与接口设计，不代表已经实现 |
| 锁屏、退出软件后的厂商推送 | 本轮不做，只做软件内消息和前台提醒 |

本包没有新增可直接上线的六项功能迁移或服务代码。`contracts/` 为 **v1 拟定契约**；新表、新 RPC 和 `mode=plan` 都必须开发后才能调用。

## 附件怎么用

- `reference/通知基础实现-2026-10-15.zip`：之前已经形成的通知基础交接包，原文件不变。内有 09/10/14 号 SQL、两个 Edge Function 及共享模块和原验证说明。先按其 README 检查现有环境，不能把它当作六项功能的成品。
- `reference/current/`：本轮核对过的少量当前代码快照，供理解课表、服务目录和接口；不要求覆盖仓库文件。
- `contracts/ai-plan-result.schema.json`：拟定的规划结果 JSON Schema。
- `contracts/rpc-contracts.json`：拟定 RPC、参数、响应和错误约定。
- `examples/`：全部是合成联调样例；不是实际用户数据或学校的真实活动公告。
- `verify_package.py` 和 `SHA256SUMS.txt`：本地包内容、样例和校验和验证。运行验证不会连接数据库、调用模型或安装依赖。

## 两位同学分别先做什么

**数据库/后台同学：**核对现有 09/10/14 基础，落实本人数据隔离、课表同步、待办和事项状态、规划确认事务、提醒调度与去重；提供增量迁移和 RPC。

**AI 同学：**沿用现有 AUV 网关，增加规划和办事建议能力；读取经过授权的当前数据，返回带依据的结构化草案；用规则校验时间冲突、来源和有效性。先联通现有模型服务，无需先训练新模型。

两侧先对齐 v1 契约，再让前端接入。遇到契约调整，请同步更新文档、Schema、样例和版本，不单独改字段。

## 贯穿全部功能的要求

通知只在“特别重要”或“有明确依据与本人相关”时产生。**经确认的施工导致道路不能通行，也属于重要事件。**普通新活动和失物发布保留在社区，不自动全量进入消息中心。

AI 提建议；正式通知由授权人员确认；日程写入由用户确认；数据库负责权限、幂等、状态和冲突校验。现有地图、课表、社区、报修、官方服务入口和清爽校园风格保留。
