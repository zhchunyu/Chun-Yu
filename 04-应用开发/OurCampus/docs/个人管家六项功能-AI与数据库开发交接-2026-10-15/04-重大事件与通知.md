# 重大事件与个人相关通知

用户明确要求：**特别重要，或者有明确依据与本人相关，才通知。施工导致道路不能走，也算重要事件。只做软件内通知。**

## 决策分为两步

先判断信息是否有效、是否经授权确认，再判断重要性与本人相关性。AI 的“疑似重要”不等于已发布的正式重要公告；普通用户的一条“听说封路”不能直接全员通知。

| 情况 | 消息中心 | 前台提醒与解释 |
| --- | --- | --- |
| 经确认的主要道路封闭/无法通行，重要停水停电、安全风险、范围广的关键调整 | 按确认的影响范围发送，确需全校知晓时全员 | priority=3；说明受影响区域、有效时间、信息来源及需采取的行动 |
| 局部施工但未阻断通行、局部设施维修 | 只给有明确依据受影响的人 | 根据用户明确路线、当天课程/待办地点、关注地点等解释；不能只凭“施工”两个字升级全员 |
| 与本人白色耳机寻物具备可核对特征的招领 | 只给相关当事人，匹配开关生效 | priority=2；说明共同特征和待核对点，不判定物主 |
| 收藏图书馆、明确阅读兴趣对应的有效活动 | 只给有相关依据且未屏蔽的用户 | priority=2；说明收藏/兴趣依据，重复推荐聚合 |
| 本人待办截止、真实时间冲突、办理步骤缺件 | 只给本人 | priority=2；说明日期/冲突对象/指南要求，给下一步 |
| 普通无关新活动、无关失物、重复或过期内容 | 不新建个人消息 | 留在社区或不再展示，不弹横幅 |

priority=1 保留用于用户主动订阅的低优先信息；订阅表示明确意愿，但仍需有效、去重和免打扰。`priority=0` 不用于绕过筛选塞入一批普通新发布。

## 施工封路需要哪些信息

- 具体区域/道路、影响方式（完全不能走/限行/仅绕行提示）、开始与预计结束时间。
- 来源、现场核实/官方确认记录、审核人、审核时间、事件版本。
- 可以确认的替代入口或路线依据；不清楚时只提示避开并查看现场公告，不编造绕行道路。
- 影响范围 all/area/route 和选择理由。重要程度与范围分开：局部严重封路也可能只对某区域/路线用户相关。

“与你的路线有关”只能使用用户主动保存/本次规划的路线、已确认的途经关系及有效封路证据。现有 `affected_edge_ids` 含兼容演示道路 ID，不等于完整真实路网；不能仅凭建筑距离近就宣称已证明路线穿过封路段。证据不足时写“该区域通行可能受影响”，不能输出确定的个人路线命中。

## 当前实现与待调整点

14 号现有 `campus_review_report` 对 construction/closure/water-power **一律将 scope 设为 all**，也没有本包拟定的重要程度/区域影响字段。因此：

1. 已确认的封路等重要事项本来就在已有公共通知链路内，不需要另建消息系统。
2. 若实现本文件的“局部普通施工只定向提醒”，需要同学新增审核和分发逻辑并同步管理员界面；仅修改 AI 提示词或通知页面文案无效。
3. 必须保留旧接口兼容；旧版本传来未知重要性时，不把未核实普通上报直接升级全员。新的审核界面显式确认 importance/impact_scope。
4. 新界面和迁移未一起上线前，继续说明旧链路仍按原公共类别全员分发，不宣称细分规则已生效。

## 少打扰、更新与去重

- 只有筛选后的消息写入 `notifications`；不先全量塞入消息中心再靠前端隐藏。
- 每个用户、同一来源和同一有意义版本只发一次。改标点、重复审核、Worker 重试、并发领取不能变成新提醒。
- 延期、扩大封闭范围、恢复通行等有实际影响的变化可再次提醒；优先对原收件人及新增受影响人发送，解释“发生了什么变化”。只有相关历史/当前影响者收到恢复消息，避免给新注册无关用户补发旧结束通知。
- 结束/过期后停止后续催办，保留历史记录和正确的已结束状态；撤回错误信息时给已有收件人更正，不再向新用户分发原错误内容。
- 多条同源消息聚合为一条前台提示；首次连接和翻页不补弹旧消息，账号切换重建基线。保留数据库微秒时间和延迟到达消息的判断。
- 免打扰只抑制前台横幅，不丢失消息中心记录。重要通知是否突破免打扰由 `important_bypass_quiet` 控制；默认 true，用户可改。任何设置都不启用厂商推送。
- 推荐反馈与屏蔽只影响普通推荐；重大公共通知不因兴趣低、没收藏地点而被吞掉。

## 通知 context 拟定扩展

```json
{
  "delivery": "in-app",
  "policy_version": "butler-v1",
  "cause": "important_campus_event",
  "source": {"type": "event", "id": "00000000-0000-4000-8000-000000000001", "revision": "2"},
  "evidence": [{"type": "manager_confirmed", "text": "主要通行道路已确认封闭"}],
  "next_action": "查看封闭区域和可确认的通行说明"
}
```

这是拟定结构；id 为合成值。不得放入他人联系方式、私人路线原文或用户敏感资料。reason 使用可解释的短句，点击仍跳转现有地点、事项或消息详情。前端动作白名单由代码映射，不执行模型返回的任意 URL/脚本。
