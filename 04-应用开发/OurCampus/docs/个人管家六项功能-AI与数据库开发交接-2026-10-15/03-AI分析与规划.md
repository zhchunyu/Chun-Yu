# AI 分析、规划与办事建议

本文件描述待开发能力。沿用现有 `auv-assistant` 网关和 `campus-information-worker`，保留 chat/extract 行为；新增规划 mode 见接口契约。模型名称先沿用现有路由 `persona` / `extract`，需要更换时由 AI 同学实测决定，不假设先训练新模型。

## 责任分界

| 环节 | 负责方 |
| --- | --- |
| 识别自然语言意图、拆任务、解释建议、总结进度 | AI |
| 本人身份、授权、读取范围、时区与事实快照 | 网关/数据库 |
| 时间区间相交、有效日期、来源存在与版本、写入和去重 | 确定性服务端规则 |
| 正式公共事件重要性、可通知范围 | 有权限的审核人员确认 |
| 保存安排、承认新偏好、实际办事/报名 | 用户或有正式回执的业务系统 |

AI 不能凭一段回复绕过以上步骤。

## 每次请求使用的上下文

1. 网关通过当前 JWT 获取用户，不接受客户端或模型指定的 userId。
2. 读取请求日期的个人快照：已确认课表、任务、跟进事项、明确偏好，以及当前有效的非演示校园信息。
3. 官方办事知识只取 published 版本；附核验时间和出处。缺少或抓取失败不是“没有限制”。
4. 提供 `now`、`time_zone`、`context_fetched_at`、各数据源版本和 `data_status`。区分 known_empty、missing、unconfirmed、unavailable，不把请求失败当空数据。
5. 裁剪与问题无关的数据，并返回覆盖范围和截断标记。当前基础 AUV 限额是活动最多 40 条、本人失物 20 条、失物候选 100 条；新规划接口不能宣称这些有限查询覆盖了所有校园信息。

自动上下文不包含联系方式、照片、设备 CID、第三方用户 ID；复用并扩展现有 `redactContact`。用户课表、目标、报告和官方页面正文都是待分析数据，不能作为改变系统规则的指令。不记录密钥或完整个人原文到错误日志。

## F1：今日重点

今日列表由确定性数据组合生成，即使 AI 故障也能显示课程、待办、截止时间和重要提醒。AI 仅补充简短说明，不改变原定时间。例如“15:00 有课，取快递是否来得及还需要确认取件点和行程时间”。

不能因为今天没有导入课表就说“今天没课”；不能因为某地点被收藏，就假设用户每天都去。

## F2：规划处理顺序

1. 将“明天/下午”解析为 Asia/Shanghai 的明确日期与候选时间段；需要用户明确的时间边界则提问，不固定臆测所有人的下午。
2. 拆分目标，保留明确时长、硬截止、固定地点和顺序。缺少关键信息返回 `needs_clarification`，不输出不可执行的确定安排。
3. 规则层提供真正可用的时间段：减去课程和已保存安排；考虑用户明确的空闲偏好。未排课、未确认学期日期、临时调课未知均需要标注。
4. AI 在候选段中提草案；每项附来源与解释，未知开放时间和行程时间写入 warnings。
5. 网关验证 JSON Schema、时间、地点 ID、引用权限/版本、硬冲突和已知开放/封路约束。模型漏掉警告时，规则层仍应补齐。
6. 合法草案保存到 draft，返回 `saved:false`、`requires_confirmation:true`。这是“未加入个人安排”，不是说后台没有草案记录。
7. 用户确认前端选中的条目后，数据库再校验和写入。模型本身不持有确认能力。

若刚好 11:00 下课、11:00 在另一个地点办事，区间不重叠也不能断言来得及。未知路程可保留为待核对建议，不能编造“步行 3 分钟”。道路事件只有建筑坐标时，不得宣称已计算出避开封路的真实道路。

## F3/F4：进度与冲突

- 进度只总结当前实际源状态，明确“用户标记”和“官方/后台回执”。
- 失物：继续使用原文特征提取＋现有保守候选规则。类型/主色冲突、本人发布、已完成和不合时间的候选排除；输出“可能相关，待核对”，不认定物主。
- 截止/冲突：服务端规则先产出原因，模型只解释并给 1–2 个可选调整。没有截止日期不猜截止日期；没有材料要求不猜缺件。
- 长期无进展：提示查看原记录或联系处理方，不伪装成后台已经催办。

## F5：校园办事

检索对象是经维护的 `campus_service_guides`，按 service_key/关键词匹配，优先当前 published 版本。材料、费用、受理时段等每一项必须能对应到来源字段；模型推测不得进入“必需材料”。

当前已有的官方入口可复用，例如 `campus-card` 的校园卡指南、`network-repair` 的网络报修指南；链接快照在 reference/current 的服务目录。**本包没有重新核验页面中的具体办事细则。**同学上线前需实际核验、记录来源和时间。

遇到“校园卡丢了”：可识别办事主题、提供官方指南和待核对清单。只有拿到已核实的流程后，才显示确定的挂失/补办步骤、材料和地点。实际挂失、缴费、提交申请仍在官方系统由用户操作。

## F6：偏好与反馈

把明确目标、收藏、兴趣与可用时间用于排序。反馈“少推荐这类”只影响普通内容，不自动推断敏感身份、健康、经济状况等。模型从对话总结出的偏好以候选形式展示，用户确认后才能进入长期上下文。

偏好删除后，当前快照、后续提示词和衍生推荐缓存都不再使用；不要把整段聊天历史当长期记忆的替代实现。

## 失败处理与资源边界

| 情况 | 对前端返回 |
| --- | --- |
| 未登录/无权引用 | 401/403，结构化错误；不向模型发送私人信息 |
| 未确认课表日期或目标不明确 | 正常 plan 响应，status=needs_clarification、questions 非空；不生成可确认草案 |
| 上游超时、非 JSON、Schema 不通过 | 502/504，保留用户输入；不得显示保存成功 |
| 数据源部分不可用 | 标明 unavailable；关键约束缺失时只澄清或退回手工待办，不能自动安排 |
| 引用过期、课表/任务刚被修改 | 409 stale_context，请求重新规划 |
| 模型不可用 | 今日原数据和手工待办可用；仅在确有规则降级实现时标注 rules，不冒充 AI 已成功 |

继续使用现有上游 HTTPS 和服务器 Secret；首版输入沿用 text 最多 1000 字。新 mode 的上下文大小、超时和每账号限流需要 AI 同学联调后在发布配置中明确回传；不能让客户端无限放大 payload。推荐与提醒使用增量事件/定时任务，不给每个用户每几秒调用一次模型。
