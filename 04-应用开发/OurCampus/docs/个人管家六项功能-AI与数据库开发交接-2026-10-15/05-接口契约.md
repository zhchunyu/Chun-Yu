## 当前已有接口

- AI：开发环境 `/api/auv-assistant`；正式环境按现有配置使用网关或 `/functions/v1/auv-assistant`。现只接受 `mode=chat/extract`，text 为 1–1000 字。
- 请求字段：`text,mode,locationId,history,favoriteLocationIds`；当前返回仍以 `kind,text,locations,generated_by` 为主。
- 本人通知偏好：`campus_save_notification_preferences(p_preferences jsonb)`，读取 `campus_notification_preferences`。不要换名字或增加前端 userId 来决定归属。
- 本人上报状态：`campus_set_report_status(p_id uuid,p_status text)`，继续负责原始寻物/报修的结束。

## 拟新增 AI 请求

沿用同一认证网关，增加 mode=plan：

```json
{
  "mode": "plan",
  "text": "明天下午找两小时复习高数",
  "date": "2026-10-16",
  "timeZone": "Asia/Shanghai",
  "clientRequestId": "10000000-0000-4000-8000-000000000001"
}
```

date 是用户选定/确认日期；文本日期和 date 不一致时返回 invalid_date 或澄清，不默默选一个。网关返回明确的规划结果；不得用 chat 文本冒充已经保存的任务。

认证沿用当前 JWT；客户端不发送 service role、模型密钥或 userId。模型只能生成内容部分；服务端生成 plan_id、快照 token、时间戳和保存状态，验证完后再返回。重复 clientRequestId＋同一正文返回同一草案，正文不同报 idempotency_conflict。

## 拟新增 RPC 目录

所有写入参数均不含 user_id。`p_client_request_id` 为一次用户操作固定 UUID；网络重试复用。`p_expected_version` 指行版本，首建为 0。参数和类型以 JSON 契约为准。

| RPC | 用途 | 关键响应 |
| --- | --- | --- |
| campus_butler_snapshot | 读取指定日的本人快照 | now、date、time_zone、data_status、timetable、agenda、matters、relevant_events、preferences、snapshot_token |
| campus_save_timetable | 主动同步当前课表和可选课程地点映射 | timetable、row_version |
| campus_save_butler_preferences | 保存补充偏好；原收藏/兴趣仍走旧 RPC | preferences、row_version |
| campus_upsert_personal_task | 手工新增/编辑/完成个人待办 | task、row_version、conflicts |
| campus_confirm_plan | 确认选中的草案条目，允许用户编辑时间等受控字段 | plan_id、saved=true、task_ids、row_version |
| campus_start_matter | 跟进本人报告/活动/官方指南 | matter、row_version |
| campus_set_matter_state | 停止/恢复/标记个人事项完成 | matter、row_version |
| campus_set_matter_step | 勾选本人办事步骤 | matter、row_version |
| campus_record_recommendation_feedback | 记录有用/不感兴趣/少推荐 | feedback_id、row_version |
| campus_delete_recommendation_feedback | 删除本人反馈及其个性化用途 | deleted=true |

读取快照不得只返回一个含糊的 success。`data_status` 中分别标记 timetable/tasks/matters/events/guides/preferences 为 available/missing/unconfirmed/unavailable，并附 `coverage`（例如事件日期范围、分页截断）和 `context_fetched_at`。known empty 用 available＋空数组，不能与 missing 混用。

## 规划确认事务

参数 `p_plan_id`、`p_items`（用户选中/编辑条目）、`p_expected_snapshot_token`、`p_client_request_id`。

`p_items` 每项仅允许 `draft_item_id,title,start_at,end_at,due_at,location_id`；source、用户归属、优先级和 reason 从服务端保存的草案取，不接受客户端改写。空数组不执行保存；重复 draft_item_id 拒绝。新增与草案无关的项目走手工待办接口。

事务依次验证：属于本人且未过期 → 选中项确在草案里 → 关键版本仍一致 → 时间/地点/引用有效 → 与已确认课程和任务不冲突 → 全部插入 → 标记草案已确认。对多设备同一账号确认同一草案，最多产生一组任务。已确认草案使用不同请求号再次确认也只能返回原结果。

成功响应示例：

```json
{
  "schema_version": 1,
  "plan_id": "20000000-0000-4000-8000-000000000001",
  "saved": true,
  "task_ids": ["30000000-0000-4000-8000-000000000001"],
  "row_version": 2
}
```

## 状态约定

- 任务：pending → done/cancelled；用户可显式重新打开，重新检查提醒，不复发已处理旧通知。
- 草案：draft → confirmed/discarded/expired；confirmed 不允许重新写一遍。
- 事项：tracking/waiting → done/stopped；resume 从 stopped 恢复时需确认原来源仍有效。
- 上报状态沿用原 submitted/analyzed/published/resolved/withdrawn/rejected，不能直接把处理中的 repair 改成不存在的官方状态。

## 统一错误约定

AI 网关返回非 2xx：`{"error":{"code":"stale_context","message":"课表或任务已变化，请重新生成安排。","details":{}}}`。RPC 由后台提供稳定 SQLSTATE 与业务 code 的映射，避免前端依赖数据库中文报错文本；下表 HTTP 值指网关/适配层映射，不强行改变 PostgREST 固有行为。

| code | 建议 HTTP | 前端动作 |
| --- | --- | --- |
| unauthenticated / forbidden | 401 / 403 | 登录或提示权限，不重试写入其他账号 |
| invalid_input / invalid_date / invalid_reference | 400 | 保留输入，定位待改字段 |
| version_conflict / stale_context | 409 | 刷新并展示变化，不自动覆盖 |
| schedule_conflict | 409 | 展示冲突对象，等待用户改时间 |
| draft_expired / invalid_state | 409 | 重新规划或刷新源记录 |
| idempotency_conflict | 409 | 同一请求号正文不同，停止重放 |
| rate_limited | 429 | 展示可重试时间，禁用连续提交 |
| ai_unavailable / invalid_ai_result | 502 | 保留输入，今日原数据可继续查看 |
| upstream_timeout | 504 | 允许原请求号安全重试，不显示已保存 |
| service_unavailable | 503 | 明确未升级/暂不可用，不清空旧数据 |

错误 details 只返回本人有权查看的信息，不回传密钥、其他人标题或私人数据。
