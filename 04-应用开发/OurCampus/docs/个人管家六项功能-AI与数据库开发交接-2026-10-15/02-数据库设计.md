# 数据库设计与后台约束

**这是拟定数据字典，不是已经执行的 SQL。**开发同学据此编写增量迁移，先在测试环境验证，再按项目现有发布流程部署。新迁移编号需检查仓库后确定，不占用或覆盖已有 14 号文件。

## 复用现有数据

| 现有来源 | 用法与注意点 |
| --- | --- |
| `auth.users`、`profiles`、`campus_private.user_roles` | 沿用账号和管理员权限；前端传来的 userId、模型输出都不能决定身份 |
| `campus_locations` | 继续使用现有文本地点 ID 和别名；教室原文不等于已定位建筑 |
| `campus_events` | 读取有效、非演示的活动和公共事件；保留 `source`、`information_scope`、`information_revision` |
| `campus_reports` | 当前失物/招领、报修和反馈主数据；按本人 author_id 关联个人事项 |
| `notifications` | 复用 `priority`、`reason`、`context`、`dedupe_key` 和已读状态，不建第二个消息中心 |
| `campus_notification_preferences` | 14 号已有收藏、兴趣、失物匹配开关；作为这些字段的唯一账号级来源 |
| 本机课表 `campus-twin-timetable-v1:<userId或guest>` | 当前只存 localStorage；需要新增账号同步，不能假设云端已有 |

旧 `lost_found_posts` 仍存在于早期建表中。当前 App 的云端社区失物由 `campus_reports` 转换；新功能以当前链路为准，不往两个表重复写同一条信息。

## 拟新增表

所有本人数据表使用 `user_id uuid` 关联 Auth；通用字段 `created_at/updated_at timestamptz`、`row_version bigint`。时间点统一存 `timestamptz`，本地日期使用显式 `Asia/Shanghai` 转换；不能使用服务器默认时区解释“明天”。

### 1. `campus_timetables`：本人当前课表

一人一条当前课表，`user_id` 为主键。保存 `payload jsonb`、`row_version`。payload 兼容当前 `version:1`、`semester`、`termStart`、`dateConfirmed`、`courses[]`、`unscheduled[]`。

课程保留 `id/name/teacher/classroom/weekday/weeks/periods/startTime/endTime`；建筑映射另存可选 `course_locations jsonb`，每项是 `{course_id, location_id, confirmed_by_user}`，避免改坏现有导入格式。无法唯一映射时为 null，不让模型猜楼。

上传需要用户主动选择账号并核对；游客课表、其他账号和另一设备旧数据不自动覆盖。版本冲突时返回冲突信息，由用户选择合并/保留，不做静默最后写入覆盖。服务端校验与当前 `validTimetable` 至少同等严格，另校验真实日期和周一锚点；未确认日期允许存储，但不能据此排实际日期日程。

### 2. `campus_butler_preferences`：补充的个人偏好

字段：`user_id` 主键、`time_zone`（首版仅 `Asia/Shanghai`）、`goals jsonb`、`free_windows jsonb`、`quiet_enabled boolean`、`quiet_start time`、`quiet_end time`、`important_bypass_quiet boolean`、`blocked_topics text[]`、`row_version`。

- `goals`：最多 20 条 `{id,title,source:'user_confirmed',confirmed_at}`，标题最多 100 字。
- `free_windows`：最多 28 条 `{weekday:1..7,start:'HH:mm',end:'HH:mm'}`，start < end；它是用户偏好，不能覆盖已知课程。
- 首次默认：免打扰关闭；`important_bypass_quiet=true`。用户开启免打扰后生效，允许跨午夜；start=end 视为无效配置并拒绝保存。
- `blocked_topics`：最多 20 个，单项 2–20 字；只过滤普通个性推荐。
- 收藏/兴趣沿用原偏好表和 `campus_save_notification_preferences`，不在此表复制。
- 用户删除目标/时间偏好用明确的空数组替换；模型不得直接写此表。反馈删除见第 7 表。

### 3. `campus_personal_tasks`：已确认的个人待办

字段：`id uuid`、`user_id`、`client_id uuid`、`title text`（1–100 字）、`kind`（study/life/activity/service/other）、`status`（pending/done/cancelled）、`start_at/end_at/due_at timestamptz null`、`location_id text null`、`source_type/source_id/source_version`、`plan_id uuid null`、`row_version`。

约束：起止同时为空或同时存在且 start < end；独立截止日期可空；source 类型 user_request/event/service_guide/task。引用必须可读且与当前用户权限相符；禁止跨账号引用私人任务。`unique(user_id,client_id)` 防重复提交；索引 `(user_id,status,start_at)`、`(user_id,status,due_at)`。

不能在 SQL 中简单禁止所有相交区间：用户可能保留已知冲突的手工待办。AI 规划确认接口对与课程/待办的硬冲突返回 `schedule_conflict`，提供冲突详情；手工输入若存在冲突，需要显式 `allow_conflict=true`，并记录用户确认。

### 4. `campus_plan_drafts`：待确认规划

字段：`id uuid`、`user_id`、`client_request_id uuid`、`result jsonb`（Schema 中的完整响应）、`snapshot_token text`、`status`（draft/confirmed/discarded/expired）、`expires_at`、`confirmed_task_ids uuid[]`、`row_version`。

草案 24 小时内可确认，超过时间返回 `draft_expired`；原输入非必要不另存。`snapshot_token` 为服务端签发/保存的不可伪造标识，绑定本人、课表/任务/偏好版本及引用事件和指南版本。关键版本变化需重新校验并返回 `stale_context`，不能只相信客户端说“没有冲突”。唯一 `(user_id,client_request_id)`。

### 5. `campus_personal_matters`：事项与办事进度

字段：`id uuid`、`user_id`、`source_type`（report/event/service_guide）、`source_id uuid`、`source_version text null`、`kind`（lost/repair/activity/service）、`state`（tracking/waiting/done/stopped）、`steps jsonb`、`user_reported_state text null`、`next_follow_up_at timestamptz null`、`last_source_version text null`、`row_version`。

同一用户同一来源只保留一个当前跟进：`unique(user_id,source_type,source_id)`。步骤 `{step_id,title,done,done_at,evidence_source}`，用户勾选为 `evidence_source='user_reported'`；官方回执单独保存来源引用，不把勾选当官方确认。完成/停止时撤销未执行跟进任务。

原始寻物/报修状态与个人跟进状态分开。标记“已找回”走现有本人上报状态 RPC，再结束相关跟进；“停止跟进”不改变原上报。不能只看列表缓存决定一条已完成事项仍需提醒。

### 6. `campus_service_guides`：经维护的官方办事知识

字段：`id uuid`、`service_key text`（对应现有目录 id）、`version text`、`title`、`applies_to`、`steps jsonb`、`materials jsonb`、`location_id text null`、`official_url`、`source_urls text[]`、`verified_at timestamptz null`、`status`（draft/published/retired）。唯一 `(service_key,version)`。

只允许授权维护人员发布。每条步骤/材料保留 `source_url` 与可定位的来源摘录/段落标记；未核实细节标为 unknown，不能出现在必需材料列表。已发布指南不可原地改版本；新版本发布后旧版本保留以解释正在办理的事项，必要时提示用户核对变化。

### 7. `campus_recommendation_feedback`

字段：`id uuid`、`user_id`、`client_id uuid`、`target_type`（notification/event/plan）、`target_id uuid`、`feedback`（useful/not_useful/less_like_this）、`reason text`（最多 200 字）、`deleted_at timestamptz null`、`row_version`。唯一 `(user_id,client_id)`。

只能反馈自己收到/可读的对象；目标不存在、跨账号或未授权则拒绝。删除接口对本人记录清除 reason 和用于推荐的衍生标签，后续查询必须排除已删记录；如保留最小技术审计，不保留已删除的个性偏好原文。推荐缓存一并失效。

### 8. `campus_private.butler_jobs`：跟进与截止提醒任务

单独队列，避免直接往现有只支持 analysis/push 的 `information_jobs.kind` 塞新值。字段至少有 id、user_id、purpose（deadline/follow_up）、source_type/source_id/source_revision、available_at、status、attempts、lease_until、claim_token、last_error。

唯一 `(user_id,purpose,source_type,source_id,source_revision)`；行锁领取并绑定租约令牌，有限重试。执行前重读源记录、本人偏好和完成状态；事务中写 notifications 并标记任务完成。重要性升级/撤回时重算，不能重复通知。

## 公共事件补充字段（待增量实现）

`campus_events` 拟增加 `importance`（ordinary/important）、`importance_reason`、`importance_confirmed_by`、`importance_confirmed_at`、`impact_scope`（all/area/route）、`affected_location_ids text[]`、`route_evidence jsonb`。公开读模型不得暴露私人路线或管理员私人信息。

`heat_level` 是现有热度，不能直接当“重大事件”依据。新字段由授权审核确定，AI 只能提交候选。未来生效的封路需支持真实 start_at；当前审核函数非活动使用 now()，需要保持旧调用兼容地新增审核入口或迁移参数，不直接破坏原签名。

## 权限、事务和清理

- 本人表 RLS：`auth.uid()=user_id`；普通用户和管理员都不因公共审核权限而获得其他人的课表/偏好。Service Role 仅在后台使用，且后台查询仍显式限定本人。
- 写入走限定字段的 RPC；撤销 public/anon 默认执行权限；security definer 固定安全 search_path，并在函数内检查身份和对象归属。
- 确认规划：锁草案＋校验版本与源对象＋重新算冲突＋插入所有选中任务＋更新草案，在一个事务完成；任何一项失败则全部回滚。相同 client_request_id 重试返回同一结果，参数不同则报 idempotency_conflict。
- 多设备修改使用 expected_version；拒绝旧版本覆盖。不可由客户端回传 user_id 改变归属。
- 草案到期后取消确认能力，清理过期敏感结果；账号删除按外键清理私人数据。清理任务也应可重试。
- 迁移重复执行、失败回滚、权限、并发确认、队列重试必须在测试环境验证。不要在已有业务库重跑 01/02 或导入演示种子。
