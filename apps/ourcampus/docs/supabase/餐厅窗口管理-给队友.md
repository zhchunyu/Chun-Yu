# 餐厅窗口管理启用说明

1. 在现有 Supabase 项目的 SQL Editor 执行旁边的 `08-restaurant-windows.sql` 一次。已有账号和聊天表保持不变，不需要重新建库。重复执行会提示表已存在并回滚。
2. 确认哪一个注册邮箱是管理员，在 SQL 文件末尾找到管理员设置语句，替换真实邮箱后单独执行。App 读取服务器角色，不提供自行升级权限的入口。
3. 管理员退出后重新登录，打开「大厅 → 餐厅评价 → 禾香等餐厅 → 添加窗口」。编号可以包含楼层，如「二层 03」。同一家餐厅编号不可重复，不同餐厅可使用同样编号。
4. 打开已添加窗口的详情，点击「删除这个窗口」，确认后删除。普通同学没有增删入口，服务器 RLS 也禁止其增删。
5. 另一台手机重新打开对应餐厅即可读取名单。窗口存服务器；评价目前仍存本机，本次未改为多人评价系统。

建表后的四家餐厅初始没有窗口，方便直接录入真实名单。未建表时 App 显示标注清楚的示例窗口，并禁用管理员新增操作；示例不会提交到服务器。删除窗口不会清除设备上的旧评价，但旧评价不会计入当前窗口列表。

## 服务端检查

- 管理员可添加、删除；学生及未登录用户请求 insert/delete 应被权限拒绝。
- 所有人可读取名单；跨设备打开同一家餐厅看到相同窗口。
- 创建同餐厅重复编号应失败，四家餐厅数据应隔离。
- 删除最后一个窗口后，应显示「还没有收录窗口」，不能写评价。

前端及 APK 已包含接口调用；只有 Publishable key 无法远程执行建表，需要项目管理者执行上面的 SQL。

权限实现参考：[Supabase RLS 文档](https://supabase.com/docs/guides/database/postgres/row-level-security)。
