## 部署

1. 核对 `public.restaurant_windows` 是否存在。如果还没有，先执行 `reference/08-restaurant-windows.sql`；已有表不要重跑 CREATE TABLE。
2. 执行 `database/11-restaurant-reviews.sql`，创建真实评价表、统计 view、鉴权提交 / 撤回 RPC 和实时订阅。
3. 执行 `database/12-guyuan-real-windows.sql`，增加菜单、楼层、编号是否核实字段并导入六个真实窗口。
4. SQL 避免覆盖已有同名窗口或编号；若导入数量少于六个，请核对冲突记录并手动合并，保留已有窗口 UUID 与评价关联。
5. 客户端重新打开“大厅 → 餐厅评价 → 谷园餐厅”。未部署时客户端提供这六条现场资料预览；服务器真实名单加载后，以管理员名单为准。删除所有窗口后可再次见到预览，但预览不可云端评价，需要重新导入或管理员新增。

## 数据与功能

- 每窗口独立一至五星、短评、消费金额和最多三个标签；可按推荐 / 吐槽筛选及分数排序。
- `restaurant_reviews` 保存真实用户 UUID、昵称快照、窗口 ID、评分和评论。游客可读公开评价，登录后才能提交；用户不能伪造作者、昵称或管理员身份。
- 每账号每窗口只有一条有效评价，避免反复打分影响口碑。可撤回本人评价，再发布新的体验；管理员可撤回不当内容。每分钟最多五次新提交。
- 统计 view `restaurant_review_stats` 只统计服务器有效评价：数量、平均星级、价格参考和推荐比例，不含本机历史或示例。
- 详情按最近 50 条分页，继续加载更早记录；排序 / 推荐吐槽筛选作用于当前已加载评论，评分统计始终来自全部云端记录。
- 30 秒轮询、前台恢复与 Realtime 订阅用于更新；SQL 安装前 UI 清楚标注“本机评价”，不自动上传历史评论。
- 管理员添加 / 删除窗口沿用已有服务器权限。删除窗口将级联删除该窗口云端评价，手机会二次确认；如需关闭营业但保留评价，先不要删除，后续增加停用字段。
- 菜单 `menu` 是 `[菜名,价格]` 数组，`floor` 是楼层，`number_verified` 是否真实编号；管理员可在 Dashboard 修正现场资料，客户端使用服务器提供的数据。

## 联调

甲登录写评价，乙打开同窗口能读到；平均评分和数量变化。乙不能撤回甲的评论。甲撤回后公开列表和统计更新。游客只读；未部署或网络失败保留表单错误，不伪装服务器保存成功。不新增示例五星评价或虚构营业信息。

接口：`campus_submit_restaurant_review(p_client_id,p_window_id,p_restaurant_id,p_rating,p_content,p_tags,p_price)` 返回评价 UUID；`campus_withdraw_restaurant_review(p_id)` 撤回。重试同一草稿复用 p_client_id；内容变更需新表单。
