# 个推与手机端配置

## 当前状态

1.8 APK 已加入个推 Android SDK、通知权限、设备绑定和点击消息跳转。当前还没有团队的个推 AppID，默认不初始化推送，也不能收到真实系统通知。站内通知由 Supabase 保存，和个推分开运行。

## 创建应用

在个推开发者控制台创建 Android 应用，名称 OurCampus，包名必须是 `cn.edu.sxau.campustwin`。取得同一应用的 AppID、AppKey、MasterSecret。控制台要求哪些审核材料、配额或收费以当前账号显示为准。

| 参数 | 保存在哪里 |
| --- | --- |
| AppID | 服务器 Secret `GETUI_APP_ID`；客户端 `android/push.local.properties` 的 `GETUI_APP_ID` |
| AppKey | 服务器 Secret `GETUI_APP_KEY` |
| MasterSecret | 服务器 Secret `GETUI_MASTER_SECRET`，禁止进 APK、网页和共享仓库 |

Android 工程 Gradle 占位符内部名称是 `GETUI_APPID`，代码自动从本机 `GETUI_APP_ID` 字段读取。不需要改模板占位符，也不要往 manifest 放服务器密钥。

## 手机端重新打包

在客户端工程运行，填入公开 AppID 后构建：

```powershell
Copy-Item android/push.example.properties android/push.local.properties
# 编辑新文件，填写 GETUI_APP_ID=控制台公开AppID
npm run android:apk
```

复用当前 JDK 21 / Android SDK 36。应用 ID 不变，更新时递增 versionCode，并使用原签名。仅改服务器 Secrets 不能让当前空 AppID 安装包自动具备推送能力，必须重新构建并安装更新包。

用户在软件消息中心阅读说明、勾选同意、点击“开启系统通知”；Android 13+ 申请通知权限。CID 返回后，通过鉴权 RPC 登记为当前账号的设备。拒绝通知时可进入系统设置开启；关闭或退出账号会停用当前设备。其他设备不受影响。

## 厂商离线通道

基础个推通道适合应用进程和连接仍可用时接收。锁屏、后台、系统清理等场景需进一步配置实际手机品牌的厂商通道，不能把“有个推 AppID”等同于“所有手机在任何状态都能收到”。

服务器已发送 `push_channel.android.ups.notification` 参数，但本版尚未集成华为、荣耀、小米、OPPO、vivo 等独立厂商 SDK 与应用参数。队友应：

1. 确定演示 / 试用手机品牌，优先完成对应厂商应用申请、包名和签名核对。
2. 在个推后台启用对应厂商服务，按官方集成流程补 SDK 和客户端公开应用参数。
3. 厂商服务器私密参数只保存平台后台或服务器，不能放共享文件。
4. 对前台、后台、锁屏、系统清理和用户强制停止分别实际检查。强制停止和系统策略仍可能阻断通知；站内消息作为保底。

后续需要负责人提供 AppID 和目标手机品牌，客户端负责人继续补厂商 SDK 并重打包。不要用后台 GPS 或定时保活代替厂商通知通道。

## 通知与隐私

- 通道 ID 固定 `campus_public`。客户端包含透明白色通知图标；后端 click intent 只携带通知 UUID，不携带账号令牌、联系方式或模型密钥。
- 公共校园通知可展示审核后的简短标题和说明；失物等定向通知只提示有更新，详细联系方式需要登录后读取。
- 自建推送接口只上报安装 UUID、CID 和启用状态，不发送课表、聊天历史或应用定位坐标。第三方 SDK 数据处理按其隐私政策核对并纳入正式应用隐私说明。
- `accepted` 回执仅代表服务商受理，不代表手机实际展示；控制台到达 / 点击统计与真实手机结果需分别查看。
