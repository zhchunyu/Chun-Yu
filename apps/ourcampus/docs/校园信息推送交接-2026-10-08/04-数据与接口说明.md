# 数据、权限与接口

## 流程

用户主动发布 → `campus_submit_report` → `campus_reports` → 私有 analysis 任务 → worker 调用 AUV → 保存草稿与候选关联。

公共信息 → manager 调用 `campus_review_report` → `campus_events` → 每用户 `notifications` → 私有 push 任务 → 已启用设备 CID → 个推受理回执。

失物 → 同地点、相反类型、七天内、不同作者、特征关键词匹配 → 两位作者的可能匹配通知。订阅 lost / found 的账号可收到对应新信息提醒。地点和时间条件严格，不能认定物品归属。

## 表

| 表 | 主要内容 / 权限 |
| --- | --- |
| `campus_reports` | UUID、真实作者、幂等 client_id、类型、标题说明、地点、原始 details、来源消息、状态、AI 草稿、关联 ID；作者 / manager 可读自己的或待审内容，登录用户可读已发布及有效失物信息 |
| `campus_subscriptions` | 当前用户地点 / 类别订阅；空字符串代表全部。仅本人增删查询 |
| `campus_push_devices` | 安装 UUID、CID、当前账号、enabled、updated_at；仅本人可读，鉴权 RPC 管理 |
| `campus_private.information_jobs` | analysis / push、目标 UUID、领取令牌、租约、次数、重试时间和安全错误码；客户端不可读写 |
| `campus_push_receipts` | 通知 / 设备组合唯一、provider accepted、时间；仅后台 |
| `notifications`（已有） | recipient_id、标题说明、相关对象、read_at；增量添加 dedupe_key；只读 / 标记自己的通知 |
| `campus_events`（已有） | 官方审核事件；增量信息类型、全员 / 订阅范围和 revision；复用原有地点 FK 与可见性规则 |

数据库的新报告不会写入旧 `lost_found_posts` 或 `place_feedback` 表。移动端将其作为云端社区信息读取，旧本机资料单独保留，不要做双表监听导致重复分析。

## 客户端 RPC

| RPC | 参数与结果 |
| --- | --- |
| `campus_submit_report` | p_client_id UUID、p_kind、p_title、p_body、p_location_id、p_details JSON、p_source_message_id；返回报告 UUID。重试使用同一个 UUID；同 UUID 不同内容会报错 |
| `campus_set_report_status` | p_id、p_status withdrawn / resolved；只操作本人；公共官方事件由 manager 结束 |
| `campus_retry_information_report` | p_id；作者或 manager 重排失败分析 |
| `campus_review_report` | p_id、p_publish、p_title、p_summary、p_location_id、p_kind、p_end_at、p_scope、p_event_id；仅 manager；返回官方事件 UUID |
| `campus_close_information_event` | p_id；仅 manager，结束并给对应用户发送更新通知 |
| `campus_register_push_device` | p_installation_id、p_cid；绑定 auth.uid，返回设备 UUID |
| `campus_disable_push_device` | p_installation_id；仅停用本人当前安装 |

订阅通过表 CRUD；notifications 只允许更新 read_at。上述操作必须使用真实 Supabase 会话，不接受客户端提交 author_id、role、recipient_id 或 AI 已确认状态。

报告类型：construction / closure / water-power / crowd / notice / lost / found / repair / feedback。状态：submitted → analyzed → published；可 rejected、withdrawn 或 resolved。AI 失败只影响 analysis_status，不丢原报告。每账号最多每分钟十次新上报，幂等重试不计作新报告。

## 后台接口

`POST https://hkdblizadnkskxslyjyq.supabase.co/functions/v1/campus-information-worker`

请求头 `x-campus-worker-token`，正文 `{}`。返回 processed 与不含原文 / 密钥的结果码。仅调度器或服务器调用，不在前端调用。

后台专用 RPC：`campus_claim_information_jobs`、`campus_finish_information_job`、`campus_complete_information_analysis`、`campus_wake_information_worker`。普通 authenticated / anon 无 EXECUTE 权限。任务一次领取两条、三分钟租约、最多五次尝试；失败按退避时间等待，再由调度补偿。

模型只接收主动上报的标题和说明文本。独立联系方式字段、图片、CID、用户 UUID、课表和登录令牌不传模型。若用户把个人信息直接写进说明，它仍会随说明发送，因此发布页应引导只填事件事实。

## 关联边界

同地点同类型事件仅生成候选；管理员核对后选择关联现有事件，合并会增加 revision 并产生更新通知。AI 不自动修改腾讯道路、发全员广播或确认现场事实。校园封路信息会在地图提示，但未取得道路段的准确对应关系时，不自动改腾讯导航路线。

新窗口评价不自动送 AI、全员广播或改施工订阅。用户可主动提交为校园信息，避免把吐槽误识别为公共事故。
