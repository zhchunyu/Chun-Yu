# CampusTwin 手机端地图优先界面设计

## 目标

把 CampusTwin 手机端整理成地图优先的校园导航界面。参考用户提供的地图应用截图：地图铺满主区域，常用地图控件悬浮显示，底部集中地点分类、搜索和主导航。应用仍使用 CampusTwin 自有地图、地点、校园热点与路线数据。

手机端通过浏览器访问。开发时在电脑 Chrome 的响应式设备视图中使用约 390×840 CSS 像素的竖屏视口，并由 Vite 热更新呈现修改。这个视口的高宽比约为 155:72；CSS 像素模拟的是页面视口，实际显示的毫米尺寸受显示器与系统缩放影响。

## 当前项目背景

- 项目使用 React 与 Vite，已有 2D/3D 校园地图、地点搜索与分类、地点详情、校园热点、路线规划、角色演示和本地设置。
- 地图与交互主要由 `App`、`MapWorkspace`、`MapToolbar`、`MapSearchOverlay`、`LocationDetail` 和 `RouteDock` 组合。移动样式目前仍保留桌面顶部栏、地图覆盖控件和地图最小高度，尚未形成截图式的底部主导航。
- 地点、热点、角色更改和部分偏好保存在当前浏览器；没有账号、服务端数据同步或真实 GPS。

## 导航结构

移动端新增四个主入口，底部导航栏固定在设备安全区之上。桌面端继续沿用现有工作区布局。

### 首页 / 地图

- 地图占满可用页面区域，默认显示现有主地图场景，并保留 2D/3D 切换。
- 地图显示现有地点标记、选中状态、热点和路线；不加入没有数据来源的实时路况或天气图层。
- 右侧浮动控件聚合图层开关、地图视角/缩放控制和模拟位置入口；指南针等地图方向提示保持可见且不遮挡地图关键区域。
- 底部导航上方显示可横向滑动的地点分类快捷入口和搜索框。快捷入口复用现有分类；搜索复用地点、服务与校园热点搜索。
- 点选地图标记或搜索结果后，在底部详情抽屉显示名称、开放状态、人流、活动和关联热点。管理者演示角色仍可从详情编辑地点状态。

### 探索

- 复用现有地点过滤、搜索、分类和地点卡片，展示教学学习、餐饮生活、住宿空间、校园服务、出行节点等类别。
- 提供当前有效校园热点的浏览入口。
- 选中地点后切回地图首页，定位并打开该地点详情；搜索词和筛选结果在切换过程中保持一致。
- 无匹配项时显示现有空状态和清除筛选操作。

### 行程

- 提供起点、终点选择和现有路线模式：最短、无障碍、避开施工、避雨、夜间安全。
- 默认起点使用已选的模拟位置；没有模拟位置时沿用当前演示默认起点。界面明确位置为模拟数据，不标作真实 GPS。
- 展示现有路线长度、预计时长、路线图层状态和分段指引；允许调整起终点、切换模式、交换起终点和清除路线。
- 遇到地点关闭或路线不可用时，展示现有原因与更换路线的操作。

### 我的

- 展示访客、学生、管理者三种演示角色切换，以及地图显示偏好和默认路线模式。
- 管理者可访问热点发布、更新和关闭入口，并保留现有撤销与恢复演示数据能力。
- 明确标注本地演示数据；不呈现账号登录、云端个人资料或跨设备同步状态。

## 界面行为与布局

- 借鉴参考图的视觉层级：轻量地图底图作为背景，圆角浅色浮层承载搜索、分类和导航，地图操作控件沿侧边收纳；保留 CampusTwin 现有视觉主题，不复用参考图中的品牌、地图内容或专属素材。
- 手机优先适配 360–430 CSS 像素宽的竖屏。页面使用动态视口高度并适配刘海与底部安全区；主要触控控件保持足够触控面积。
- 顶部品牌栏在手机地图主屏收起；校园名称、数据状态等次要信息放入轻量地图状态提示或“我的”页面，避免持续占用地图高度。
- 搜索结果、地点详情、路线和管理工具按需呈现为底部抽屉或可滚动面板；同一时刻只让当前任务的面板占据主要底部空间。
- 地图、浮动控件、分类条、搜索和底部导航之间不得互相遮挡。小屏下分类条允许横向滚动，面板内容允许自身滚动。
- 保持现有桌面端顶部栏和地图工作区，不因手机导航改写桌面信息架构。

## 架构与数据流

- 保留现有 React 单页应用、校园 reducer、领域函数、地图数据源和本地存储；不增加运行时依赖或后端。
- 新增移动端底部导航与探索/行程/我的视图容器；地图首页继续组合现有地图、搜索、图层、地点详情和路线组件。
- 主导航选中项属于界面状态。搜索、地点、角色、地图场景、热点和路线继续经现有 reducer 更新，避免在新页面复制一套领域状态。
- 探索页选中地点时派发既有地点选择动作并切回地图；行程页复用既有路线 reducer 与路线算法；我的页面复用角色、设置和管理组件。
- 窄屏布局使用现有 CSS，不改地图数据、道路图、路线算法或地图资源。

## 失败状态

- 复用现有地图加载失败提示及 2D 回退路径；3D 资源加载失败不阻断地点探索和 2D 地图操作。
- 搜索无结果、没有可用路线、地点关闭等情况保留清楚的原因提示与恢复操作。
- 模拟位置不可用时仍允许用户从路线页选择起点；不请求设备 GPS 权限。
- 本地演示数据各自保存在不同浏览器中，手机和电脑之间不会自动同步。

## 不包含

- 天气、实时交通、语音搜索、真实 GPS 定位、账号、云端同步、实时校园数据服务。
- Android/iOS 安装包、PWA 离线能力或地图资源重制。
- 具体静态托管商的选择与网站发布。手机通过公网长期访问需要 HTTPS 托管目标，另行确定。

## 验收标准

1. 在 360×800、390×840 和 430×932 CSS 像素竖屏视口下，地图优先布局无页面横向溢出；主要控件避开设备安全区且互不遮挡。
2. 地图首页可使用地点分类、搜索、2D/3D 切换、图层、地点详情、热点和模拟位置。
3. 探索页可筛选和选择地点；选中地点后回到地图并显示详情。
4. 行程页可选择起终点、切换五种路线模式、查看指引并清除路线；不可用状态有说明。
5. 我的页面可切换演示角色和地图偏好；管理者入口遵守现有角色限制。
6. 桌面端现有工作区布局保持可用；开发时 390×840 手机视口能通过 Vite 热更新查看变化。
7. 在真实手机浏览器中，页面交互适合触控；公网访问以之后选定的 HTTPS 静态托管为准。
8. 页面不把本地演示热点、状态或模拟位置标示为实时服务或真实定位。
