# 校园服务、活动日历、设施报修与个人收藏设计

## 目标

把校园常用信息和地点操作整合进现有手机端原型：可查校园服务、按日期看活动、提交并跟踪设施报修、收藏地点与路线；室内导航仅在真实楼层图和室内路网可用时开放。

## 已确认需求与首版边界

- 校园服务条目包含说明、开放时间、电话和官网。信息以学校官方网页为来源；未找到可核实的信息时显示“暂无官方信息”，不推测时间或联系方式。存在校内地点的条目可直接查看地点详情并规划路线；线上办事大厅只提供官网入口。
- 活动日历复用现有校园动态数据，支持按日筛选活动，并从活动卡片查看地点或规划路线。活动由现有管理员演示工具维护，不伪装成实时校历。
- 设施报修复用地点反馈流程，提供路灯、饮水机、电梯和其他四类；本机保存记录，管理员演示角色可将状态从“待处理”改为“处理中”再改为“已完成”。
- 收藏地点与已保存路线写入现有本机持久化；“我的”页可打开收藏、重新规划路线或删除收藏。
- 当前仓库没有可用的室内楼层图或楼内路网。室内导航入口显示待数据状态，不绘制虚构平面图或路径。获得经确认的数据后再启用楼层选择和楼内路径。
- 登录、跨设备同步、真实报修工单流转及校园系统 API 不在本次范围内。

## 用户流程

### 校园服务

用户在“地点”页搜索或浏览校园服务卡片。卡片显示服务说明、已核实的开放时间和电话、来源链接；支持点击官网、拨号、查看对应地图地点和导航。

### 活动日历

用户选择日期查看当天尚未结束的活动。每条活动显示标题、类型、起止时间和地点；点地点打开校园地图，点导航直接生成从当前位置出发的路线。

### 设施报修

用户从地点详情提交报修类别和情况说明。报修在“我的”页显示当前处理状态；管理员演示角色在审核区推进状态。所有数据只保存在当前浏览器。

### 收藏

用户可在地点详情收藏或取消收藏地点，也可在路线卡片保存路线。“我的”页可以打开地点、重新规划路线，并移除保存记录。

### 室内导航

用户可见室内导航入口和所需数据说明。没有已确认楼层图的建筑不可开始楼内规划；校园室外导航继续使用现有路线实现。

## 数据与组件边界

- `src/data/campusServices.js` 保存服务目录和官方来源字段，位置以现有地点 ID 关联。
- `ExplorePanel` 展示服务目录、活动日历及数据待补齐的室内导航状态。
- `placeFeedback.js` 扩展报修类别与状态；现有报修弹层保持统一提交入口。
- 独立的报修状态面板复用 `placeFeedback` 存储和管理员角色。
- `campusReducer.js` 管理报修状态、收藏地点和保存路线；`appStorage.js` 迁移至新 schema 并为旧数据设置空集合。
- `MePanel` 显示收藏和报修状态；`LocationDetail` 和 `RouteDock` 提供收藏动作。

## 验收标准

1. 服务目录中可以搜索图书馆、餐厅、校医院和线上办事大厅；数据不全时明确显示未核实，已有地点可直达详情或路线。
2. 活动可按日期筛选；地点选择和路线按钮可操作。
3. 用户可提交四类设施报修并看到待处理状态；管理员可以推进到处理中、已完成；刷新后记录仍在。
4. 收藏地点与路线刷新后保留；点击可以重新打开或规划。
5. 室内导航不会显示未经提供的数据或生成假路线；无楼层数据时解释无法使用的原因。
6. 现有项目可通过 `npm run build`。
