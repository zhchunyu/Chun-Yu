# 本校区 2D / 3D 双场景地图设计

## 目标

把 CampusTwin 的地图工作区扩展为两个可切换场景：默认进入本校区 2D 校园平面图，用户可在地图左上角切换到 3D 校园模型。搜索、地点详情、热点、路线、模拟位置和管理员状态由同一套应用状态驱动，不因切换场景而丢失。

## 已确认的产品决策

- 地图是页面主体，右侧功能面板可以收起。
- 2D / 3D 切换放在地图左上角，采用 A 方案。
- 2D 使用本校区官方校园平面图作为底图，并在上面叠加交互图层。
- 默认进入 2D 场景；3D 用于查看校园模型和沉浸式浏览。
- 3D 使用已下载并转换的 `public/assets/campus-extracted.glb`。
- 第一阶段不接真实登录和后端接口，保留现有本地数据源和未来 API 边界。

## 范围与非目标

本次实现包含场景切换、2D 底图显示、地点标记、路线覆盖、当前地点标记、状态颜色、加载与错误状态，以及切换时的状态保持。

本次不包含室内楼层、GPS 真定位、第三方地图瓦片、真实账号权限、后端同步和重新制作 3D 模型。3D 模型的建筑标签与路线坐标通过独立的地图坐标元数据校准，不把校准逻辑写死在 React 组件中。

## 架构

### 工作区编排

`MapWorkspace` 负责通用工具栏、搜索、状态摘要、场景切换和地图来源说明；具体地图渲染交给两个独立组件：

- `Campus2DViewer`：显示官方平面图、地点标记、路线线段和当前位置。
- `Campus3DViewer`：加载 GLB，显示模型、地点标签、路线和第一人称相机。

`MapWorkspace` 只根据 `mapScene` 选择渲染器，不在两个渲染器之间复制搜索、路线和管理员逻辑。

### 应用状态

在现有 reducer 中增加：

```js
mapScene: '2d'
```

新增动作：

```js
{ type: 'SET_MAP_SCENE', scene: '2d' | '3d' }
```

切换场景时保留 `selectedId`、`routePlan`、`currentLocationId`、`query`、`category`、`role` 和事件状态。只有地图渲染层改变。

### 地图配置

`src/data/campusMap.js` 改为描述两个场景的数据源：

```js
{
  campusName,
  defaultScene: '2d',
  scenes: {
    '2d': { imageUrl, imageWidth, imageHeight, sourceUrl },
    '3d': { modelUrl, sourceUrl, modelSize }
  }
}
```

来源信息保留在配置中，用于地图底部说明和后续替换资源，不散落在组件内。

## 坐标与数据流

每个地点和路线节点使用场景独立的显示坐标：

```js
{
  id: 'library',
  mapPosition: {
    '2d': { x: 0.52, y: 0.34 },
    '3d': { x: 0, y: 4, z: -518.4 }
  }
}
```

2D 坐标采用 0 到 1 的归一化比例，底图尺寸变化时仍能正确定位；3D 坐标采用 GLB 世界坐标。路线节点也使用同样的双场景坐标，路线算法仍只返回逻辑节点和距离，渲染器负责投影到当前场景。

如果某个地点暂时没有当前场景坐标，界面显示“该场景点位校准中”，不绘制误导用户的假路线，同时保留地点搜索和详情功能。

## 2D 场景交互

- 底图使用 `object-fit: contain` 放入地图视口，不裁剪官方平面图。
- 地点以状态颜色圆点和短标签显示；点击后复用现有 `LocationDetail`。
- 路线以高对比色折线显示，起点和终点使用不同标记。
- 当前模拟位置使用独立定位标记。
- 支持缩放、拖拽、重置视图；第一版使用 CSS transform 和 pointer events，不新增地图 SDK。
- 右侧详情和工具继续可以收起，不遮挡底图主内容。

## 3D 场景交互

- 继续使用 Three.js `GLTFLoader`；新模型从 `campusMap.scenes['3d'].modelUrl` 加载。
- 首次加载根据模型包围盒自动计算初始相机和控制器目标，避免依赖旧山河大学模型的硬编码镜头。
- 已校准的 3D 点位显示悬浮信息标签；未校准点位只保留列表和详情入口。
- 继续支持旋转、缩放、拖拽和第一人称切换。
- GLB 加载失败时保留工具栏和 2D 切换入口，并显示可操作的错误状态。

## 场景切换行为

左上角使用分段控件：`2D 平面图`、`3D 模型`。切换后：

1. 当前选中地点不变；
2. 当前路线不变，并按当前场景坐标重新投影；
3. 当前模拟位置不变；
4. 搜索结果、筛选、热点和角色不变；
5. 新场景加载中显示轻量遮罩，加载失败允许切回另一场景。

## 错误和空状态

- 官方平面图加载失败：显示“2D 底图加载失败”，保留重试和切换 3D 操作。
- GLB 加载失败：显示“3D 模型加载失败”，保留重试和切换 2D 操作。
- 当前路线没有场景坐标：显示“该场景暂未完成路线校准”，不伪造路线。
- 当前筛选没有地点：复用现有空状态组件。

## 测试与验收

必须覆盖以下行为：

1. 初始状态为 2D；
2. `SET_MAP_SCENE` 只改变场景，不清空选中地点、路线和模拟位置；
3. 2D 地点坐标能投影到地图容器的正确比例位置；
4. 2D 路线能根据 route plan 绘制起点、终点和线段；
5. 缺少场景坐标时不会绘制假路线；
6. 3D 使用新的模型 URL 配置；
7. `npm test` 和 `npm run build` 均通过。

## 迁移策略

旧的 `public/assets/campus.glb` 保留，不删除；新模型单独使用 `campus-extracted.glb`。如果新模型坐标校准尚未完成，2D 仍是默认稳定入口，3D 可以先作为模型浏览场景逐步补齐标签和路线。后续接真实 API 时，只替换数据源实现，不修改两个地图渲染器的交互契约。
